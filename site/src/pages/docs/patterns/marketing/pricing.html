Overview

Pricing sections help users understand and compare your offerings. These patterns use data-layout="grid" for responsive card layouts and semantic table markup for feature comparisons, creating accessible and mobile-friendly pricing displays.

Key features:

  • Responsive card grids with data-layout="grid"
  • Highlighted recommended tier
  • Feature comparison tables with row-group headings and a data-table-scroll wrapper
  • Monthly/yearly billing toggle: a native input[data-switch] plus the :has() selector
  • Accessible markup with proper semantics
  • No JavaScript required

Required CSS

The card, badge and list come from VB. Only the featured lift and the price typography are bespoke:

Comparison Table

A feature comparison table with plan columns and feature rows. Uses semantic <table> markup with proper scope attributes for accessibility: each category is its own <tbody> headed by a th scope="rowgroup", and each feature name is a th scope="row". Included and missing features use the .status marker with visually hidden text, so the table reads correctly without the glyphs. The data-table-scroll wrapper lets the table scroll sideways on narrow screens; add data-table-scroll="block" and data-sticky="header" to pin the plan row while scrolling a long table.

Required CSS

VB styles the table itself. These rules centre the plan columns and set the plan-header typography; on a real site, scope them under your pricing section:

 td { text-align: center; vertical-align: middle; } thead th:not(:first-child) { text-align: center; vertical-align: bottom; } td > .status { font-size: var(--font-size-l); } th[scope="rowgroup"] { background: var(--color-surface-raised); } th[scope="row"] { font-weight: var(--font-weight-normal); color: var(--color-text-muted); } .plan-header { display: flex; flex-direction: column; align-items: center; gap: var(--size-xs); } .plan-name { font-size: var(--font-size-l); } .plan-price { font-size: var(--font-size-2xl); font-weight: var(--font-weight-bold); } .plan-period { font-size: var(--font-size-s); color: var(--color-text-muted); font-weight: var(--font-weight-normal); } th[data-featured] .plan-header { color: var(--color-interactive); }

With Billing Toggle

Pricing cards with a monthly/yearly billing toggle. The switch is a native checkbox with data-switch, labelled "Yearly". The CSS :has() selector swaps the prices and highlights the active billing period, so no JavaScript is needed.

 <section data-layout="center" data-layout-max="wide" data-layout-gap="2xl"> <header data-layout="stack" data-layout-gap="m" data-layout-align="center"> <h2>Simple, transparent pricing</h2> <p>Choose the plan that's right for you</p> <p class="pricing-toggle"> <span class="toggle-label" aria-hidden="true">Monthly</span> <input type="checkbox" role="switch" data-switch id="billing-yearly"/> <label class="toggle-label" for="billing-yearly">Yearly</label> <layout-badge data-color="success" data-variant="subtle">Save 20%</layout-badge> </p> </header> <layout-grid data-layout-min="l" data-layout-gap="l"> <layout-card data-variant="outlined" data-padding="l" data-layout="stack" data-layout-gap="l"> <hgroup data-layout="stack" data-layout-gap="xs"> <h3 class="plan-name">Basic</h3> <p><span class="price price-monthly">$9</span><span class="price price-yearly">$7</span> <span class="price-period">/month</span></p> <p><small>Perfect for individuals and small projects</small></p> </hgroup> <!-- features... --> <a href="#" class="button secondary full-width">Get Started</a> </layout-card> <!-- more cards... --> </layout-grid> </section>

Required CSS

Add these styles for the billing toggle, alongside the card styles above. VB draws the switch; the :has() rules handle the label state and the price swap:

 /* Billing toggle: the switch is a native checkbox (input[data-switch]) */ .pricing-toggle { display: inline-flex; align-items: center; gap: var(--size-m); } .toggle-label { font-weight: var(--font-weight-medium); margin-block: 0; color: var(--color-text-muted); transition: color 0.2s ease; } /* The active side: Monthly while unchecked, Yearly while checked */ .toggle-label:has(+ input:not(:checked)), input:checked + .toggle-label { color: var(--color-text); } /* Price visibility follows the switch, no JavaScript */ section:has(.pricing-toggle input:checked) .price-monthly, section:has(.pricing-toggle input:not(:checked)) .price-yearly { display: none; }

Layout Configuration

Common data attributes for pricing sections:
Element Attribute Values Description
data-layout="grid" data-layout-min CSS length (e.g., 280px) Minimum card width before wrapping.
data-layout="grid" data-layout-gap xs s m l xl Gap between grid items.
data-layout="center" data-layout-max narrow measure wide Maximum width of pricing section.
data-layout="stack" data-layout-gap xs s m l xl 2xl Vertical spacing between elements.
layout-card data-featured Boolean attribute Highlights the recommended plan.

Usage Notes

  • Tier naming: Use clear, hierarchical names (Basic, Pro, Enterprise) that indicate value progression.
  • Feature ordering: List features in order of importance. Lead with the most compelling features.
  • Highlight recommended: Always highlight one tier as recommended. This guides user decisions and improves conversion.
  • CTAs: Use primary buttons for the recommended plan and secondary buttons for others. Use "Contact Sales" for enterprise tiers.
  • Pricing transparency: Show all costs upfront. If there are per-user or usage-based costs, make them clear.
  • Yearly savings: When offering discounts for annual billing, display the savings prominently (e.g., "Save 20%").
  • Comparison tables: Use tables for detailed feature comparisons. Cards work better for quick overviews.
  • Mobile considerations: Cards stack naturally on mobile. Tables may need horizontal scrolling.
  • Accessibility: Use proper table semantics with scope attributes. Ensure toggle has proper labeling.
