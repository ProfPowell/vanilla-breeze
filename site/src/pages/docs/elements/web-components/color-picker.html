Overview

The <color-picker> component wraps a native <input type="color"> and replaces the limited browser picker with a full color space UI: a saturation/lightness area, a hue slider, a format selector with HEX, RGB, HSL and OKLCH inputs, a Copy button, preset swatches from a <datalist>, and EyeDropper API integration.

Point the <label for> at the inner input. After upgrade the native input is hidden from assistive technology, so the component reuses its label to name the trigger button together with the current value (“Brand color #6366f1”). Clicking the label focuses the trigger.

Progressive enhancement: Without JavaScript, the native <input type="color"> provides an OS-level color picker and submits under its own name. On upgrade the component moves that name to itself (if the host has a name too, the host wins) and removes it from the input, so the form always submits exactly one value.
Coexistence with data-color: The existing data-color attribute enhancer automatically skips inputs inside a <color-picker> element. Use data-color for simple swatch+hex display; use <color-picker> for the full color space UI.

Formats and Copy

The Format selector in the panel switches the text inputs between HEX, RGB, HSL and OKLCH. All four stay in sync with the color; only the active one is shown. The Copy button writes the current color to the clipboard in the active format, using modern CSS Color 4 syntax:

Format Inputs Copied as
hex Hex #6366f1
rgb R, G, B (0–255) rgb(99 102 241)
hsl H (0–360), S, L (0–100) hsl(239deg 84% 67%)
oklch L%, C (0–0.4), H° oklch(58.5% 0.204 277.1deg)

Set the format attribute to open the picker in a particular format. The user’s choice at runtime is kept for the life of the element.

The submitted form value and the value property are always a 7-character hex string, whatever format is displayed.

Preset Swatches

Add a <datalist> child with <option> elements to provide a row of preset color swatches. The option text is the swatch’s accessible name.

EyeDropper

On supported browsers, a pipette button appears that opens the EyeDropper API to pick any color from the screen. The button is omitted on browsers that don’t support the API.

Form Integration

The component is form-associated via ElementInternals. The submitted value is always a 7-character hex string (e.g. #6366f1). A color picker always holds a color, so there is no required state.

  • Reset restores the inner input’s value attribute, even after the element has been moved in the DOM.
  • Disabled: the disabled attribute, or a disabled ancestor <fieldset>, disables the trigger, closes the panel, and leaves the value out of the submitted FormData.

JavaScript API

PropertyTypeDescription
element.valuestringCurrent color as #rrggbb (read/write). Accepts 3- or 6-digit hex; anything else is ignored. Assigning fires color-picker:change with source: 'api' unless the color is unchanged.
const picker = document.querySelector('color-picker'); picker.value; // "#6366f1" picker.value = '#22c55e'; // updates UI + form value, fires change (source: 'api') picker.addEventListener('color-picker:change', (e) => { if (e.detail.source === 'api') return; // ignore our own assignments console.log(e.detail.hex, e.detail.rgb, e.detail.hsl); });

Accessibility

  • The trigger is a <button> with aria-haspopup="dialog" and aria-expanded, named by the inner input’s <label> plus the current hex value via aria-labelledby. Without a label it falls back to the input’s aria-label, the host’s aria-label, or “Color”.
  • The panel is role="dialog" with an accessible label. Escape closes it and returns focus to the trigger; closing by clicking elsewhere leaves focus where the user clicked.
  • The color area is a single role="slider". There is no APG pattern for a two-dimensional slider, so aria-valuenow (0–100) tracks saturation on the horizontal axis, Arrow Up/Arrow Down adjust lightness, and aria-valuetext announces both (“Saturation 84%, lightness 67%”) on every change. The HSL inputs give a dedicated one-dimensional control for each channel.
  • The hue strip is role="slider" with aria-valuenow 0–360 and aria-valuetext in degrees.
  • Preset swatches are plain buttons in a role="group" labelled “Preset colors”; the swatch matching the current color has aria-pressed="true".
  • Text inputs provide direct numeric entry for users who prefer precision over the visual interface.
