Overview

The <consent-banner> component wraps a native <dialog> to handle cookie and privacy consent. It manages localStorage persistence, expiry, and provides a trigger attribute to let users re-open their preferences from anywhere on the page.

The author controls all content inside the dialog — the component handles the plumbing: show/hide, localStorage read/write, and event dispatch.

Simple Banner

The minimal setup: a <dialog> with a paragraph and footer containing accept/reject buttons. The value attribute on each button drives the consent logic.

We use cookies to improve your experience. Privacy Policy
How it works: On page load, the component checks localStorage. If no stored consent (or expired), the dialog opens via dialog.show() (non-modal). After the user clicks a button, consent is stored and the element is removed from the DOM.

Granular Preferences

Add checkboxes for per-category control. The value="save" button stores whatever the user has checked. The value="accept" button marks everything true; value="reject" only keeps disabled checkboxes (typically Necessary) as true.

Cookie categories
Equal choices: Give Reject All the same visual weight as Accept All. Many privacy regulators treat a de-emphasised reject option as a dark pattern, so the examples use the same button style for both.

Position Variants

The position attribute controls where the banner appears and whether it is modal. Changing it while the banner is open re-shows the dialog in the new mode.

Value Behavior Dialog API

top Fixed to viewport top, page remains interactive dialog.show()
center Centered modal with backdrop — user must choose (ESC prevented) dialog.showModal()

Re-opening Preferences

Set trigger to a CSS selector pointing at a Manage Cookies button (or link) elsewhere on the page. When clicked, the dialog re-opens with previously saved checkbox states restored.

The trigger uses document-level event delegation, so the target element can exist anywhere in the DOM — even if it loads after the banner.

How it works: When trigger is set, the banner is hidden (not removed) after consent. This keeps the element alive so the trigger can re-open it.

Events

The component dispatches a single event when the user makes a consent choice.

Event Detail Description
consent-banner:change { preferences: Object, action: string } Fired when the user clicks accept, reject, or save. preferences maps checkbox names to booleans. action is the button’s value.
// Listen for consent changes document.addEventListener('consent-banner:change', (e) => { const { preferences, action } = e.detail; if (preferences.analytics) initAnalytics(); if (preferences.marketing) initMarketing(); console.log(`User chose: ${action}`, preferences); });

Static API

The ConsentBanner class exposes static methods for reading and clearing consent from external code. Both are async — await them.

Method Parameters Returns Description
ConsentBanner.getConsent(key?, options?) key: string (default: 'banner', matching a banner without persist)
options.expires: number | 'never' (days)		 Promise<{ preferences, action } | null> Read stored consent. Resolves null when nothing is stored, the entry has expired, or storage is unavailable. Expiry uses options.expires; if omitted, the expires attribute of a <consent-banner> in the document with the same persist key; otherwise the 365-day default. A banner without trigger removes itself after a choice, so pass expires explicitly when you use a non-default value.
ConsentBanner.reset(key?) key: string (default: 'banner') Promise<void> Clear stored consent. The banner reappears on next page load.
import { ConsentBanner } from '/src/web-components/consent-banner/logic.js'; // Check stored consent on page load (null if missing or expired) const consent = await ConsentBanner.getConsent('cookie-prefs'); if (consent?.preferences?.analytics) { initAnalytics(); } // Banner uses expires="30"? Pass the same value here const recent = await ConsentBanner.getConsent('cookie-prefs', { expires: 30 }); // Clear consent (banner reappears on next load) await ConsentBanner.reset('cookie-prefs');

Recipe: Gate Scripts on Consent

Load optional scripts only after consent. Check stored consent once on load (returning visitors), then listen for consent-banner:change (first-time visitors and later changes via the trigger). Guard each loader so it runs only once.

localStorage Format

Consent is stored through VBStore (namespace consent) under the localStorage key vb:consent:<persist> — vb:consent:banner when persist is not set. The value is a VBStore envelope: your choice sits in data, and VBStore adds the timestamp.

{ "data": { "preferences": { "necessary": true, "analytics": true, "marketing": false }, "action": "save" }, "timestamp": 1709913600000 }

The envelope timestamp drives expiry. When expires days have elapsed since it, the banner reappears on the next page load and getConsent() resolves null. getConsent() returns only the data part ({ preferences, action }), not the timestamp.

If localStorage is unavailable (blocked storage, some privacy modes), the banner still opens and still fires consent-banner:change; the choice simply is not remembered on the next load.

Accessibility

Dialog Behavior

  • Accessible name: Unless you set aria-label or aria-labelledby on the <dialog>, the component points aria-labelledby at the first heading inside it (adding an id if needed), or sets aria-label="Cookie consent" when there is no heading.
  • Bottom / Top: Uses dialog.show() (non-modal). The page remains interactive — users can scroll and navigate freely.
  • Center: Uses dialog.showModal() (modal). Focus is trapped inside the dialog. ESC is prevented to enforce a consent choice.

Keyboard

Key Action
Tab Move between buttons and checkboxes
Enter / Space Activate button or toggle checkbox
Escape Prevented in center (modal) position; no effect in bottom/top (non-modal)

Reduced Motion

When prefers-reduced-motion: reduce is set, the slide-in animation is disabled. The banner appears instantly.

No JavaScript

The consent-banner:not(:defined) CSS rule hides the banner until the component is defined. Without JavaScript, the banner never appears and no consent is required — a safe progressive enhancement default.

Scope

This is a client-side consent UI helper built around native <dialog>. It stores the user's decision in localStorage. If your project requires a broader compliance workflow (server-side enforcement, cookie-less tracking prevention, or jurisdiction-specific legal requirements), those concerns live outside this component.
