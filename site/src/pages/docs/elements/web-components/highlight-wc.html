Overview

<highlight-wc> lets readers highlight passages of an article. Highlights are painted with the CSS Custom Highlight API (no DOM changes; a <mark> fallback elsewhere) and persist in localStorage per page.

It has two modes:

  • Inside <selection-menu> (primary usage) — it renders a highlighter button in the selection toolbar. The button opens a colour palette; choosing a swatch highlights the selection.
  • Standalone — it renders no UI. It turns on persistence and rendering for its target and exposes a JavaScript API and events, so you can build your own controls.

The engine underneath is the data-highlights attribute.

With selection-menu

Put <highlight-wc> inside a <selection-menu> that targets your content. Every target of the menu can be highlighted, each with its own set of highlights; stored highlights are painted as soon as the page loads.

Standalone (programmatic)

Without a selection-menu, <highlight-wc> wraps its target (or points at one with for) and renders nothing itself. Stored highlights are painted, and you drive creation from your own UI with highlightSelection() or listen for highlights:selected.

Colours

Each colour is a light-dark() pair: a pale wash with dark text in light mode, a deep wash with light text in dark mode. Highlighted text takes --highlight-ink so it meets WCAG AA in both schemes. Override a colour, or add your own, with a matching pair:

:root { --highlight-yellow: light-dark(#fef08a, #5c4d00); --highlight-mint: light-dark(#ccfbef, #0f4d3f); /* optional per-colour text colour */ --highlight-mint-ink: light-dark(#062e25, #f0fdf9); }

JavaScript API

Inside a selection-menu the methods act on the most recently highlighted target (initially the first).

const hw = document.querySelector('highlight-wc'); hw.highlightSelection('yellow'); // highlight the current selection hw.getHighlights(); // [{ id, startOffset, endOffset, text, color, note, created }] hw.removeHighlight('hn-abc123'); hw.clearAll(); const json = hw.exportHighlights(); const { imported, rejected } = hw.importHighlights(json);

importHighlights() drops records with the wrong shape, offsets outside the article text, or a colour that is not in the palette.

Events

Dispatched on the highlighted element (the article) and bubble.

EventDetailWhen
highlights:added{ id, text, color, note }A highlight was created
highlights:removed{ id }A highlight was removed
highlights:selected{ text, rect }Text was selected in the target (standalone UI hook)
highlights:clicked{ id, highlight }A highlight or its margin annotation was clicked
highlights:note-changed{ id, note }A note was saved via <note-wc>

Accessibility

  • The highlighter is a <button> named “Highlight selection” with aria-expanded and aria-controls pointing at the palette.
  • The palette is a named group of swatch buttons. Each swatch is named after its colour (also shown as a tooltip) and the last-used colour carries aria-pressed="true". Opening the palette moves focus to that swatch.
  • Escape closes the palette and returns focus to the button; clicking outside or dismissing the toolbar also closes it.
  • Creating or removing a highlight is announced through a polite live region.
  • In forced-colors mode swatches keep their fills, highlights use the system Mark colours, and each palette colour gets a different underline style.
  • Limitations: Custom Highlight API ranges are not exposed to assistive technology — a screen reader hears the announcement when a highlight is made, but highlighted text is not otherwise identified when read back. Margin annotations are aria-hidden. Use getHighlights() to render an accessible list of highlights if your readers need one.
