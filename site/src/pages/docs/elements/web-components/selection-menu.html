Overview

The <selection-menu> component provides a Medium-style floating toolbar that appears when text is selected. It composes action components as children: <highlight-wc> for color highlighting, <share-wc> for sharing quotes, <note-wc> for private notes, and <comment-wc> for collaborative comments.

The host only coordinates. On upgrade it moves its authored children into a generated <pop-over data-mode="manual" data-selection-menu-host role="toolbar">, which is the visible toolbar. It sits in the top layer, so there are no z-index fights. The host itself is display: contents. To restyle the toolbar, target selection-menu > pop-over[data-selection-menu-host], not the host.

The toolbar opens when a pointer or keyboard selection ends inside a target. It is placed above the selection (below it for touch, where the OS selection callout sits above), clamped to the viewport, and moved with the selection on scroll and resize. It hides once the selection scrolls out of view.

Not what you want? For a persistent in-flow bar of emoji reactions attached to an item (GitHub-style), use <reaction-bar> instead — the trigger model is different (in-place chips + a curated palette popover, not a text-selection anchor).

JavaScript API

const menu = document.querySelector('selection-menu'); // Get current selection state (a cloned range), or null when hidden menu.getSelection(); // { range, text, target } // Dismiss the toolbar (focus inside it returns to the target) menu.dismiss(); // Read or replace the toolbar actions as data menu.actions; // [{ tag: 'highlight-wc', attrs: {}, html: '…' }, …] menu.actions = [ { tag: 'highlight-wc' }, { tag: 'share-wc', attrs: { 'data-label-share-selection': 'Share quote' } }, ];
MemberTypeDescription
getSelection()method{ range, text, target } for the selection the toolbar is showing, or null
dismiss()methodHide the toolbar. If focus is inside it, focus returns to the selection's target.
actionsget/setToolbar children as { tag, attrs?, html? } entries (or elements). Setting it replaces them and fires selection-menu:actions-changed.

Events

EventDetailDescription
selection-menu:select{ range, text, target }Text selected, toolbar shown
selection-menu:dismiss—Toolbar hidden (outside click, Escape, dismiss(), selection collapsed from the keyboard, or scrolled out of view)

Accessibility

  • The composed pop-over has role="toolbar", aria-orientation="horizontal", an aria-label from data-label, and aria-keyshortcuts="Alt+F10"
  • Keyboard selections open it too. Shift+Arrow selections (caret browsing or assistive technology) open the toolbar when Shift is released or the selection settles.
  • Each child action has its own accessible name
KeyAction
Alt+F10Move focus into the toolbar (opens it first when the selection is in a target)
← / →Previous / next action (roving tabindex, mirrored in RTL)
Home / EndFirst / last action
EscapeClose the toolbar. From inside it, focus and the selection return to the text. A handler that calls preventDefault() keeps it open.

Clicking outside the toolbar dismisses it.
