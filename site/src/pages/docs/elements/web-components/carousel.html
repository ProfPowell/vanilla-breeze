Overview

A scroll-snap carousel with full progressive enhancement. Without JavaScript it renders as a simple scrollable row. With JS it adds prev/next buttons, dot indicators, autoplay, looping, keyboard navigation, and ARIA roles.

Usage

Wrap slide elements inside <carousel-wc>. Each direct child becomes a slide. Give each carousel a name with aria-label or aria-labelledby: the carousel is a region landmark, and unnamed ones all fall back to "Carousel", which makes several on one page indistinguishable.

Autoplay with Looping

Add autoplay and loop to cycle slides automatically. Autoplay renders a pause/play rotation control as the first control in the carousel. Pausing with it sticks until the user presses play again. While rotation is on, it also pauses while the pointer is over the carousel or keyboard focus is inside it, and resumes when they leave. When prefers-reduced-motion is active, autoplay is off entirely and no rotation control appears.

carousel-wc:play and carousel-wc:pause follow the autoplay timer. They also fire when hover or focus suspends rotation and when rotation resumes afterwards.

Data API

The slides property swaps the slide set from data. Each record needs html (the slide content as an HTML string). id becomes the slide element's id. label replaces the default "n of total" slide label. Assigning rebuilds the carousel at slide 0 (or start) and fires carousel-wc:slides-changed. If you assign before the element is in the document, the carousel builds once when it connects.

const el = document.createElement('carousel-wc'); el.setAttribute('aria-label', 'Release notes'); el.slides = [ { id: 'v1', html: '

v1.0

First release.

' }, { id: 'v2', html: '

v2.0

Rotation control.

', label: 'Version 2' }, ]; document.querySelector('main').append(el); el.slides; // [{ id: 'v1', html: '…', label: '1 of 2' }, …]

The data API is HTML-only: content is assigned with innerHTML. Sanitize untrusted strings before you assign them.

Keyboard Navigation

Focus the carousel track (Tab into it), then use arrow keys:

KeyAction
ArrowLeftPrevious slide
ArrowRightNext slide
HomeFirst slide
EndLast slide

In right-to-left documents the arrow keys follow the visual direction: ArrowLeft goes to the next slide, ArrowRight to the previous one, and the prev/next chevrons are mirrored.

Accessibility

ARIA Roles

The component uses role="region" with aria-roledescription="carousel". An authored aria-label or aria-labelledby names the region; without one it falls back to "Carousel". Each slide has role="group" with aria-roledescription="slide" and a label like "1 of 4", unless the slide already has an aria-label. Dot indicators are simple buttons with aria-current marking the active slide, inside a role="group" named "Slide indicators".

Rotation Control

With autoplay, a pause/play button comes first in the carousel's reading order, following the APG carousel pattern and WCAG 2.2.2 (Pause, Stop, Hide). Its accessible name says what it will do: "Pause automatic slide show" or "Start automatic slide show".

Live Region

A visually hidden live region announces "Slide n of total". It is aria-live="off" while slides rotate on their own, so screen readers are not interrupted on every tick. It becomes aria-live="polite" when rotation is paused or suspended, and on carousels without autoplay.

Reduced Motion

When prefers-reduced-motion is active (or the page sets data-motion-reduced on the root element), autoplay is completely disabled, no rotation control is rendered, and scroll behavior uses instant transitions.

Styling

Override the button and dot styles using the .carousel-rotate, .carousel-prev, .carousel-next, and .carousel-dot classes.

/* Custom button styling */ .carousel-prev, .carousel-next { background: var(--color-interactive); color: white; border: none; } /* Custom dot styling */ .carousel-dot[data-active] { background: var(--color-primary); }

Progressive Enhancement

Without JavaScript, <carousel-wc> renders as a horizontal scrollable row using the :not(:defined) fallback. Once JS registers the component, controls and indicators appear.

/* Without JS: simple horizontal scroll */ carousel-wc:not(:defined) { display: flex; overflow-x: auto; gap: var(--size-s); scroll-snap-type: x mandatory; } carousel-wc:not(:defined) > * { flex: 0 0 auto; scroll-snap-align: start; }

View Transitions

Add transition to switch from scroll-snap to View Transition animations. When active, the carousel uses a stacked-grid layout and animates between slides using the View Transitions API.

ValueEffect
fade (default)Crossfade between slides
slideDirectional slide — forward when advancing, backward when retreating
scaleScale down old slide, scale up new slide

Dual-Mode Behavior

Without transition, the carousel uses scroll-snap with IntersectionObserver — slides are arranged in a horizontal row and the user scrolls between them. With transition, the carousel switches to a stacked CSS Grid layout where slides occupy the same grid cell and are shown/hidden with View Transition animations.

Progressive enhancement: View Transitions work in Chrome 111+, Safari 18+ and Firefox 144+ (support table). In unsupported browsers, the carousel falls back to scroll-snap behavior automatically.
