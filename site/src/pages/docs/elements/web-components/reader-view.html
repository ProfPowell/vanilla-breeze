Attributes

Attribute Values Default Description
mode scroll, pages scroll Reading mode. Observed and reflected: setting it after upgrade switches modes. pages is a full-viewport overlay (see Accessibility).
columns auto, 1, 2, 3 auto Column count in pages mode. Observed and reflected.
persist true, false true Persist font size and columns (and the mode, with data-remember-mode) to localStorage.
storage-key any string vb-reader:<pathname>[#id] localStorage key. The default is unique per page, and per reader when it has an id, so one reader's settings never leak into another.
data-remember-mode boolean off Restore the persisted mode on load. Without it a reader always opens in its authored mode (or scroll), never as a fullscreen overlay the user chose on an earlier visit.
col-controls true, false true Show/hide column picker in chrome.
font-controls true, false true Show/hide font size buttons in chrome.
reader-title any string auto Chrome bar title. Falls back to first <h1>, then document.title.
data-label-* string English Override UI strings: kicker, controls, mode-group, mode, scroll, pages, font-group, type, font-decrease, font-increase, columns-group, cols, auto, column-auto, column-1/-2/-3, pages-region, page-nav, prev, next, page-indicator ({page} / {total}).

Progressive Enhancement

reader-view degrades gracefully at every layer:

  • Without JS — renders as a block element. Content is fully readable as a normal scrolling article.
  • Without CSS — semantic HTML renders in document order.
  • With CSS only — layout-columns reading defaults apply. No page controls.
  • With JS — full paged reading with chrome, font controls, column picker, keyboard navigation, and persistence.

    Chrome Actions

    Any element inside slot="chrome" can trigger behaviour via data-reader-action:

    Action Effect
    toggle-modeToggle between scroll and pages
    set-mode-scrollSwitch to scroll mode
    set-mode-pagesSwitch to pages mode
    font-increaseIncrease font size one step
    font-decreaseDecrease font size one step
    set-columnsSet columns from data-reader-value (auto, 1, 2, 3)
    prev-pagePrevious page
    next-pageNext page

    The runtime keeps aria-pressed (and the data-reader-state="active" styling hook) in sync on mode, toggle and column buttons, and fills <output data-reader-output="page-indicator"> and data-reader-output="mode-label".

    Events

    Event Detail When
    reader-view:mode { mode: 'scroll' | 'pages' } Mode changed (not on upgrade)
    reader-view:page { page: number, total: number } Page changes
    reader-view:font { size: string, index: number } Font size changes

    Keyboard Shortcuts

    Active in pages mode only. They also work while focus is on a chrome button (Space still activates the button). In right-to-left documents the arrow keys are mirrored.

    Key Action
    ArrowRight / Space / PageDownNext page
    ArrowLeft / PageUpPrevious page
    Shift + SpacePrevious page
    EscapeReturn to scroll mode (focus goes back to the mode toggle)
    HomeFirst page
    EndLast page

    Accessibility

    • Pages mode is a full-viewport overlay that behaves like a modal: the rest of the page is made inert, document scrolling is locked, focus moves into the pager region, and Escape returns to scroll mode with focus restored to the mode toggle.
    • The overlay stacks at --reader-view-z (default var(--z-overlay)), above sticky site headers.
    • Control sets are labelled role="group"s (Reading mode, Font size, Page columns); mode and column buttons expose aria-pressed, and the column buttons have descriptive names (“2 columns”).
    • Page indicator is an <output> with aria-live="polite"; the pager has role="region" and aria-label="Article pages".
    • The component never adds a <main> landmark, so it can sit inside your page's <main>.
    • Forced-colors mode marks the active segment with Highlight; paging, arrows, progress and the nav pill mirror in right-to-left documents.
    • Printing always outputs the article as one static flow, in either mode.
    • All animations respect prefers-reduced-motion: reduce; content stays in source order.

    Best Practices

    • Use data-prose on the article — this enables hyphenation from the native article styles.
    • Give multiple readers an id — the default storage key includes it; or set storage-key to share settings across pages deliberately. Authored attributes (mode, columns) take precedence over persisted state.
    • Prefer auto columns — let the component resolve the best count for the viewport.
    • Position anchoring works automatically — switching modes preserves the reader's position in the content.
