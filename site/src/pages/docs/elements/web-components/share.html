Overview

<share-wc> provides social sharing with three-tier progressive enhancement:

  1. Tier 1 (native) — On supported platforms, a single button triggers the OS share sheet via navigator.share()
  2. Tier 2 (platforms) — On desktop, individual platform buttons open share URLs
  3. Tier 3 (no JS) — Slotted <a> links work without JavaScript

Attributes

color boolean absent Platform brand colours on each button's border and icon; label text keeps the theme text colour for AA contrast

tier string auto Force tier: native or platforms. Overrides auto-detection. native without Web Share support resolves to hidden.
data-tier-resolved output — Set by the component: native, platforms, hidden or selection (inside <selection-menu>)

Inside selection-menu

As a child of <selection-menu>, <share-wc> renders one icon button. It shares the selected text as a quote with the share sheet. Without Web Share it copies the quote instead and announces the copy. The quote links to the resolved url (attribute, then canonical link) with a #:~:text= fragment, so readers land on the quoted passage.

Progressive Enhancement

For full no-JS support, slot <a> elements with data-platform attributes. The component enhances them with click handlers and substitutes {url}, {title}, {text} tokens in href values. It keeps the original templates, so setting url, shareTitle or text from JavaScript substitutes them again.

Force platform buttons

On devices with navigator.share (macOS, iOS, Android), the component auto-selects the native share sheet. Use tier="platforms" to always show individual platform buttons instead, giving authors full control over which platforms appear.

Native-only mode

Use platforms="native-only" to show only the native share button. Hides entirely on platforms without Web Share API support.

Mastodon Instance

Set a custom Mastodon instance with mastodon-instance. Defaults to mastodon.social.

Events

Event Detail Description
share-wc:open { platform } Fired when a share is initiated
share-wc:success { platform } Fired after a share window opens, the native share resolves, or the link is copied (platform: 'copy')
share-wc:error { platform, error? } Fired when native share fails (a user cancel is not an error) or the clipboard write fails. After a native failure the component copies the link instead.
const share = document.querySelector('share-wc'); share.addEventListener('share-wc:success', (e) => { console.log(`Shared via ${e.detail.platform}`); }); share.addEventListener('share-wc:error', (e) => { console.error(`Share failed: ${e.detail.error}`); });

JavaScript API

Property/Method Type Description
url get/set Share URL. A value set here wins over the attribute and page metadata, survives reconnects, and re-substitutes slotted tokens.
shareTitle get/set Share title, with the same rules. Named so it does not shadow HTMLElement.title (the tooltip).
text get/set Share description, with the same rules
share() method → Promise<boolean> Native tier: opens the share sheet and copies the link if that fails. Other tiers: copies the link. Resolves true when the page was shared or the link was copied.
const share = document.querySelector('share-wc'); // Update share data share.url = 'https://example.com/new-page'; share.shareTitle = 'New Title'; // Share sheet in the native tier, copy the link otherwise const ok = await share.share();

Accessibility

  • The Tier 1 button is named by its visible label, so the name always matches what is on screen, in any language
  • Tier 2 wraps buttons in <nav aria-label="Share this page"> (data-label-share-page)
  • Platform buttons are named "Share on X" and so on, a name that contains the visible platform label. The copy button is named by its visible "Copy link" label.
  • Copying announces "Link copied to clipboard" (data-label-link-copied) through a role="status" live region, and the label reads "Copied!" for 2 seconds
  • Icons are hidden from assistive technology with aria-hidden="true"
  • In the icon variant, labels stay in the accessibility tree (visually hidden, not removed)
  • With color, brand colours apply only to borders and icons, so label text keeps AA contrast
  • Reduced motion: transitions disabled via prefers-reduced-motion
