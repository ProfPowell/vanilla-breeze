Overview

The <theme-picker> component lets a visitor choose two things: the color mode and the theme. It integrates with ThemeManager for persistence and system preference detection.

The theme chooser has two forms. By default every theme is a swatch, which suits a site that wants to show its range. Add compact and the swatches become one grouped <select>, which fits a header, a mobile menu or a narrow sidebar. Everything else a visitor can adjust (sizing, accessibility themes, motion, sound) belongs to <settings-panel>; the two share state and can sit on the same page.

Attributes

compact boolean - The theme chooser is one grouped select instead of the swatch grid
open boolean - Reflected attribute indicating open state (popover only). Set by open() / close() / toggle(); not meant as initial markup.

Put data-trigger on your own trigger button (or make it the first child <button>). Without one the picker generates an icon <button type="button">.

ThemeManager API

For programmatic theme control, use the ThemeManager module:

import { ThemeManager } from './lib/theme-manager.js'; // Initialize (called automatically in main.js) ThemeManager.init(); // Get current state const { mode, brand, accent, effectiveMode } = ThemeManager.getState(); // Set color mode: 'auto', 'light', or 'dark' ThemeManager.setMode('dark'); // Set brand theme (personality themes) ThemeManager.setBrand('swiss'); // Set a color accent (no control in the picker; see the accent table below) ThemeManager.setAccent('ocean'); // Toggle between light and dark ThemeManager.toggleMode(); // Reset to defaults ThemeManager.reset(); // Listen for changes window.addEventListener('vb:theme-change', (e) => { // { mode, brand, accent, borderStyle, iconSet, fluid, backdrop, // backdropChrome, pageBgType, effectiveMode } console.log(e.detail); });

Creating Custom Themes

Create new brand themes by copying the template:

# Copy the template cp src/tokens/themes/_brand-template.css src/tokens/themes/_brand-coral.css

Edit the hue values (0-360). Keep the @layer bundle-theme wrapper: every theme self-declares that layer, which places it above the framework layers, below packs, and below your own unlayered CSS.

@layer bundle-theme { :root[data-theme="coral"], [data-theme="coral"] { --hue-primary: 15; /* coral orange */ --hue-secondary: 350; /* pink */ --hue-accent: 180; /* teal contrast */ /* Colors are auto-calculated from hues */ --color-primary: oklch(50% 0.15 var(--hue-primary)); /* ... */ } }

Register in src/tokens/themes/index.css:

@import "./_brand-coral.css";

Accessibility

  • The popover is a non-modal role="dialog" with an aria-label. Focus is not trapped: opening moves focus to the selected colour mode, Escape closes and returns focus to the trigger, and tabbing out of the picker or clicking outside closes it.
  • Every radio set (mode and each theme group) is a role="radiogroup" inside a labelled <fieldset>. Radio names are unique per picker, so a header picker and a mobile-menu picker on the same page don't share groups.
  • Arrow keys move through a radio group and apply each choice, but never close the popover. Only pointer selections auto-dismiss it.
  • The trigger announces its state with aria-expanded and aria-controls.
  • In forced-colours mode the selected mode segment and options use Highlight, and swatches keep their real colours with a visible outline.
  • Swatches have no visible text, so the name of the swatch under the pointer or focus is shown beside the Theme legend (the current theme's name otherwise). Each swatch also has its name as its accessible label.
  • Accessibility themes on <html data-theme> (for example a11y-large-text, authored or set through <settings-panel>) are kept when the visitor picks another theme.
