Overview

The <image-map> component replaces native HTML <map>/<area> with percentage-based coordinates that scale responsively. Areas are defined as <map-area> children with rich HTML tooltip content, full keyboard navigation, and progressive enhancement.

Progressive enhancement: Without JavaScript, the image renders normally and each <map-area> displays as a list item below it: the label in bold, then the area content. <map-area href> is not a link without JS — if the destination must stay reachable, put an <a href> in the content (see Progressive Enhancement).

Markup Pattern

Place an <img> as a direct child of <image-map>. The component adopts it and overlays an SVG hit-testing layer. Each <map-area> defines a hotspot region — its inner HTML becomes the tooltip content.

Alternatively, src and alt attributes on <image-map> itself can create the image, but placing <img> as a child gives better progressive enhancement.

Coordinate System

All coordinates are percentages (0–100) of the rendered image dimensions — not pixels. Values are unitless numbers separated by spaces or commas. The SVG overlay uses viewBox="0 0 100 100" so percentage coordinates map directly to SVG units with no runtime conversion.

Tooltip Content

The inner HTML of each <map-area> becomes the tooltip content. Use any HTML: headings, paragraphs, lists, images, links.

Tooltip modes

By default, tooltips show on hover and keyboard focus (tooltip="hover"). The tooltip is hoverable: moving the pointer from the area onto it keeps it open, and Escape dismisses it wherever focus is. Set tooltip="click" for a click-to-toggle disclosure, which is better for interactive content like links: click, Enter, or Space opens it, keyboard activation moves focus to the first link inside, and Escape closes it and returns focus to the hotspot. Set tooltip="none" to disable tooltips entirely (on hover and focus).

Content is cloned from the <map-area> into a single tooltip container that is hidden (out of the accessibility tree and tab order) while closed and placed right after the active hotspot, so Tab flows from the hotspot into the tooltip content.

JavaScript API

The regions property reads or replaces the <map-area> children. Each entry is { shape, coords, label, href, target, tooltip, disabled, content }. String content renders as plain text, never HTML; pass a Node, DocumentFragment, or <template> for rich tooltips. Reading returns a cloned DocumentFragment for areas with markup, so map.regions = map.regions round-trips.

const map = document.querySelector('image-map'); map.addEventListener('image-map:regions-changed', (e) => { console.log(e.detail.regions.length, e.detail.source); // 2 'property' }); map.regions = [ { shape: 'rect', coords: '5 8 40 44', label: 'Conference Hall', href: '/rooms/conference', content: 'Seats 120.' }, { shape: 'circle', coords: '62.5 32 10', label: 'Server Room', tooltip: 'none' }, ];

Accessibility

Each <map-area> generates a focusable anchor element (<a> when href is set, <button> otherwise) named by the area’s label (or its text content). Hover-mode hotspots are described by their own area content via aria-describedby; click-mode hotspots expose aria-expanded/aria-controls instead. The SVG overlay is aria-hidden — it handles only pointer hit-testing.

The tooltip is hidden whenever it is not showing, so it is never an empty stop in the tab order or the accessibility tree. It meets WCAG 1.4.13: it can be hovered, dismissed with Escape without moving focus, and stays until the pointer or focus leaves.

The host element uses role="group" with an aria-label derived from the image alt text. Do not put role="img" on the host — it hides the hotspots from assistive technology. In forced-colors mode the area outlines use system colours and thicken on hover/focus.

Progressive Enhancement

Without JavaScript the image renders and every <map-area> becomes a list item showing its label followed by its content. href on <map-area> only works once JS creates the hotspot anchor, so author a real link in the content when the destination must be reachable without JS. With JS, that content becomes the tooltip.

Touch Behaviour

On touch devices with tooltip="hover", a two-tap pattern is used: the first tap shows the tooltip, the second tap navigates (if href is set). For tooltip="click", tapping toggles the tooltip on/off. Press Escape or tap outside the map and tooltip to dismiss. The tooltip follows its hotspot while the page scrolls.
