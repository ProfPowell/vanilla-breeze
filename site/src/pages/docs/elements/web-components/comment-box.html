Overview

<comment-box> is a small form-associated primitive that wraps <markdown-editor> with the canonical Submit / Cancel button row. It's used standalone for top-level comment forms or as the reply-form template inside a <comment-thread>.

The component is presentational with respect to persistence. It fires comment-box:submit and you make the network call; hand the request to e.detail.waitUntil() and the box stays busy until it settles, clearing on success and keeping the text on failure. See Submit contract.

When to use which primitive

Use thisWhen
<comment-box>You want a standalone comment / reply form with Submit + Cancel and form participation.
<markdown-editor>You just want the editor — no Submit/Cancel chrome, no form participation.
<form-field>Generic input wrapper. Doesn't know about markdown.
<chat-input>Single-line chat input with send. Different shape from a paragraph comment.

Basic usage

The component auto-creates the inner <markdown-editor> + <textarea> for you and forwards placeholder to it. If you need pre-existing markdown content, use the value attribute or provide your own <markdown-editor> child explicitly. name stays on the host: the host is the form field, so the inner textarea is left unnamed and the value submits once.

Accessible name

The editor textarea is named by the label attribute. Without one it uses the text of an associated <label for> (the host is a form-associated, labelable element), and falls back to “Comment”.

Edit mode

Pre-fill via value and add the Cancel button via data-show-cancel. Customize the Submit label.

Toolbar slot

Children with slot="toolbar" are moved into the toolbar row, on the left of the Submit / Cancel buttons.

When it has children the tool row is a labelled group (role="group", “Comment tools”); it has no arrow-key roving, so it does not claim role="toolbar". You wire the click handlers; the comment-box doesn't interpret them. The slotted buttons are kept when the comment-box is moved.

Length validation + counter

Set data-min-length and / or data-max-length. When data-max-length is set, a counter is rendered next to the buttons. It is not announced on every keystroke: a status message speaks only within 10% (at least 10 characters) of the limit and when over it.

Submitting an invalid value does not fire comment-box:submit; the browser's validation message is shown on the editor and focus moves there, so the blocked submit is never silent.

Form participation

The component is form-associated via ElementInternals. Drop it inside any <form> with name set, and the markdown source submits like any other field.

Submit contract

comment-box:submit is dispatched synchronously, so the box decides what to do as soon as your handler returns. Calling preventDefault() after an await is too late: by then the event has finished and the value has already been cleared. Pick one of three outcomes inside the handler:

In your handlerWhat the box does
NothingClears the value right after the event.
e.detail.waitUntil(promise)Goes busy (aria-busy="true", Submit aria-disabled, editor read-only) until the promise settles. Resolve: clears. Reject: keeps the text and refocuses the editor for a retry.
e.preventDefault()Keeps the value and does nothing else. Call clear() yourself when appropriate (e.g. client-side checks you handle synchronously).
box.addEventListener('comment-box:submit', (e) => { const request = api.postComment(e.detail.value); e.detail.waitUntil(request); // busy until settled; clears on success request.catch(() => { showToast('Failed — your comment is still there, try again'); }); });

waitUntil() must be called while the event is dispatching (synchronously in the handler); calling it later throws an InvalidStateError.
