Overview

The <page-info> component is a disclosure panel for document provenance. Its trust bar summary shows author, date, and a trust badge at a glance. Clicking expands a detail panel with authorship, history, and AI provenance information.

Without JavaScript, the <details>/<summary> structure provides native expand/collapse behavior. With JS, the component adds relative time rendering and reading time computation.

Need to switch versions? <version-switcher> complements <page-info>: page-info answers what version is this?, version-switcher answers what other versions exist, and how do I get there?. Set data-page-info-target="ID" on the switcher to mount its version list as a section inside this panel.

Keep links out of <summary>: it is the disclosure control, so a link inside it competes with the toggle. Put the author link in the panel and plain text in the summary.

In static markup the component enhances three hooks: time[data-relative] (localized relative time, absolute date in title), any element with data-reading-time (filled with the estimated reading time), and the first .page-info-badge (trust tier).

Auto Mode

When the CMS cannot easily render the full static markup, auto makes the component self-contained. It reads the meta-tag contract fields from the page <head> and renders the panel. Every value is inserted as text, never as markup, and links are only rendered when they resolve to http: or https:.

Meta tags read in auto mode

Concept IDs link to /topics/{id}/. Set data-concept-base to point them elsewhere, for example data-concept-base="/tags/". A vb:status other than published also adds a status badge to the summary.

Provenance Vocabulary

The vb:provenance meta tag and data-provenance attribute use the controlled vocabulary defined in data-provenance. Core tokens describe how the content was produced; extension tokens compose with a core value (space-separated; labels are joined with ·). Unknown tokens are shown as written.

TokenTypeDisplay Label
humancoreHuman written
ai-assistedcoreHuman-written, AI-assisted
ai-generatedcoreAI-generated
translatedextensionTranslated
synthesizedextensionSynthesized from sources
migratedextensionMigrated content

Review level (vb:review: Unreviewed, Fact-checked, Editor-reviewed) and publication state (vb:status: Draft, Published, Archived) are declared separately; see data-review and data-status.

Verification Tiers

The badge data-trust attribute holds the runtime verification tier. The component starts at declared (or undeclared) and, when the page carries <meta name="vb:signature">, fetches the link rel="author-key" JWK and checks the signature over the canonical document. The tier is also written as visible text inside the badge (for example Human-written, AI-assisted · Verified), so it never depends on colour alone. See data-trust.

Tierdata-trustBadge textMeaning
0undeclared—No provenance metadata
1declaredSelf-declaredProvenance claimed, not verified
3verifiedVerifiedRendered content matches the cryptographic signature
−1failedSignature failedSignature present but content doesn't match, the algorithm is unsupported, or no author key is linked
−2key-unavailableKey unavailableSignature present but the author key could not be fetched or imported

The signed url is the raw href of <link rel="canonical"> (normalized when absolute; an empty string when there is no canonical link). The build-time signer and the browser verifier use the same rule, so pages with a relative canonical link, or none, still verify.

Attributes

AttributeValuesDefaultDescription
auto Boolean — Render from <meta> tags instead of light DOM
data-concept-base URL path /topics/ Auto mode: base for concept links ({base}{id}/)
data-heading-level 2–6 2 Auto mode: level of the panel section headings. Match it to where the component sits in the page outline.
data-label-* string English Override any UI string: section headings (author, history, provenance, topic), row labels (published, updated, version, authorship, ai-tools, review, status, license, concepts, keywords), tier text (tier-declared, tier-verified, tier-failed, tier-key-unavailable), vocabulary labels (provenance-{token}, review-{token}, status-{token}) and reading-time (template, default ~{n}).

Relative times use Intl.RelativeTimeFormat and reading time uses Intl.NumberFormat, both in the language of the closest [lang] ancestor. Future dates read in 3 days. Reading time counts the page's outermost [data-signable] roots at 238 words per minute (500 characters per minute for Chinese and Japanese), the same rules as <page-stats>; [data-signable="false"], hidden content and scripts are skipped.

Granularity

The author chooses what to expose by varying the content inside <page-info>. A minimal usage with only an author and date renders a compact trust bar; a fully-populated panel surfaces every metadata section. Same component, different depths — matching how photo EXIF data has a small always-present core (date, format) and expands from there.

The auto attribute renders the entire component from the <meta> tags in the document head, useful when the same metadata is needed for SEO and the visible disclosure panel.

Accessibility

  • <details>/<summary> provides native expand/collapse without JavaScript
  • The summary holds only text; links live in the expanded panel so they do not compete with the disclosure toggle
  • The trust tier is spelled out as text inside the badge and the badge colours use AA text tokens; colour is never the only signal. If static markup puts an aria-label on the badge, the component appends the tier to the authored label instead of piling up suffixes
  • Separator dots use aria-hidden="true"
  • Section headings are real headings (level set with data-heading-level), so the panel shows up in heading navigation
  • Relative time text replaces the <time> content; the datetime attribute keeps the machine-readable date and title shows the absolute date
