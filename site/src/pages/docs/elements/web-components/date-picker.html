Overview

The <date-picker> component wraps a native <input type="date"> and replaces the inconsistent browser chrome with a combobox text input and calendar popup. Users can type a date directly or pick from the calendar grid. It supports min/max date ranges, disabled dates, locale-aware formatting, and participates in form submission via ElementInternals.

Progressive enhancement: Without JavaScript, the native <input type="date"> is the whole control: the browser’s own picker, min/max, required and form submission all work. Put name on the inner input; on upgrade it moves to <date-picker> so exactly one value is submitted. The <label for> keeps naming the control after upgrade — it is forwarded to the generated text input.

Attributes

Attribute Type Default Description
name string — Form field name for submission. A name on the inner input is moved here on upgrade (the host’s own name wins if both are set).
data-disabled-dates string — Comma-separated ISO dates to disable. Optionally append :reason for visual variants (e.g. 2026-04-05:booked,2026-04-06).
data-highlight-dates string — Comma-separated ISO dates to highlight. Optionally append :category for visual variants (e.g. 2026-12-25:holiday,2026-04-15:deadline).
disabled boolean false Disables the text input and calendar button and drops the value from submission. A disabled ancestor <fieldset> has the same effect; a disabled on the inner input is moved here on upgrade.
required boolean false Marks the field as required for form validation (on the host or the inner input). Toggling it at runtime re-validates.
data-label-* string English Translate the built-in UI strings. See Localization.

Native input attributes

The following attributes are read from the child <input type="date">:

Attribute Effect
value Initial date in YYYY-MM-DD format.
min Earliest selectable date.
max Latest selectable date.
name Submission name for the no-JS fallback; moved to the host on upgrade.
id Target for <label for>. Its labels name the generated text input (a <label for> pointing at the <date-picker> itself works too, as does an aria-label on either).

Date Constraints

Use min and max on the native input to restrict the date range. Use data-disabled-dates to exclude specific dates. Disabled days stay reachable with the keyboard (so focus never gets lost) but cannot be selected by click, Enter, or typing.

Disabled Date Styles

Append a :reason to any disabled date to get a distinct visual treatment. Dates without a reason use the default faded style. Three built-in reasons are provided:

Reason Visual Treatment Use Case
booked Strikethrough text Reservations, appointments already taken
unavailable Diagonal hatching Out-of-service, maintenance, closed periods
holiday Accent color, bold Public holidays, special dates

Custom reasons are also supported. Any value is set as data-disabled-reason on the calendar button, so you can target it with CSS:

td button[data-disabled-reason="maintenance"] { opacity: 0.5; background: var(--color-warning-subtle); }

Highlighted Dates

Use data-highlight-dates to visually mark key dates that remain selectable. Append a :category to each date for distinct styling. Three built-in categories are provided:

Category Visual Treatment Use Case
holiday Warm accent background and text Public holidays, observances
deadline Red accent background and text Due dates, cutoff dates
event Blue accent background and text Meetings, scheduled events

Dates without a category get a subtle default highlight. All highlighted dates remain fully selectable.

Custom categories are supported. Any value is set as data-highlight on the button:

td button[data-highlight="payday"] { background: oklch(from green l c h / 0.1); border-color: oklch(from green l c h / 0.3); font-weight: 600; }

Form Integration

The component is form-associated via ElementInternals and works inside <form-field> for validation messaging. The submitted value is always in ISO format (YYYY-MM-DD). Form reset restores the inner input’s authored value, and a disabled <fieldset> disables the picker. To clear a date, empty the text input (or assign value = ''): the field becomes empty, re-validates, and fires date-picker:change.

The host owns validity: valueMissing (required and empty), rangeUnderflow (before min) and rangeOverflow (after max). Submitting an invalid form focuses the visible text input. Once upgraded, the hidden native input is detached from the form, so it never blocks submission or sends a second value. It still mirrors the host’s message, so <form-field> shows it (an authored data-message-rangeunderflow and similar attributes on the inner input win). Changing min or max never rewrites the value: a date that falls outside the new range is kept and marked invalid.

Text Entry

The date input accepts typed dates in the following formats. The calendar navigates live as you type.

Format Example
ISO date 2026-04-15 or 2026/04/15
Month name + day + year April 15, 2026 or Apr 15 2026
Day + month name + year 15 Apr 2026
Month + year (partial) April 2026 — navigates calendar without selecting a day
CJK numeric 2026年4月15日
Japanese era (和暦) 令和8年4月15日, 令和元年5月1日 or R8/4/15 — when the picker’s locale is Japanese

Whatever the picker displays in its locale can be typed back in, including the CJK forms. Full-width digits are accepted in the CJK forms, and era dates outside their era (令和元年4月30日) are rejected.

Locale-aware month names are also accepted. Ambiguous numeric formats like 4/15/2026 are intentionally rejected to avoid locale confusion, and so are impossible dates (2026-02-31, April 31, 2026) — they are not rolled over into the next month. On blur, empty text clears the date; text that does not parse to a selectable date reverts to the current value.

Calendar grid

Key Action

Arrow Up / Arrow Down Move focus one week.

Events

Event Detail Description
date-picker:change { value, date, source } Fired when the selected date changes (not on form reset). value is the ISO string ('' when cleared), date a Date or null. source is 'pointer' (grid click), 'keyboard' (grid Enter/Space or a typed date) or 'api' (.value assignment).
date-picker:open — Fired when the calendar opens.
date-picker:close — Fired when the calendar closes.

Accessibility

The text input uses role="combobox" with aria-haspopup="dialog" and aria-expanded, following the W3C Date Picker Combobox pattern. It takes its accessible name from your <label> (via aria-labelledby), since the native input is hidden from assistive technology after upgrade. The calendar popup uses role="dialog" with an accessible label. The date grid uses role="grid" with a button in each gridcell and a roving tabindex. Today is marked with aria-current="date"; the selected day’s gridcell (<td>) carries aria-selected="true" (buttons do not support it); disabled dates use aria-disabled="true" rather than the native disabled attribute, so they remain focusable during keyboard navigation but cannot be chosen. The month/year header uses aria-live="polite" so screen readers announce navigation changes.

Localization

The locale is the nearest lang attribute (on the element or an ancestor), falling back to the browser language. It drives the displayed date (Intl.DateTimeFormat), the month name, the weekday column headers, typed month names, and the first day of the week (from Intl.Locale week info). The submitted form value is always ISO-formatted regardless of display locale.

A BCP 47 calendar extension in lang changes the displayed calendar. lang="ja-JP-u-ca-japanese" shows Japanese era dates (令和8年4月15日), which can also be typed back in, as can R8/4/15. See Internationalization.

JavaScript API

Property Type Description
value string Get or set the selected date as an ISO string (YYYY-MM-DD). Assigning '' or null clears it; malformed or impossible dates are ignored.
min string Get or set the earliest selectable date. Updates the calendar and validity immediately; an earlier current value is kept and flagged rangeUnderflow.
max string Get or set the latest selectable date. Updates the calendar and validity immediately; a later current value is kept and flagged rangeOverflow.
form, validity, validationMessage, willValidate — Standard form-control properties (via ElementInternals).
checkValidity(), reportValidity() method Standard constraint validation; reportValidity() anchors the message on the text input.

Recipe: Date Range (Linked Pickers)

Two standard <date-picker> elements can be linked for date range selection. Picking the start date sets min on the end picker. The start stays free, so the user can move it past an existing end date. The end date is then kept but marked invalid (rangeUnderflow), its message appears, and submitting focuses it until it is fixed. No custom range component needed.

const checkIn = document.getElementById('check-in'); const checkOut = document.getElementById('check-out'); const floor = '2026-04-01'; // The start date constrains the end picker (never below the floor) checkIn.addEventListener('date-picker:change', (e) => { checkOut.min = e.detail.value > floor ? e.detail.value : floor; // An existing end date before the new start is kept but now invalid: // show its message straight away instead of on its next blur. if (checkOut.value) checkOut.closest('form-field')?.validate(); });

The min and max properties update the calendar constraints and validity in real time. Dates outside the allowed range are greyed out in the grid. A value already outside the new range is kept, so checkValidity() returns false and validationMessage explains the range. The demo also moves check-out to at least one night after check-in, and restores the derived min on form reset.

Need richer visual range selection? For an always-visible calendar with range highlighting, multi-date selection, or event display, see <calendar-wc>.
