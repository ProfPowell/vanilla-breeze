Overview

The <time-index> component enhances a static changelog or timeline with relative dates, version filtering, sort toggle, and a recently updated pages feed. Without JavaScript, the changelog renders in document order as plain, readable markup.

Per-page history? <time-index> is a site-wide changelog of releases. For switching between versions of a single page over time (release versions or per-page edit history), use <version-switcher>.

Entry Structure

The component finds its entries through .changelog-entries. Two shapes are supported:

  • One container. The <li>, <article> or <section> children of a single .changelog-entries are the entries. Sorting reverses them; filtering hides the ones that do not match.
  • One container per release. Each release is a top-level child of <time-index> (usually a <section>) holding its own .changelog-entries. Sorting reverses the releases and the entries inside each; filtering shows or hides whole releases. The demo above uses this shape.

Version Filtering

Add versions to inject a select that filters the changelog to one version. Each entry (or release) gets its version from, in order:

  1. its data-version attribute;
  2. the text of its own .version-tag element;
  3. an id of the form v2-1-0, read as v2.1.0 (dots become dashes in the id).

The options list the versions found that way, in document order. After each change a polite live region announces how many entries are shown.

Recently Updated Pages

Set updates-src to append a feed of up to ten recently updated pages, loaded from a JSON endpoint. The endpoint returns an array of { "title", "href" | "url", "modified" | "date" } objects. The feed is built with DOM APIs, so titles are always plain text, and only http(s) or relative links are kept: an item with a javascript: or other scheme is dropped. Moving the element does not add a second feed.

Behavior

  • Relative dates: <time data-relative> elements show relative text (e.g. “2 weeks ago”). The absolute date stays available in the element’s title and datetime.
  • Order: A labelled select offers “Newest first” (the order you wrote, which the component takes to be newest first) and “Oldest first” (reversed). It always shows the order in force.
  • Version filter: When enabled, a select lists every version; filtering is announced in a polite live region.
  • Progressive enhancement: Without JavaScript, the static ordered list renders in document order.

Accessibility

  • Uses semantic <ol>, <time>, and <mark> elements
  • The order control is a native select with a visible label, so it names the current order instead of an action
  • The version select is labelled, and each filter change is announced (“Showing 1 of 3 entries for v2.0.0”)
  • Relative dates keep the absolute date in title
  • Change type badges use <mark> for semantic highlighting
  • Keyboard accessible — tab through controls and links
  • Without JavaScript, content remains fully readable
