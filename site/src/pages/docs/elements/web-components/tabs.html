Overview

The <tab-set> component transforms a group of <details> elements into a tab interface. Without JavaScript, it works as an accordion. With JavaScript, it adds keyboard navigation and ARIA linkage attributes while preserving native <details>/<summary> semantics.

Child Details Attributes

Attribute Type Description
name string Shared name for exclusive behavior. All tabs should have the same name. On upgrade, a missing, mixed, or page-shared name (another <details> outside this set uses it) is replaced with a per-instance tab-set-N, so two tab-sets never close each other's tabs.
open boolean Initially selected tab. If none specified, first tab is selected.

Panels

Each <details> holds one <summary> and exactly one panel element after it. Wrap the panel content in a <section>: the component names it from its tab with aria-labelledby, which makes it a region. A <div> panel can't carry that name, and two or more loose children would each be laid out as a separate panel.

Progressive Enhancement

The component is built on the native <details> element, which provides built-in expand/collapse functionality. The shared name attribute (supported in modern browsers) ensures only one panel is open at a time.

Without JavaScript

When JavaScript is disabled or fails to load, the tabs fall back to an exclusive accordion: the panels stack under their summaries, and the shared name still keeps only one open at a time. When the element is defined, the summaries move into the tab row.

With JavaScript

  • Native <details>/<summary> semantics are preserved (no role overrides)
  • aria-controls and aria-labelledby link each tab to its panel
  • aria-expanded state is managed on each summary
  • tabindex is managed for roving focus
  • Keyboard navigation (arrow keys, Home, End) is enabled
  • A labelled host gets role="group"

Keyboard Navigation

When focused on a tab, the following keyboard shortcuts are available:

Key Action
ArrowRight Move to and activate the next tab (the previous one in right-to-left text)
ArrowLeft Move to and activate the previous tab (the next one in right-to-left text)
ArrowDown / ArrowUp Next / previous tab, with data-orientation="vertical" only
Home Move to and activate the first tab
End Move to and activate the last tab

Many Tabs and Right-to-Left

When the tabs don't fit on one line they wrap onto another row, so a narrow screen never scrolls sideways. In right-to-left text the row runs from the right, and the arrow keys follow what you see: ArrowLeft moves to the next tab.

Events

The component dispatches a custom event when a tab is changed.

Event Detail Description
tab-set:change { index, previousIndex, tab, panel } Fired once each time a tab is activated (click, arrow key, or setting details.open), from the newly opened tab. index is the new 0-based tab index, previousIndex the tab it replaced, tab its <details> and panel its panel. Not fired during setup or when the open tab is selected again.
tab-set:tabs-changed { tabs, source: 'property' } Fired after the tabs property rebuilds the set.

Accessibility

Native Semantics

The component preserves native <details>/<summary> semantics. It does not override roles with role="tablist", role="tab", or role="tabpanel". Instead, it layers ARIA linkage attributes on top of the native elements:

  • aria-controls on each <summary> points to its panel
  • aria-labelledby on each panel points back to its summary
  • aria-expanded reflects which tab is currently open
  • tabindex is managed via the roving tabindex pattern (active tab gets 0, others get -1)
  • A host with aria-label or aria-labelledby (and no role of its own) gets role="group", so the name is announced. An unlabelled tab-set gets no role: aria-label on a role-less element is ignored.
  • In forced-colors mode the selected tab's border uses the system Highlight colour.

Screen Reader Behavior

Screen readers will recognize the native disclosure widgets and allow users to navigate between tabs using the roving tabindex pattern.

JavaScript API

Control tabs by setting open on the underlying <details> elements, or replace the whole set with the tabs property.

const tabs = document.querySelector('tab-set'); // Get all tab panels const panels = tabs.querySelectorAll('details'); // Programmatically open a tab panels[1].open = true; // Opens the second tab // Check which tab is open const openIndex = [...panels].findIndex(p => p.open); console.log('Open tab index:', openIndex); // Listen for changes tabs.addEventListener('tab-set:change', (e) => { console.log('New tab:', e.detail.index); }); // Read the tabs as data, or assign an array to rebuild the set console.log(tabs.tabs); // [{ id, label, content, active }, ...] tabs.tabs = [ { label: 'Overview', content: '

Progressive enhancement: View Transitions work in Chrome 111+, Safari 18+ and Firefox 144+ (support table). In unsupported browsers, tabs switch instantly — no animation, no errors.

Styling

Restyle the tabs and panels, but leave the host's display alone: the tab row and panel placement depend on it. Style the selected tab with details[open] > summary, the same selector the component uses.

/* Individual tabs */ tab-set > details > summary { padding-inline: var(--size-l); } /* Selected tab */ tab-set > details[open] > summary { color: var(--color-primary); border-block-end-color: var(--color-primary); } /* Tab panels */ tab-set > details > section { padding: var(--size-l); }

Dark mode

Tabs use theme tokens, so data-mode="dark" on the page (or any ancestor) is all a dark set needs.

Print

With the print utilities loaded, a printed tab-set shows every panel in order, each under its tab label as a heading.
