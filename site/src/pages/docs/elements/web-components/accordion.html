With indicator="custom", the glyphs come from the --indicator-closed and --indicator-open custom properties (defaulting to ▸ and ▾). Their values are CSS strings, so use CSS escapes such as '\2192', not JavaScript-style \u{...} escapes.

/* Arrows: → closed, ↓ open */ accordion-wc.arrows { --indicator-closed: '\2192'; --indicator-open: '\2193'; } /* Emoji: red circle closed, green circle open */ accordion-wc.dots { --indicator-closed: '\1F534'; --indicator-open: '\1F7E2'; }

Keyboard Navigation

When focused on a panel header, the following keyboard shortcuts are available:

Key Action
ArrowDown Move focus to the next panel header
ArrowUp Move focus to the previous panel header
Home Move focus to the first panel header
End Move focus to the last panel header
Enter / Space Toggle the focused panel (native behavior)

Events

The component dispatches bubbling events when panels are toggled and when the panel set is replaced through the panels property.

Event Detail Description
accordion-wc:toggle { index: number, open: boolean } Fired when a panel is opened or closed. index is the panel's 0-based position.
accordion-wc:panels-changed { panels: Array, source: 'property' } Fired after panels is assigned and the accordion has been rebuilt. panels is the array that was assigned.
const accordion = document.querySelector('accordion-wc'); accordion.addEventListener('accordion-wc:toggle', (event) => { const { index, open } = event.detail; console.log(`Panel ${index} is now ${open ? 'open' : 'closed'}`); });

JavaScript API

The component exposes methods for programmatic control. Out-of-range indexes are ignored. When transition is set, open(), close() and toggle() run inside a View Transition; openAll() and closeAll() do not.

Method Parameters Description
open(index) index: number Open a specific panel by its 0-based index.
close(index) index: number Close a specific panel by its 0-based index.
toggle(index) index: number Toggle a specific panel open/closed.
openAll() - Open all panels. Does nothing when single is set.
closeAll() - Close all panels.
const accordion = document.querySelector('accordion-wc'); // Open the second panel accordion.open(1); // Close the first panel accordion.close(0); // Toggle the third panel accordion.toggle(2); // Open all panels (not in single mode) accordion.openAll(); // Close all panels accordion.closeAll();

Data API: panels

The panels property reads and writes the panel set as plain data, so the same accordion can be authored in HTML or driven from JavaScript.

Property Type Description
panels (get) Array<{ id?, summary, content, open }> One record per <details>: its id (if any), the trimmed summary text, the panel's innerHTML as content, and whether it is open.
panels (set) Array<{ id?, summary, content, open? }> Removes all children and rebuilds one <details> per record. summary is set as text; content is inserted as HTML into a panel wrapper. id becomes the <details> id and open: true opens it. With single, the rebuilt panels share a generated name. Open/closed state is not preserved across assignments. Dispatches accordion-wc:panels-changed.
Note: content is assigned with innerHTML. Only pass trusted or sanitised HTML.

Accessibility

ARIA Attributes

The component automatically applies ARIA attributes for accessibility:

  • aria-expanded on each summary indicates open/closed state
  • aria-controls links summaries to their panels
  • aria-labelledby links panels back to their summaries
  • role="region" on each panel, named by its summary via aria-labelledby

Because each region has an accessible name, screen readers may expose open panels as region landmarks. The WAI-ARIA Authoring Practices caution against the region role when many panels can be open at once, since it adds landmark clutter. The component applies it to every panel unconditionally, so prefer single or a small number of panels where that matters.

Screen Reader Announcements

Screen readers will announce the expanded/collapsed state when panels are toggled. The keyboard navigation allows users to move between headers without expanding panels.

Focus Management

Focus remains on the summary element when toggling, and arrow key navigation moves focus between summaries without changing the open state.

View Transitions

Add transition to animate panel content when opening and closing using the View Transitions API. The content fade composes with the existing CSS ::details-content height animation — height animates via CSS, content appearance via VT.

ValueEffect
fade (default)Crossfade panel content
slideSlide panel content in from the side
scaleScale panel content in/out

The standalone demo shows all three transition types side by side.

Progressive enhancement: View Transitions work in Chrome 111+, Safari 18+ and Firefox 144+ (support table). In unsupported browsers, panels open and close with the existing CSS height animation only.
