Overview

Experimental stub. <comment-wc> pins comments to a <review-surface>, and Vanilla Breeze does not ship <review-surface>. Unless your page defines one (an element with an addPin({ x, y, text }) method), the action is always unavailable. The API may change or the element may be removed. For a working discussion UI today, use <comment-thread>.

The <comment-wc> component is an “Add comment” action for <selection-menu>. It looks for a <review-surface> (an ancestor, or the one whose for matches the menu's for) each time it is clicked and adds a pin at the selection's position.

If no <review-surface> is found, the button is marked aria-disabled="true", styled as inert, and described by visually-hidden text explaining why. It stays focusable so that explanation can be reached.

For private reader notes (not shared), use <note-wc> instead.

Looking for a full threaded discussion container? Use <comment-thread> instead. <comment-wc> is a single inline action button used inside a <selection-menu> toolbar — <comment-thread> is the persistent multi-comment container with replies, reactions, and edit/delete.

Usage

Select text and click the comment icon to create a pin.

Accessibility

  • Button is named “Add comment” in both states.
  • Unavailable state: aria-disabled="true" (not disabled, so it stays focusable) plus aria-describedby pointing at visually-hidden text (“Comments are unavailable: this content has no review surface.”). No title tooltip.
