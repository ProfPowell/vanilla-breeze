Overview

The <page-toc> component creates a table of contents that highlights the current section as you scroll. It supports two modes:

  • Auto-generated: Scans the page for headings and builds the ToC automatically
  • Manual markup: Enhances existing navigation with scroll-spy (progressive enhancement)

Attributes

Attribute Type Default Description
levels string h2,h3 Comma-separated heading levels to include
scope string main CSS selector for the container to scan. The first match is used, so be specific (the docs layouts use main article)
data-title string On this page Summary text shown above the generated ToC, also used as the nav’s aria-label
orientation horizontal — (vertical) Renders an inline, horizontally scrollable bar instead of the vertical tree. See Horizontal bar

Excluding Headings

Headings inside live examples or embedded content can pollute the table of contents. Add data-toc-ignore to exclude them.

On an ancestor container

All headings inside the marked container are skipped. This is the most common pattern for doc pages with inline examples:

<section data-toc-ignore> <h2>Demo Heading</h2> <p>This heading will not appear in the ToC.</p> </section>

On a single heading

Exclude an individual heading while keeping its siblings:

<h2 data-toc-ignore>This heading is skipped</h2> <h2>This heading appears in the ToC</h2>

Ignoring one h2 does not ignore the h3s after it: they are listed under the previous h2. To drop a whole section, put the attribute on the <section>.

Skipped automatically

Headings inside a <dialog> or a <browser-window>, and headings that are not rendered (hidden, or a data-visible variant hidden at this width), are skipped too — the same list <heading-links> uses. Headings inside a closed <details> are kept: following the link opens it. Headings without an id are skipped; <heading-links> supplies ids. An auto-generated ToC updates itself when headings are added or removed or data-toc-ignore changes; see data-toc-ignore.

Auto-Generated Mode

When the component is empty, it automatically scans the page for headings (with IDs) and builds the table of contents.

Requirements

  • Headings must have id attributes (use heading-links to auto-generate)
  • Headings must be within the scope container (default: main)

Manual Markup Mode

For progressive enhancement, provide your own markup. The component will add scroll-spy behavior without modifying your structure. Express hierarchy by nesting a .list inside an .item — nested lists collapse unless their branch contains the active link, exactly like the generated tree.

Scroll-Spy Behavior

The component uses IntersectionObserver to track which section is currently visible and highlights the corresponding link.

  • The first visible heading in the viewport is highlighted
  • Links receive the .active class and aria-current="true"
  • URL hash is updated when clicking links
  • Syncs with browser back/forward navigation (percent-encoded hashes such as #caf%C3%A9 are decoded before matching ids)

Responsive Behavior

The component adapts to different screen sizes:

Wide Screens (1024px+)

  • ToC is always visible — the summary acts as a heading and does not collapse it
  • Position: sticky for sidebar placement (when the sticky system is active)
  • Sub-sections collapse except the branch containing the active section

Narrow Screens

  • Collapsible disclosure pattern — click the summary to expand/collapse
  • Sub-sections collapse except the active branch, as on wide screens

Sidebar Layout

Common pattern: ToC in a sidebar alongside main content.

Horizontal Bar

Add orientation="horizontal" for an inline, horizontally scrollable bar — useful above an article or under a sticky header. The summary is hidden, nesting is flattened so every heading is a chip in one row, and the active link gets an underline instead of a start border. With the sticky system active the bar sticks below --sticky-offset.

Events

Event Detail Description
page-toc:navigate { id: string } Fired when a ToC link is clicked
const toc = document.querySelector('page-toc'); toc.addEventListener('page-toc:navigate', (event) => { console.log('Navigated to:', event.detail.id); });

JavaScript API

Member Description
refresh() Rebuild ToC after dynamic content changes (manual mode re-scans your links)
entries (read-only) Array of { id, text, level } for the headings in the ToC
// After dynamically adding content const toc = document.querySelector('page-toc'); toc.refresh();

Accessibility

  • Uses semantic <nav> element with aria-label
  • Active link marked with aria-current="true"
  • Keyboard accessible - tab to navigate, enter to activate
  • Focus moves to the target heading after navigation (it receives tabindex="-1" if it is not already focusable)
  • Respects prefers-reduced-motion: link activation jumps instead of smooth-scrolling
  • The ToC label is data-title, not the global title attribute, so no hover tooltip covers the list

Styling with CSS Custom Properties

The component uses scoped styles via @scope. Override these properties for customization:

  • --color-interactive - Active link color
  • --color-text-muted - Inactive link color
  • --color-surface-raised - Hover background
  • --border-width-medium - Active link border

Best Practices

  • Use with heading-links to ensure headings have IDs
  • Keep ToC visible on wide screens for easy navigation
  • Use levels="h2,h3" for most documentation pages
  • Add data-toc-ignore to example containers that include headings
  • Consider manual markup for static sites (better initial render)
