Overview

A star rating widget built the Vanilla Breeze way — CSS-first with native HTML, enhanced with JS, wrapped in a web component for convenience. Supports half-stars, custom icons via <icon-wc>, read-only display, and native form participation.

Three Layers

The rating widget follows the progressive enhancement model:

  1. CSS-only — Author writes a fieldset with radio inputs. :has() selectors handle visual selection and hover. Works without JS.
  2. JS enhancement — add data-effect="rating" to the fieldset. The rating effect (src/effects/rating.js, in the default bundle) adds clear/unrate, rating:change events, and a clear announcement.
  3. Web component — <star-rating> generates the fieldset (already opted into the effect). Form-associated via ElementInternals: FormData gets exactly one name=value entry and no hidden inputs are needed.

CSS-Only Usage

Write a <fieldset data-rating> with radio inputs. The CSS handles selection highlighting and hover preview via :has() selectors. No JavaScript required.

Half Stars

Add data-rating-half to the fieldset and use data-half="left" / data-half="right" on labels. Each star gets two radio inputs: one for the half value, one for the full value. For the web component, use the allow-half attribute instead.

JS Enhancement

The enhancement is opt-in: add data-effect="rating" to a <fieldset data-rating>. The rating effect (src/effects/rating.js, included in the default bundle) then adds:

  • Clear/unrate: activate the already-selected star again (click, or Space), or press Delete / Backspace on it. The radio is unchecked and the value resets to 0.
  • rating:change event: fires on the fieldset with { detail: { value } } for every change, including clear.
  • Clear announcement: a persistent polite live region inside the fieldset announces Rating cleared (override with data-label-cleared). Selecting a star is not announced again — the checked radio already announces itself.

Without data-effect="rating" the fieldset stays CSS-only and no rating:change events fire.

const rating = document.querySelector('#product-rating'); rating.addEventListener('rating:change', (e) => { console.log('New rating:', e.detail.value); });

Attributes

Attribute Default Description

max 5 Number of stars
label "Rating" Legend text (visually hidden)
allow-half — Enable half-star increments
readonly — Display-only mode, no interaction

required — Makes rating required for form validation

data-label-readonly "{label}: {value} out of {max}" Read-only summary (role="img" name)
data-label-required "Please select a rating" Validation message
data-label-cleared "Rating cleared" Clear announcement

Form Participation

The web component uses ElementInternals to participate in native forms — no hidden inputs. It supports FormData (exactly one name=value entry: the internal radios are detached from the form), the required attribute, Constraint Validation API, form.reset() (back to the value attribute), and :invalid/:valid pseudo-classes.

All attributes are live: changing value, max, label, required or readonly after upgrade updates the stars. The value property can be set before the element is connected (the usual framework pattern) and is applied when the stars are built.

Keyboard Navigation

Key Action
ArrowRight / ArrowDown Select next star
ArrowLeft / ArrowUp Select previous star
Space on the selected star / Delete / Backspace Clear the rating (with data-effect="rating")
Tab Move focus into/out of the rating group

Arrow-key navigation is provided natively by the radio group; only clearing needs the effect.

Events

Event Detail Description
rating:change { value: number } Fired on the fieldset when the rating value changes (including clear to 0).

Accessibility

  • <fieldset> + <legend> groups the radios with an accessible label
  • Each radio has aria-label announcing the star count
  • Native radio keyboard navigation (arrow keys) requires no custom handling
  • Focus-visible outline appears on the active star label
  • The effect announces clears through one persistent live region per fieldset; selection is announced by the radio itself
  • Read-only mode uses role="img" with a descriptive, localizable aria-label
  • Filled and empty stars differ by shape, not just colour: empty text stars are outlines, filled ones are solid (hover preview too). In forced-colours mode filled stars use Highlight and empty outlines CanvasText
  • Read-only partial stars fill from the inline start, so RTL pages fill from the right

Styling

Override the rating colours with --rating-color (filled) and --rating-color-empty (empty outline) on the fieldset, the component, or any ancestor:

/* Custom colours */ star-rating, [data-rating] { --rating-color: var(--color-error); --rating-color-empty: var(--color-text-muted); } /* Custom size */ [data-rating] > label { font-size: 2rem; }

Progressive Enhancement

Each layer adds capability without breaking the previous one:

  • No JS: CSS-only radios work for selection, hover preview, form submission, and keyboard navigation
  • With JS: Clear/unrate, events, and announcements enhance the experience
  • Web component: Convenience wrapper that generates the markup and adds form participation via ElementInternals
