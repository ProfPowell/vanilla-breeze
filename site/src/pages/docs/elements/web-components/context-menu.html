Description

The <context-menu> component provides a custom right-click menu that opens at the cursor position. It supports keyboard navigation, separators, danger items, and disabled states. Shares menu styling patterns with <drop-down>.

It is keyboard-operable too: a trigger that is not already focusable gets tabindex="0", and Shift+F10 or the ContextMenu key opens the menu at the trigger. Focus returns to the trigger when the menu closes. Any action in a context menu should still be reachable another way — a toolbar button or inline control — because touch users and many screen reader users never right-click.

    Disabled Items

    Mark an item data-disabled. It gets aria-disabled="true", stays in the arrow-key order (so screen reader users learn it exists, per the APG menu pattern), and cannot be activated: no click handlers run, the menu stays open, and its shortcut does nothing. A native disabled button is skipped by the arrow keys because it cannot take focus.

    With Icons

    Add <icon-wc> or inline <svg> inside buttons. The existing flex layout handles alignment automatically.

    Keyboard Shortcuts

    Add data-shortcut to any button to display a keyboard shortcut badge and bind a real global keyboard shortcut. Pressing the shortcut anywhere on the page (outside text fields) triggers the button's click. The badge is platform-aware — meta shows ⌘ on Mac and Ctrl elsewhere — and the item gets a matching aria-keyshortcuts. Shortcuts are cleaned up when the component disconnects.

    Warning: the binding is page-wide and calls preventDefault(). Binding meta+c, meta+x, meta+v or meta+a would break native copy, cut, paste and select-all everywhere on the page. Choose combos that do not shadow browser or OS shortcuts (function keys and shift+ letters are safe choices).

    •

    Group Labels

    Use <li data-group> to create labeled sections within the menu. Group labels are non-interactive and visually separated from items. Non-first groups automatically get a top border. On upgrade, each label and the items after it (up to the next label or separator) are wrapped in <li role="group" aria-labelledby> so assistive technology announces the group name; the authored flat list is restored on disconnect, and the items property reads through the wrapper.

    Keyboard Navigation

    Key Action
    Shift+F10 / ContextMenuOpen the menu at the focused trigger
    Arrow DownMove to next item
    Arrow UpMove to previous item
    HomeMove to first item
    EndMove to last item
    Enter / SpaceActivate focused item
    EscapeClose menu and return focus to the trigger
    TabClose menu

    JavaScript API

    Properties

    Property Type Description
    items Array Get or replace the menu as data. Entries are { label, value?, href?, shortcut?, disabled? }, { group } or { separator: true }. Setting it rebuilds the menu and fires context-menu:items-changed.
    isOpen boolean Read-only. Whether the menu is open.

    Methods

    Method Description
    close() Close the context menu

    Events

    Event Description
    context-menu:open Fired when the menu opens
    context-menu:close Fired when the menu closes
    context-menu:select Fired when an item is activated by click, keyboard or its shortcut. detail.item is the activated element, detail.value its data-value. Not fired for disabled items.
    context-menu:items-changed Fired after the items setter rebuilds the menu (detail: { items, source: 'property' })
    const menu = document.querySelector('context-menu'); menu.addEventListener('context-menu:select', (e) => { console.log('Selected:', e.detail.value, e.detail.item); }); // Replace the menu from data menu.items = [ { group: 'File' }, { label: 'Rename', value: 'rename', shortcut: 'f2' }, { label: 'Share', value: 'share', disabled: true }, { separator: true }, { label: 'Delete', value: 'delete' }, ]; menu.addEventListener('context-menu:open', () => { console.log('Menu opened'); });

    Accessibility

    • Opens from the keyboard: the trigger is made focusable when needed, and Shift+F10 / ContextMenu open the menu at the trigger
    • The trigger carries aria-haspopup="menu", aria-expanded and aria-controls
    • Full keyboard navigation (Arrow keys, Home/End, Enter, Escape); focus returns to the trigger on close
    • Menu items have role="menuitem", their <li> wrappers role="none", separators role="separator"
    • Group labels name a role="group" through aria-labelledby
    • data-disabled items expose aria-disabled="true" and stay reachable but inert
    • Keyboard focus shows a focus ring, not only a background tint
    • Closes on click outside, Escape, or scroll
    • Menu is positioned within viewport bounds
