Overview

The <nav-bar> component is the top-level navigation primitive for VB sites and apps. It does one thing: synchronizes aria-current="page" on the matching link as the URL changes, so consumers stop hand-rolling that logic. There are two ways to use it:

  • HTML-first: wrap your existing <a> children — pathname matching and popstate sync run automatically.
  • JS-first: assign .items = [...] and let the default renderer build the link list from data.

It is deliberately small — no router, no click interception, no custom renderer in v1. See Reactive integration for the trade-offs.

HTML-first

Wrap a normal set of links. Without JS the nav still works as plain HTML; with JS, aria-current="page" appears on the link that best matches location.pathname.

Matching policy:

  1. Each link is resolved against the document base URL (so relative hrefs and <base> work) and compared by origin plus pathname. Trailing slashes, query strings and hashes are ignored, so /docs matches /docs/. Other-origin, non-http(s) and bare #fragment links never match.
  2. Exact pathname match wins.
  3. Otherwise, longest href prefix wins. So on /docs/elements/web-components/nav-bar/ the link /docs/elements/ beats /docs/.
  4. Ties broken by first-in-DOM-order.

Add data-match="exact" on the <nav-bar> to opt out of prefix matching.

Nested links (e.g. inside <drop-down> or <li>)

JS-first

When your routes live in JSON or are produced by code, assign .items. The component renders <a> children with the default markup.

const nav = document.querySelector('nav-bar'); await new Promise(r => nav.addEventListener('nav-bar:upgraded', r, { once: true })); nav.items = [ { href: '/', label: 'Home' }, { href: '/dashboard/', label: 'Dashboard', icon: 'gauge' }, { href: '/settings/', label: 'Settings' }, { href: 'https://github.com/...', label: 'Repo', external: true }, ];

The setter is idempotent — assigning a deep-equal array is a no-op and emits no event. It replaces only the direct <a> children; other content (and nested data-nav-link anchors) stays. In nested mode the rendered links get data-nav-link so they join the candidate set. If .current is explicitly owned, the owned value is re-applied to the new links and no nav-bar:current-changed fires.

Item shape

FieldTypeDescription
hrefstringRequired. Anchor target. Only http:, https: and relative URLs are rendered; any other scheme (javascript:, data:, …) produces an anchor with no href.
labelstringRequired. Link text.
routestringOptional. .current diff target. Falls back to href.
iconstringOptional. Renders <icon-wc name="..."> before the label.
externalbooleanAdds target="_blank", rel="noopener noreferrer", and an SR-only "(opens in new tab)" suffix (override with data-label-new-tab on the host).
badgestring | numberOptional pill chip after the label.

Properties

PropertyTypeDescription
.itemsNavItem[] | nullRead returns last assignment, else inferred from children. Set replaces children with default renderer; idempotent.
.currentstring | nullRead returns the active route (data-route or href of the aria-current link). Set takes ownership and disables URL sync until .releaseCurrent().

Methods

MethodDescription
.releaseCurrent()Restore auto mode after explicit assignment to .current. Re-runs pathname matching.
.refresh()Manually re-run pathname matching. Browsers with the Navigation API re-sync on pushState automatically; call this for routers in other browsers, or frameworks (e.g. HTML-Star) that change the URL without firing popstate. No-op when .current is explicitly owned.

EventDetailWhen
nav-bar:upgraded—After every connect, including a reconnect after the element is moved.

Reactive integration (important caveat)

v1 does not support driving .items from a signal/effect with preserved in-flight state. Each .items assignment fully replaces children. There is no keyed diff, so a link mid-focus loses focus on reassignment, and any <icon-wc> inside re-mounts. This is fine for nav (links don't carry load-bearing state) but it is not the right primitive for reactive route lists.

If you need reactive routing with preserved state, use your framework's link primitive instead of <nav-bar>:

  • Montane — use Link() from montane/router.js. It is bound to the Montane router and reactively tracks active state. <nav-bar> would duplicate that work less well.
  • View-switching without a router — use <content-swap>.
  • Other frameworks — keep using their Link primitive. <nav-bar> is a drop-in for HTML-first sites and JSON-driven apps without a reactive router.

If your use case needs renderItem or keyed diff, open an issue with the concrete scenario so we can scope a Phase 2.

Composition

  • With <mobile-menu> — mobile-menu is a breakpoint observer, not a shell. Below its breakpoint it hides sibling nav, nav-bar and site-tools elements in the header and shows the trigger for your popover panel. For active-link sync in the mobile menu, put a second nav-bar inside that popover panel: <mobile-menu><button popovertarget="m"></button><nav popover id="m" aria-label="Site menu"><nav-bar>...</nav-bar></nav></mobile-menu>.
  • With <drop-down> — wrap an item in <drop-down> for a sub-menu and tag the item's canonical link with data-nav-link (see Nested links). Without any data-nav-link, nav-bar manages only its direct <a> children.
  • Not a router and not a view-switcher. See Reactive integration.

Accessibility

  • Sets role="navigation" on the host if absent, unless the host contains a <nav>. Then the inner <nav> is the only landmark, and the label belongs on it.
  • aria-current="page" on the active link only. In forced-colors mode the current link also gets an outline and underline, because the background and colour cues are dropped.
  • External links get target="_blank", rel="noopener noreferrer", and an SR-only "(opens in new tab)" suffix. Translate it with data-label-new-tab on the host.
  • Native keyboard navigation — Tab through links, Enter / Space activates. No custom focus management.
