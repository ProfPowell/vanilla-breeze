Overview

The <foot-notes> component works with <foot-note> elements to create accessible footnotes. Without JavaScript, footnotes appear inline. With JavaScript, they become superscript links with a collected list at the bottom.

The Vanilla Breeze frameworkVanilla Breeze is an experimental component library. provides a layered approach.

Components

<foot-note>

The footnote reference element. Place inline within your content where you want a footnote marker.

Element Content Description
<foot-note> Phrasing content Contains the footnote text (links and inline markup allowed). When enhanced the content nodes are moved into the note and the element holds a superscript reference link.
Attribute Value Description
data-ref id Cites an existing note again. Names the id of another <foot-note> collected by the same <foot-notes>; leave this element empty. See Repeat Citations.
data-side "false" In sidenote mode, sends this note to the collected list instead of the margin.

<foot-notes>

The footnotes container. Place at the end of your content where you want footnotes collected.

All data-label-*, data-mode and data-preview changes are observed and re-render the notes in place.

Attribute Type Default Description
data-mode "sidenotes" (list) Place notes in the margin instead of a collected list. See Sidenote Mode.
data-label-back string "Back to content" Accessible name of the back-reference links. Repeat citations append (a), (b)…
data-label-ref string "Footnote {n}" Accessible name of each reference link; {n} is the note number.
data-label-heading string "Notes" Text of the generated, visually hidden heading that labels the notes list. An authored heading child (<h2> etc.) is used instead when present.
data-preview "false" (on) Disables the hover / focus preview popover.

Progressive Enhancement

The footnotes component demonstrates progressive enhancement principles.

Without JavaScript

When JavaScript is disabled or fails to load, footnotes remain inline within parentheses, keeping the content readable:

The framework (Vanilla Breeze is an experimental component library) provides a layered approach.

With JavaScript

When JavaScript loads, the component:

  • Finds all <foot-note> elements before the <foot-notes>
  • Converts them to superscript numbered links named “Footnote N”
  • Moves the footnote content into an ordered list inside a labelled notes section
  • Adds back-reference links from each footnote
  • Shows a preview of the note when a reference is hovered or focused

Basic Usage

Place <foot-note> elements inline where footnotes should appear, then add a single <foot-notes> element where the footnote list should be rendered.

Custom Labels

Use data-label-back to customize the accessible label for back-reference links, data-label-ref for the reference links ({n} is the number) and data-label-heading for the hidden list heading.

The defaults are “Back to content”, “Footnote {n}” and “Notes”. Customize them for internationalization or to match your site's terminology.

Repeat Citations

To cite the same note more than once, give the first <foot-note> an id and point later, empty <foot-note> elements at it with data-ref. Every citation gets the same number and the note gets one back-reference per citation, lettered a, b, …

Bush described the Memex.Vannevar Bush, As We May Think, 1945.

The same essay again.

Numbering follows the first citation in document order, so the referenced note may come before or after the data-ref. A data-ref that does not name a collected note logs a warning and is rendered as its own note. Without JavaScript an empty data-ref element renders nothing.

Note Preview

Hovering a reference with a mouse, or focusing it with the keyboard, shows the note in a small popover anchored to the reference (CSS anchor positioning, with a script fallback). Escape closes it and keeps focus on the reference; moving away or tabbing on closes it too. The fade is skipped under prefers-reduced-motion: reduce.

The preview is a visual convenience only: it is inert and aria-hidden, so screen readers do not hear the note twice and its links are not extra tab stops — follow the reference to reach the real, interactive note. Add data-preview="false" to turn it off.

Long Form Content

Footnotes work well with longer articles and prose content.

How It Works

The component processes footnotes in the following steps:

  1. Collection: Finds all <foot-note> elements that appear before the <foot-notes> element in document order.
  2. Enhancement: Each <foot-note> gets:
    • A data-enhanced attribute (its authored id, if any, is kept)
    • A superscript <a role="doc-noteref"> with a unique ID scoped to the container (e.g. fnref-1-1; repeat citations get fnref-1-1-b, -c…) and the accessible name “Footnote 1”
  3. List Generation: A <section role="doc-endnotes"> labelled by a heading holds an ordered list with:
    • Each footnote's content — the original nodes are moved, not copied, so ids stay unique and event listeners keep working
    • One role="doc-backlink" link per citation

Disconnecting the container restores the authored markup; reconnecting it (or changing an observed attribute) re-renders from document order, so notes inserted meanwhile are numbered in place rather than starting a second list.

Accessibility

ARIA Attributes

  • References use role="doc-noteref" and are named “Footnote N” (data-label-ref) — no aria-describedby, so the note is not read into the paragraph
  • Back-reference links use role="doc-backlink" with an aria-label (data-label-back)
  • The list sits in role="doc-endnotes", labelled by a heading (visually hidden by default)
  • Sidenotes are <aside role="note">

Navigation

  • Activating a footnote number (click or Enter) moves focus to the footnote in the list
  • Activating a back-reference returns focus to the reference
  • Links work on pages with <base href>: the relative #id hrefs are resolved against the document, not the base URL, and the URL hash and :target still update
  • All links are keyboard accessible; the note content contains no hidden tab stops

Screen Reader Experience

Screen readers will:

  • Announce “Footnote 1, link” in the running text — the note itself is read once, in the list
  • Read the footnote content when navigating to it
  • Allow users to return to their reading position

Best Practices

  • Keep footnote content concise
  • Don't put essential information only in footnotes
  • Use footnotes for supplementary information, citations, or clarifications
  • Place <foot-notes> at the end of the content section

Styling

The component can be styled using CSS selectors.

/* The reference links */ foot-note[data-enhanced] > a { font-size: var(--font-size-xs); vertical-align: super; text-decoration: none; color: var(--color-interactive); } /* The notes list */ foot-notes ol { font-size: var(--font-size-s); } /* Back-reference links */ foot-notes [data-backref] { margin-inline-start: var(--size-2xs); text-decoration: none; } /* Show the generated "Notes" heading instead of hiding it (or author your own heading inside ) */ foot-notes > [role="doc-endnotes"] > .visually-hidden { position: static; inline-size: auto; block-size: auto; margin: 0; clip: auto; white-space: normal; } /* The preview popover */ foot-notes > .fn-preview { max-inline-size: 30ch; }

Print

In print, back-reference links and the preview are hidden, references print as plain superscript numbers and each note avoids breaking across pages.

Multiple Footnote Sections

You can have multiple <foot-notes> elements in a document. Each will collect only the footnotes that appear before it.

Note: Each <foot-notes> element only collects <foot-note> elements that appear before it in the document. This allows for multiple independent footnote sections.

Sidenote Mode

Add data-mode="sidenotes" to <foot-notes> to place footnotes as margin annotations alongside the text instead of collecting them at the bottom. The authored markup is identical to regular footnotes.

Gutenberg's printing press transformed European society.Johannes Gutenberg developed movable type around 1440 in Mainz, Germany. Before its invention, books were copied by hand in monasteries.

Three-Layer Degradation

  1. No JS: <foot-note> content appears inline in parentheses — the standard progressive enhancement fallback.
  2. JS + narrow viewport: Falls back to numbered sidenotes that collapse to bordered blocks via CSS responsive rules.
  3. JS + wide viewport: Superscript numbered links at each reference point, with note content floated into the margin alongside the text.

Per-Note Opt-Out

Individual footnotes can opt out of sidenote placement with data-side="false". These notes are collected into the footnote list instead. Useful for longer notes that would overwhelm the margin.

This note always goes to the footnote list, even in sidenote mode.

Sidenote Mode Attributes

On <foot-notes>

Attribute Value Description
data-mode "sidenotes" Enables sidenote mode — notes are placed as margin annotations instead of collected at the bottom.

On <foot-note>

Attribute Value Description
data-side "false" Opts this note out of sidenote placement. It will appear in the collected footnote list instead.
CSS-only sidenotes: For manual margin annotations without numbering or JavaScript, use <aside class="sidenote"> directly in your markup.

Limitations

  • Footnote numbering is determined by document order, not insertion order
  • Footnotes added after the initial render are picked up when the container is reconnected or one of its observed attributes changes — there is no mutation observer
  • The preview popover is not interactive; links inside a note are used from the list
