Overview

A web component that progressively enhances a fenced Mermaid code block into a rendered SVG figure. Without JavaScript the page shows the source as a readable code block; with JavaScript the source is replaced by an SVG <figure>.

Mermaid is loaded from a CDN URL via dynamic import() only when a <diagram-wc> renders, so the library never lands in VB's core or pack bundles.

Diagram type gallery

Six common diagram types — flowchart, sequence, ER, journey, gantt, mindmap — share the same authoring shape. Mermaid supports many more in v11.

Theme integration

VB design tokens drive Mermaid's appearance. The component reads tokens at render time via getComputedStyle, maps them onto Mermaid's themeVariables (see src/lib/diagram-tokens.js), and re-renders when the global vb:theme-change event fires. No per-instance config is required.

Attributes

AttributePurpose
typeBackend selector. v1 only supports "mermaid"; reserved for future "d2", "kroki".
srcURL of a diagram source file (.mmd). Takes priority over inline <pre><code> source. Fetched once per URL — moving the element does not refetch.
captionRendered as <figcaption> below the SVG.
loading="lazy"Defers render until the element scrolls into view.
data-theme-baseMermaid base theme (base|default|dark|forest|neutral). Default "base" so VB tokens win.

JavaScript API

PropertyTypeDescription
sourcestringGet/set the diagram source. Setting it re-renders; the previous diagram stays on screen until the new one is ready (crossfaded), and stays if the new source has a syntax error. The value survives moving the element.

Accessibility

  • The rendered SVG keeps Mermaid's own graphics-document role, so node and edge labels stay reachable to assistive technology. Nothing is collapsed into a single opaque image.
  • Name: write Mermaid's accTitle: in the source. Without one, the caption attribute (the visible <figcaption>) names the diagram. If you give neither, no generic name like "diagram" is invented — add one.
  • Description: Mermaid's accDescr: becomes the SVG description. The diagram source is always kept in a collapsed Diagram source <details> in the figure and linked from the SVG through aria-describedby, so the full text alternative is available to everyone.
  • Syntax errors are announced through a role="status" note. Animations inside the SVG are disabled under prefers-reduced-motion, and the re-render crossfade is skipped.

Security and CSP

  • Module URL: Mermaid is imported from https://cdn.jsdelivr.net/npm/mermaid@11.14.0/dist/mermaid.esm.min.mjs. Only page script can change it, by setting window.VB_MERMAID_URL before the first diagram renders (for example, to self-host). There is no per-element override: markup — including sanitized markdown, which keeps custom elements and data-* attributes — can't choose which module is imported.
  • CSP: allow the module host in script-src (script-src 'self' https://cdn.jsdelivr.net), or self-host Mermaid and point VB_MERMAID_URL at your origin. Mermaid also injects <style> elements into each SVG, so style-src must allow inline styles ('unsafe-inline') for diagrams to be styled.
  • SRI: dynamic import() can't carry an integrity attribute. The CDN URL is version-pinned; if you need integrity guarantees, self-host the file.
  • Mermaid runs with securityLevel: 'strict', which escapes labels and disables click handlers in diagram source.

Notes

  • This is the first VB component to wrap an external runtime library. The library is loaded from a CDN URL at runtime — never bundled. The type="mermaid" attribute reserves the door for substitution backends per VB's wrapped-dependency policy.
  • Bundle audit: enabling <diagram-wc> in the ux-planning pack adds < 5 KB gzip; Mermaid (~360 KB gzip) is fetched from jsDelivr only on pages that use a diagram.
