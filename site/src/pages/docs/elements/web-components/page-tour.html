Overview

A guided page tour that highlights elements sequentially with a spotlight overlay and popover card. Follows the four-layer progressive enhancement stack — content is readable without CSS or JS.

Usage

Wrap <tour-step> elements inside <page-tour>. Each step targets a page element via data-target (a CSS selector).

Basic Tour with Layer 3 Fallback

When JS is unavailable, the <details> wrapper provides a collapsible guide with anchor links. The "Start Tour" button is auto-wired when the component upgrades.

Active Tour (Action-Gated)

Set data-action on a step to require an interaction with its target (click, focus, input, change, or custom) before advancing. Until it happens, Next carries aria-disabled="true" and does nothing, and Tab reaches the target as well as the card. When the action completes, Next is enabled and announced; focus stays where the user is, so typing is never interrupted.

Placement and Labels

data-placement on a step takes top, bottom, inline-start, inline-end, or auto (the side with the most room). The inline values follow the text direction, so inline-end is on the right in English and on the left in Arabic or Hebrew. The card is centred on that side of the target and flips to the opposite side when it would overflow the viewport.

Every string the tour renders can be replaced with a data-label-* attribute on <page-tour>. In data-label-step, {n} and {total} are replaced with the step number and count.

Tour Modes

ModeSkip, Escape, backdrop clickUse Case
passiveAllowedInformational tours, docs sites
activeAllowedOnboarding where steps ask the user to perform tasks
forcedNot allowedCompliance flows, mandatory training

The mode only controls skipping. Action gates come from each step's data-action in any mode. data-skippable="false" on a single step removes skipping for that step only.

If a step's target is missing, the tour skips over it in the direction of travel. When no later step has a target, Next finishes the tour; when no step has a target at all, start() logs a warning and does nothing.

Keyboard Navigation

KeyAction
EscapeSkip tour (unless the mode is forced or the step is not skippable)
TabCycle focus within the card; on action-gated steps the target joins the cycle
ArrowRight / ArrowDownNext step
ArrowLeft / ArrowUpPrevious step
HomeFirst step
EndLast step

The keys work wherever focus is while the tour runs, including on the step's target. Arrow, Home and End keys are left alone inside text fields and selects so they keep moving the caret.

Progressive Enhancement

The component follows a four-layer degradation strategy:

LayerEnvironmentExperience
1No CSS, no JSOrdered step list with headings and anchor links
2CSS onlyStyled guide card with step numbering
3CSS + <details>Collapsible guide with start button
4CSS + JSInteractive spotlight overlay with popover

Accessibility

  • Card uses role="dialog", named by data-title. It carries aria-modal="true" only on steps without an action gate; on gated steps it drops it, because the user must operate the target outside the card
  • A waiting Next button has aria-disabled="true" and is described by the action hint
  • An aria-live="polite" region announces step transitions and when a required action completes
  • Focus is trapped within the card (relaxed during action-gated steps); completing an action never moves focus
  • In forced-colors mode the spotlight is drawn as a Highlight outline
  • Focus returns to the original element when the tour ends
  • prefers-reduced-motion disables all spotlight/card transitions
