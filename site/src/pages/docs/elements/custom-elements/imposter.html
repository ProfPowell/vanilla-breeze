Overview

<layout-imposter> lifts its content out of the flow and places it over its containing block: centred by default, or pinned to an edge or a corner. Use it for badges, image captions, status chips and loading overlays.

Prerequisite: the element it should sit over needs position: relative (or any other non-static position). The imposter is absolutely positioned, so without a positioned ancestor it lands on the nearest positioned box further out, often the page itself. With data-layout-fixed it positions against the viewport instead and needs no positioned ancestor.

.stage { position: relative; }

Element and attribute forms

Element only. There is no data-layout="imposter" form. The imposter is the box that gets positioned: it has to be a separate element between the positioned ancestor and the overlaid content, so an attribute on the ancestor or on the content could not do the same job. Wrap the overlaid content in <layout-imposter>.

Alternatives:

  • For modal or dismissible overlays, use <dialog> or the popover attribute. They render in the top layer and bring focus and Escape handling.
  • To centre content in the flow rather than over something, use <layout-center> or <layout-cover>, which both have a data-layout form.

See data-layout for the layouts that do have an attribute form.

Attributes

Attribute Values Default Applies to Description
data-layout-position center, top, bottom, start, end, top-start, top-end, bottom-start, bottom-end center element Where to place the overlay. start and end follow the writing direction.
data-layout-margin s, m, l, xl — element Inset from the edges when pinned to one (and the inset used by data-layout-contain).
data-layout-fixed (boolean) — element Position relative to the viewport instead of the containing block.
data-layout-contain (boolean) — element Never larger than the containing block (the positioned ancestor, or the viewport when fixed) minus the margin on each side; scrolls inside when the content is bigger.

Custom properties

PropertyDefaultDescription
--imposter-z 1 (absolute), var(--z-float) (fixed) Stacking order, so the overlay paints above later positioned siblings.

Child attributes

None. The imposter reads no attributes on its children; style the overlaid content as usual.

How it positions

The containing block must be positioned: give the element the imposter sits over position: relative. Every position then uses the same mechanism: the imposter is stretched to its containing block with inset: 0, shrinks to fit its content, and is placed with auto margins. Pinned edges swap the auto margin on that side for the data-layout-margin value. Because nothing is translated by a physical offset, positions are logical (start is the right edge in RTL) and a centred overlay can use the full width of its container before it wraps.

Nested imposters start from their own defaults; an inner imposter never inherits an outer one's position or margin.

Accessibility

<layout-imposter> does visual positioning only. It does not trap focus, make the rest of the page inert, close on Escape, or give the content dialog semantics. For modal or dismissible UI, use the platform:

  • <dialog> with showModal() for modal dialogs (focus containment, inert background, Escape).
  • The popover attribute for light-dismiss overlays such as menus and toasts.

The overlay stays where it is in the DOM, so screen readers and keyboard focus reach it in source order, not in the order it appears on screen. Put it next to the content it describes.

Badges that repeat information (a count, a status) should not be the only place that information lives: name it on the control (aria-label="Notifications, 3 unread") and hide the badge with aria-hidden="true", or connect the badge with aria-describedby.

Status overlays (loading, saved) should carry role="status" so screen readers announce them. Keep a decorative spinner out of the accessibility tree with aria-hidden="true" when visible text sits next to it.
