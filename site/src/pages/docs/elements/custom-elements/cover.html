Attributes

Attribute Values Default Description
data-layout-min s, m, l, xl, auto xl Minimum block size: 50 / 70 / 80vh, xl = 100dvh, auto = none. One-off: set --layout-min in a stylesheet rule (see Custom height).
data-layout-padding none, s, m, l, xl m Padding on all sides.
data-layout-gap none, 3xs, 2xs, xs, s, m, l, xl, 2xl, 3xl none Minimum space between all children (top, principal, bottom), on the shared size scale. The principal's auto margins still centre it.
data-layout-centered (boolean) — Center the principal and text horizontally; header/footer (and data-layout-cover-top/-bottom) children still span the full width.
data-layout-principal (on any child) (boolean) — The vertically centered principal element. A sole child auto-centers without it.
data-layout-cover-top (on any child) (boolean) — Pin to the top (a <header> child is pinned automatically).
data-layout-cover-bottom (on any child) (boolean) — Pin to the bottom (a <footer> child is pinned automatically).
data-container (on main, article, section, aside) (boolean) — With data-layout-centered, the layout removes container-type from semantic children so they size to their content instead of collapsing; this opts one back into container queries.

Element or Attribute

The same layout is available as data-layout="cover". Prefer the attribute when a semantic element is already the full-height region — usually the page's <main> or a hero <section> — so you don't wrap it in an extra element. Use <layout-cover> when there is no such element. All data-layout-* modifiers and child attributes work on both forms. See data-layout for the full comparison.

Custom height

For a one-off height, set --layout-min in a stylesheet rule rather than an inline style. It wins over data-layout-min:

.hero { --layout-min: 65vh; }
