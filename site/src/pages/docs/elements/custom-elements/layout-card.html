Attributes

Attribute Values Default Description
data-variant elevated, outlined, ghost — Visual style: elevated (shadow), outlined (border), ghost (no surface).
data-padding none, s, m, l, xl m Internal padding. In structured mode the children are padded one step larger (see padding scale).
data-max narrow, normal, wide, prose — Max inline size, centered in normal block flow (margin-inline: auto) and in flex/grid parents: --content-narrow / --content-normal / --content-wide, or prose (65ch). Same keyword set as layout-center and canvas.

Block Mode

By default, layout-card is a simple block container with padding. Use it for any content that just needs a card surface.

Structured Mode

Add a <header>, <section>, or <footer> child, or any child with slot="header", slot="content" or slot="footer", and the card switches to structured mode. No extra attributes are needed: the :has() selector detects the children.

Card Title

Content with automatic grid placement.

How it works

  • The <header> (or slot="header") is pinned to the top and gets a bottom border.
  • The <footer> (or slot="footer") is pinned to the bottom, so footers line up when cards in a grid stretch to equal height. It gets a top border and a wrapping flex row for actions.
  • Every other child is content. Content children stack in source order between the header and footer, one body padding apart. A <p> followed by a <section> is fine, and nothing overlaps.
  • In structured mode the card is a size container (container-type: inline-size), which powers the compact rule below. A block-mode card is not a container, so it can shrink to fit its content inside a cluster or a centered stack.

Aligning cards with subgrid

Inside <layout-grid data-layout-subgrid> each structured card spans three parent rows, so headers, content and footers line up across siblings. The header takes the first row, the footer the last, and content fills the rows between. Use one content child per spare row (one for the default span of 3), or wrap several in a <section>.

Structured Mode Variants

All visual variants work in both block and structured modes.

Structured Mode Padding Sizes

In structured mode the card itself has no padding. Each child is padded one step up the scale from the block-mode value, so data-padding="m" (the default) gives the header and footer --size-m block and --size-l inline padding, and content --size-l. none also removes the header and footer dividers.

Slot Escape Hatch

Use slot="header", slot="content" or slot="footer" to give any element one of the structured roles. Children without a slot are already content, so slot="content" is mainly useful to switch a card into structured mode when it has no header, section or footer.

Container Queries

Only in structured mode, the card uses container-type: inline-size. When the card is narrower than 300px, every child's padding is capped at --size-s, header headings shrink, and footer actions stack vertically. A structured card is a size container, so give it a width (or data-max) when it is a shrink-to-fit item, for example inside <layout-cluster>.

Accessibility

  • In structured mode, use semantic HTML elements (header, section, footer) for proper document structure
  • The header and footer are pinned visually with order. Keep them first and last in the source too, so reading and focus order match what is on screen.
  • In forced-colors mode, every card except ghost gets a CanvasText border, because the system removes the shadow and background that mark its edges.
  • Include headings in the header area for screen reader navigation
  • Footer actions should be keyboard accessible
  • Consider wrapping in article if the card represents standalone content
