Attributes

Attribute Values Default Description
data-layout-measure narrow, normal, wide normal Line measure: --measure-narrow / --measure-normal / --measure-wide (45 / 65 / 80ch by default). See Measure.
data-layout-max narrow, normal, wide normal Same as data-layout-measure (the prose attribute form spells it this way). ch-based: narrow is 45ch here but 40rem on layout-center.
data-layout-centered (boolean) — Center the container (margin-inline: auto). Off by default: the text keeps its position.
data-bleed (on a direct child) (boolean) — Break out to the full width of the nearest query container. See Full-width breakout.

How It Works

The layout-text element creates a container optimized for long-form reading content. It:

  • Sets a maximum line width of --measure-normal (65ch by default; data-fluid makes it fluid, and the dyslexia and large-text themes shorten it)
  • Applies consistent vertical spacing between block elements
  • Uses larger margins before major headings (proximity principle)
  • Tightens spacing after headings so they associate with their content
  • Provides extra breathing room around figures, pre, code-block, tables, blockquotes, video and browser-window

The rhythm applies between direct children. Content wrapped in one extra element (a single <article> inside) only gets the browser's default spacing; put the content straight inside, or use the attribute form on the article itself.

Attribute forms

The same typographic core (measure, rhythm, centering, bleed) is available without a wrapper element:

  • data-layout="prose": identical to <layout-text>. Spell the measure data-layout-max (or data-layout-measure; both work).
  • data-layout="columns": adds multi-column flow; see <layout-columns>.

Article Title

Measure, rhythm and centering on the article itself.

Measure

The default line width is --measure-normal. data-layout-measure (or data-layout-max) picks narrow, normal or wide. The tokens are 45, 65 and 80ch by default. Under data-fluid they become clamps that grow with the viewport, and the accessibility themes adjust them (dyslexia 55ch, large text 60ch).

Narrow containers: in a query container narrower than 30rem (a sidebar, a card, a phone-width column), the measure is released to 100%, so the text fills the space rather than leaving a gap.

Reading width only: article[data-measure]

For an article that needs the reading width but not the rhythm, use data-measure on the <article>. It is always centered. Bare or normal uses --measure-normal; narrow and wide use the other two tokens. data-bleed works on its direct children too.

Constrained to --measure-narrow, centered, no rhythm rules.

Centering

layout-text keeps its position by default. Add data-layout-centered to center it in its container. Since it already limits its own width, it needs no layout-center wrapper.

Centered Article

layout-text limits its own line length; data-layout-centered centers it.

Full-width breakout

Add data-bleed to a direct child (a figure, a table, a code block) to break it out of the measure. The child spans the full width of the nearest query container: main, article, section and aside are query containers by default, as is any element with data-container.

  • It works centered or not. Uncentered text bleeds from its start edge across the container; centered text bleeds evenly on both sides.
  • It measures the container, not the viewport, so it never adds a horizontal scrollbar.
  • If the text host is itself a query container (<article data-layout="prose">, article[data-measure]), it stops being one while it holds a bleed child, so the bleed reaches the next container out. Add data-container to the host to keep it as a container (the bleed then fills only the host).
  • With no query container above it at all, the bleed falls back to the viewport width.
  • In layout-columns, a bleed child also spans every column.

Spacing Rules

layout-text spaces its direct children according to their element type:

Context Spacing Rationale
Default (between elements) var(--size-m) Standard paragraph spacing
Before h2 var(--size-2xl) Major section break
Before h3 var(--size-xl) Subsection break
Before h4/h5/h6 var(--size-l) Minor section break
After any heading var(--size-s) Associates heading with content
Between consecutive lists var(--size-s) Groups related lists
Before/after figure, pre, table, blockquote, video, code-block, browser-window var(--size-l) Extra breathing room for media

Best Practices

  • Use for long-form content only - layout-text is designed for articles, documentation, and similar content. Don't use it for UI layouts.
  • Center with data-layout-centered - layout-text already limits its own width, so it doesn't need a layout-center wrapper to constrain it. Use layout-center only when the page needs a wider frame around the text (the blog post example above). Note that the two data-layout-max attributes use different scales: narrow is 40rem on layout-center and 45ch on layout-text.
  • Semantic HTML - The spacing rules work best with proper semantic markup (h2 before h3, etc.).
  • Avoid nesting layout elements - layout-stack, layout-grid, and similar elements inside prose may have unexpected spacing.
