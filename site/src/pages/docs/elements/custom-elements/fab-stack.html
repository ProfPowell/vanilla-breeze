Overview

The <fab-stack> element pins itself to one of 8 screen positions and stacks its children vertically with a gap. Position is delegated to the shared data-float system, so the stack can live in any corner or edge — not just bottom-right.

Children get position: static so their own positioning rules don't fight the stack. Without data-float the stack sits at bottom-right (inline-end, so bottom-left in right-to-left pages).

↑

Child order

The first child is the primary action. It sits nearest the anchored edge and is the first to receive keyboard focus; later children stack away from the edge.

  • bottom-* and center-* (and the bare default) use column-reverse: the first child is at the bottom of the stack.
  • top-* uses column: the first child is at the top.

For bottom stacks this means the visual top-to-bottom order is the reverse of the DOM order. Focus still moves from the edge inward, which matches how a corner stack is read, so write the markup in priority order rather than in visual order.

Usage

↑

Place at the end of the page body, after the footer. The Vanilla Breeze doc site uses this pattern for the settings gear and back-to-top arrow.

data-float positioning system

Underneath, <fab-stack> uses the same [data-float] contract any element can opt into. Eight standard positions, safe-area aware, mirrors in RTL: left/right are inline-start/inline-end, and the matching safe-area inset follows the physical edge. *-center uses the physical viewport midpoint, so it stays centred in either direction.

Position values: top-left, top-center, top-right, center-left, center-right, bottom-left, bottom-center, bottom-right.

↑

For multiple items in the same corner, wrap in <fab-stack data-float="…"> rather than placing two bare floats — the stack handles gap and prevents overlap.

Tokens

TokenDefaultPurpose
--z-float 200 z-index for floating elements (above --z-sticky 100)
--float-offset var(--size-l) Distance from the screen edge. Override per-instance with inline style="--float-offset: 2rem".
--nav-bottom-height0px Set on :root when a fixed bottom nav is present; bottom-* positions add this offset automatically so floats sit above the nav.
--safe-top / --safe-bottom / --safe-left / --safe-rightsafe-area-inset-*Mobile notch / home-indicator awareness — already added to edge positions; you don't manage these directly.

Migration from custom position: fixed

Replace ad-hoc fixed positioning with data-float to pick up safe-area insets, the shared z-index, and consistent edge offsets. The four places that used to hardcode their own corner positioning (corporate-cta .fab, back-to-top, page-tools fixed mode, fab-stack itself) all now route through this contract.

Positioning

Placement comes from data-float; a bare <fab-stack> falls back to the same bottom-right rule. Offsets are the shared --float-offset plus the safe-area inset of the physical edge the stack touches:

fab-stack:not([data-float]) { position: fixed; inset-block-end: calc(var(--float-offset) + var(--safe-bottom) + var(--nav-bottom-height, 0px)); inset-inline-end: calc(var(--float-offset) + var(--safe-right)); } /* inline-end is the left edge in RTL */ fab-stack:not([data-float]):dir(rtl) { inset-inline-end: calc(var(--float-offset) + var(--safe-left)); } …

The pointer-events: none on the container with pointer-events: auto on children ensures only the buttons are clickable, not the invisible stack area.

With Back-to-Top

When [data-back-to-top] (or any [data-float] element) is inside fab-stack, its own fixed positioning is overridden to static so the stack controls placement.

A <dialog> or [popover] child is left alone: it renders in the top layer and centres or anchors normally when opened.

Accessibility

  • Each child button should have its own aria-label
  • The stack is a visual grouping — no special ARIA role needed
  • Back-to-top visibility is JS-driven: back-to-top-init sets [data-state-visible] after one viewport of scrolling. While hidden the link is visibility: hidden, so it is skipped by Tab and screen readers.
  • The first child is focused first and sits nearest the edge — see Child order
