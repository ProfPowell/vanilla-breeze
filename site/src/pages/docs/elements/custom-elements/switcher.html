Overview

A switcher puts its children side by side, all in one row, until the switcher itself gets narrower than its threshold; then every child takes a full line. There is no in-between state where some items wrap and others don't.

The threshold is compared with the switcher's own width, not the viewport and not a container query. Each child gets flex-basis: calc((threshold - 100%) * 999): when the switcher is wider than the threshold the basis is hugely negative and the items share the row; when it is narrower the basis is hugely positive and each item wraps onto its own line. So a switcher in a narrow sidebar stacks even on a wide screen, and it needs no query container around it.

Element and attribute forms

Any element can be a switcher with data-layout="switcher". The same data-layout-* modifiers work on both forms; the two below are identical.

Which to choose: use the attribute form when a semantic element is already the row: a <footer> of form actions, a <section> of cards, a <menu>. Use <layout-switcher> when there is no such element and you would otherwise add a wrapper. In the attribute form, main, article, section and aside are also container-query containers, which the element is not; the switch itself never depends on that. See data-layout for the full comparison.

Attributes

Attribute Values Default Applies to Description
data-layout-threshold s, m, l m both The switcher's own width below which the row becomes a column: 25 / 30 / 40rem. No container query is involved. One-off: style="--layout-threshold: 35rem".
data-layout-gap none, 3xs, 2xs, xs, s, m, l, xl, 2xl, 3xl m both Gap between items, on the shared size scale.
data-layout-limit 2, 3, 4 — both Force the column layout once there are more than this many items, whatever the width.
data-layout-reverse (boolean) — both Reverse the visual order when stacked: the last item goes on top. The row keeps DOM order. Visual only; see Accessibility.

Custom properties

PropertyDefaultDescription
--layout-threshold (unset) A threshold length that beats data-layout-threshold. Registered with inherits: false, so a nested switcher does not pick it up.

Child attributes

None. Every direct child is an item; items grow to share the row equally.

Reverse when stacked

data-layout-reverse flips the order of the stacked items, so the last item ends up on top. Side by side, the items keep their DOM order. It works with or without data-layout-threshold and with data-layout-limit. A common use: put the text first in the DOM so it is read first, and show the image above it on narrow screens.

Accessibility

  • The switcher changes layout only. Reading order and focus order always follow the DOM, so write the source in the order it should be read.
  • data-layout-reverse is visual only. When stacked, focus moves from the lower item up to the upper one (WCAG 2.4.3 Focus Order). Use it only when the stacked order is presentational, for example a decorative image above text, and not when the items contain focusable controls in a meaningful sequence.
  • Because the switch depends on the switcher's width, it also happens when users zoom in or enlarge text: content reflows into a single column instead of overflowing (WCAG 1.4.10 Reflow).
