When to Use

  • Choosing from a predefined list (countries, categories, sizes)
  • When the list has more than 5 options (otherwise consider radio buttons)
  • When screen space is limited
  • When the user cannot enter custom values

Consider alternatives:

  • Radio buttons for 2-5 options when space allows
  • datalist when users can type custom values alongside suggestions
  • combo-box for a fully custom filterable dropdown

Multiple Selection

Allow selecting multiple options with the multiple attribute. Use size to control how many options are visible.

Required, with a Placeholder Option

A required single-row select is only invalid when the selected option is the placeholder label option: the first option, with an empty value="", and not inside an <optgroup>. Without that placeholder the browser selects the first real option and required never fails. The rule does not apply to multiple or size greater than 1: those are invalid only when nothing is selected.

The shared form layer styles select:user-invalid with the error border once the user has interacted, so an untouched form is not painted red on load.

Adding disabled to the placeholder (<option value="" disabled selected>) stops users from re-choosing it once they have picked a value. It is still the placeholder, so validation works the same way.

Disable the entire select or individual options within it.

Accessibility

  • Always use a label: Every select needs an associated label, either wrapping or via for/id
  • Use autocomplete: Add appropriate autocomplete values for autofill (e.g., country)
  • Keyboard navigation: Arrow keys navigate options; typing jumps to matching text
  • Option groups: Help screen readers understand option categories
  • Avoid onChange submission: Do not submit forms automatically on select change without warning
  • Multiple select guidance: Provide visible instructions for Ctrl/Cmd-click

CSS Reference

VB sets appearance: none to remove the native dropdown arrow and draws its own chevron with a currentColor gradient in background-image, so the arrow always matches the text colour: it follows data-mode="dark", themes and forced-colors mode. It sits on the inline-end side and mirrors to the left under dir="rtl". Only single-row selects get it; multiple and size greater than 1 render as a list box with no arrow. The select inherits shared input styles (border, radius, focus ring) from the form layer.

/* Tokens (tokens/forms.css) */ :root { --select-chevron: conic-gradient(from -45deg at 50% 100%, currentColor 90deg, transparent 0); --select-chevron-size: 0.625rem 0.3125rem; --select-chevron-inset: var(--size-s); } /* Select inherits shared input styles, then overrides: */ select { appearance: none; cursor: pointer; } /* Chevron: single-row selects only (not multiple, not size > 1) */ select:where(:not([multiple]):is(:not([size]), [size="0"], [size="1"])) { padding-inline-end: var(--size-xl); background-image: var(--select-chevron); background-repeat: no-repeat; background-size: var(--select-chevron-size); background-position: right var(--select-chevron-inset) center; &:dir(rtl) { background-position: left var(--select-chevron-inset) center; } /* Forced colors drop gradients, so opt out and use system colours */ @media (forced-colors: active) { forced-color-adjust: none; color: FieldText; background-color: Field; border-color: FieldText; } } select:disabled { cursor: not-allowed; } optgroup { font-weight: 600; }

Custom chevron

To swap the arrow, set --select-chevron to any image and --select-chevron-size to match. A url() image cannot see currentColor, so give it an explicit colour that works in both modes.

.brand-form select { --select-chevron: url("/icons/chevron-down.svg"); --select-chevron-size: 1rem; }

Customizable Select

Chrome 135+ ships appearance: base-select, which unlocks full CSS control over the dropdown picker, options, checkmark icon, and open/close animations — while retaining native semantics, keyboard navigation, form participation, and accessibility.

VB wraps all customizable-select styles in @supports (appearance: base-select), making this a zero-risk progressive enhancement. Non-supporting browsers keep the existing appearance: none + currentColor chevron.

What Changes Automatically

  • Dropdown picker gets surface background, border, radius, shadow, and max-height scroll
  • Options gain hover highlight, checked color, and rounded corners
  • Checkmark icon uses --color-interactive
  • Chevron rotates 180° on open
  • Picker animates in with opacity + translateY (respects prefers-reduced-motion)
  • <optgroup> headers render as uppercase muted section labels with dividers

No markup changes are required: every existing single-row <select> upgrades automatically. List boxes (multiple, or size greater than 1) are not upgraded and keep appearance: none.

Rich Content

For selects with images, icons, or descriptions inside options, add a <button> trigger with <selectedcontent> to mirror the selected option in the closed state.

  • <button> becomes the trigger. VB resets it to a plain content slot inside the select's own box: no padding, border, background, shadow, radius or minimum size. Theme button skins do not reach it, so a rich select is the same height as a plain one
  • Do not put aria-label on the inner button. The <label for> names the select, and browsers ignore names on the trigger
  • <selectedcontent> automatically clones the selected option's content
  • Elements with class="detail" are hidden in the closed trigger to keep it compact
  • Images inside options are sized to 1.5em with border-radius and object-fit: cover

Fallback Without base-select

Browsers without appearance: base-select parse a select with the older rules. The <button> and <selectedcontent> are dropped, and each option collapses to its plain text. The closed select shows the whole option text, including emoji and any .detail text, for example "🇺🇸 English — American English". aria-hidden on spans inside an option is lost with the spans.

  • Keep rich option text short and readable on its own, because it is also the fallback label
  • Put long descriptions in help text next to the select, not in the option, when they matter in every browser
  • Treat images and icons as decoration: the fallback has none of them

Select vs Combo Box

Use this table to decide between the native customizable select and VB's combo-box web component.

Capability Customizable Select combo-box
JavaScript required No Yes
Filterable / searchable No (type-ahead only) Yes
Rich content in options Yes (images, icons, text) Yes
Form participation Native Manual (hidden input)
Browser support Chrome 135+ All modern browsers
Styled dropdown Yes (with @supports gate) Yes

Browser Support

appearance: base-select ships in Chrome 135 (April 2025). Other browsers are implementing it — check caniuse for current status.

VB's implementation is fully gated behind @supports:

@supports (appearance: base-select) { /* Single-row selects only: not multiple, size absent, 0 or 1 */ select:not([multiple], [size]:not([size="0"], [size="1"])) { appearance: base-select; /* ... all customizations ... */ } } /* Non-supporting browsers keep: */ select:where(:not([multiple]):is(:not([size]), [size="0"], [size="1"])) { background-image: var(--select-chevron); }

Detect in JavaScript:

if (CSS.supports('appearance', 'base-select')) { // Customizable select is active }
