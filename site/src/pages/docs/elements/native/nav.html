Usage

Use the <nav> element for:

  • Primary site navigation in the header
  • Secondary navigation in sidebars or footers
  • Breadcrumb navigation
  • Table of contents
  • Pagination links
  • Hierarchical disclosure navigation for documentation sidebars (see .tree below) — not application tree widgets

Not all groups of links need to be in a nav element. Reserve nav for major navigation blocks. Use aria-label or aria-labelledby to distinguish multiple nav elements.

.breadcrumb separators

The default separator is “›”, from the --sep-breadcrumb token. Use data-separator to change it. In a right-to-left trail (dir="rtl") the directional separators flip: the default and chevron become “‹” and arrow becomes “←”. The RTL default comes from --sep-breadcrumb-rtl, so set both tokens if you change the glyph.

.breadcrumb collapsed and truncated

.steps

A step indicator for multi-step flows (checkout, onboarding). Use an <ol>; the circles are numbered by a CSS counter. Mark the current step aria-current="step" and finished steps data-completed (the number becomes a check mark). A link inside a completed step lets people go back. data-labels="below" puts labels under the circles, data-direction="vertical" stacks the steps, and data-size="sm|lg" changes the circle size. Connectors use logical properties, so the indicator mirrors in right-to-left pages.

Every variant uses logical properties. Breadcrumb separators flip, step connectors run from the inline start, and compact pagination and tree links round the correct ends.

Dropdowns in a nav

Put a <drop-down> in a nav list item for a sub-menu. The trigger picks up the nav’s link padding, colours and hover, and gets a chevron that turns when open. Mark the trigger aria-current="true" (or .active) when the current page is in its section. The menu keeps its pop-up behaviour at every width; a phone layout that needs a different pattern should use <nav-bar> or a mobile menu.

.tree (disclosure tree navigation)

Hierarchical “tree-style” navigation using <details> and <summary> for collapsible sections. Uses +/- indicators for expand/collapse state.

This is disclosure navigation, not an ARIA tree widget. nav.tree deliberately omits role="tree", role="treeitem", and roving tabindex. The WAI—ARIA APG recommends disclosure over tree for site navigation — tree is a heavier widget contract (arrow-key traversal, Home/End, single focusable node, typeahead) that typical sidebars do not need.

For application-style trees — file explorers, IDE sidebars, permission editors, nested selectable datasets — use a dedicated widget with the full role="tree" contract. <site-map> is VB’s example of that pattern; build a separate tree-view component only when you need that behavior.

Styling the current page

The link marked aria-current="page" (or .active) is styled from two tokens. Set them on the nav, or on :root for every nav:

TokenDefaultUsed by
--color-active-textvar(--color-interactive)Default, .horizontal, .vertical, .tabs, .bottom and dropdown items
--color-active-bgtransparentDefault, .horizontal, .vertical, .bottom (.tabs keeps it transparent and marks the item with a border)
nav.site-bar { background: oklch(20% 0.02 260); --color-active-text: white; --color-active-bg: oklch(35% 0.08 260); }

Colour is not the only cue: in the default, .horizontal, .vertical, .minimal and .bottom navs the current link is also underlined (WCAG 1.4.1). Variants that mark it another way turn the underline off: .pills and .pagination (fill), .tabs (border), .tree (inline-start bar) and .breadcrumb (position). Set --nav-active-decoration: none on a nav to remove it when you add your own non-colour cue. The underline is locked the same way as the colour, because many themes remove link underlines.

.minimal uses body text color and weight as well as the underline. .pills and .pagination fill the current item with --color-interactive and pick black or white text for it automatically (contrast-color(), with --color-text-on-primary as the fallback in older browsers).

Why tokens rather than a color rule: many themes color links, and theme styles sit in a higher cascade layer than nav. Nav therefore locks the current item's text color with !important so no theme can make it vanish; that rule reads the tokens above, so they are the way to change it. A test renders the current item under every theme to keep it legible.

Accessibility

  • Nav creates a navigation landmark for screen reader navigation
  • Use aria-label to distinguish multiple nav elements (e.g., "Main navigation", "Footer navigation")
  • Use aria-current="page" on the link to the current page
  • Breadcrumbs should use <ol> for ordered sequence semantics
  • Ensure sufficient color contrast for link text and focus states
  • Links should have visible focus indicators
  • Tree navigation uses native <details>/<summary> which are keyboard accessible and announce expand/collapse state
