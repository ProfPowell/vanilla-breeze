Description

A <template> holds HTML that the browser parses but does not render. Its children go into a separate DocumentFragment, template.content, rather than into the page. Images in it do not load, scripts in it do not run, and its styles do not apply. Nothing happens until script clones the content and inserts the copy.

A template can appear almost anywhere, including inside <table>, <select> and <ul>, where most other wrappers are not allowed. That makes it the usual way to ship row, option or list-item markup for script to stamp out.

Example: Clone and Fill

Clone template.content with cloneNode(true), fill in the copy, then insert it. Each submit below adds a row built from the same template. The template itself never appears.

     const template = document.getElementById('task-row'); function addTask(name) { const row = template.content.cloneNode(true); // a DocumentFragment row.querySelector('.task-name').textContent = name; // textContent, not innerHTML document.getElementById('tasks').append(row); }

    Use document.importNode(template.content, true) instead of cloneNode when the template lives in another document, such as a fetched HTML file. Fill text with textContent, never by concatenating user input into innerHTML.

    Declarative Shadow DOM

    With a shadowrootmode attribute, a template does something different. While the HTML is parsed, it attaches a shadow root to its parent element and moves its content into that root. No JavaScript is needed, and the template element itself disappears.

    Ada Lovelace

    Unnamed children go to the default slot.

    Declarative shadow roots only attach during parsing. A template with shadowrootmode inserted later through innerHTML stays an ordinary, inert template; use setHTMLUnsafe() or Document.parseHTMLUnsafe() for that. The <slot> page has a live demo and covers slots and ::slotted.

    Templates Read by VB Components

    Several VB components let you author part of their content as a <template> child. The component reads the template; you never clone it yourself. Because the content is inert, nothing in it renders or loads before the component upgrades.

    Component Template What it holds
    <markdown-viewer> template[data-md] Markdown source, read as text and rendered
    <tool-tip> template[data-tooltip] Rich tooltip content (takes priority over content and title)
    <reaction-bar> template[data-palette] The reaction picker's palette
    <comment-thread> template[data-reply-form] The reply form cloned under a comment
    <ai-chat> template[data-role="starters"], template[data-role="system"] Starter prompts (one per line) and the system prompt
    <card-list> template (first child template) The card markup stamped for each item, with data-field bindings
    <chart-wc> template[data-chart-data] Inline chart data

    Attributes

    Attribute Purpose
    shadowrootmode open or closed. Attaches a declarative shadow root to the parent element while parsing.
    shadowrootdelegatesfocus Focusing the host forwards focus to the first focusable element in the shadow root.
    shadowrootclonable Shadow roots created from this template are copied by cloneNode().
    shadowrootserializable The shadow root is included by getHTML({ serializableShadowRoots: true }).

    This element also supports global attributes.

    Accessibility

    • Template content is not in the accessibility tree. Screen readers do not see it, and nothing in it can take focus until a clone is inserted into the page.
    • Clones are ordinary DOM once inserted. Give them the same headings, labels and names you would write by hand, and use unique id values per clone (a cloned id is duplicated every time).
    • Content added after load is not announced on its own. Insert it into an aria-live region, as the demo's list does, or move focus to it when the user needs to act on it.
    • A declarative shadow root is rendered and exposed to assistive technology like any other content.
