Description

The <mark> element represents text highlighted for reference due to its relevance in a particular context. VB styles it with a subtle background derived from var(--color-interactive) using relative oklch colors, sets the text to var(--color-text) so the highlight stays readable in dark mode, and adds padding-inline and border-radius. Three category classes colour-code different kinds of highlight, for example review annotations.

When to Use

  • Search results: Highlight matching search terms
  • Quotations: Mark parts of a quote that are particularly relevant
  • Annotations: Categorise highlights in a review (agreed, query, problem)
  • Comparisons: Highlight differences between items
  • User selections: Show text the user has bookmarked or selected

When NOT to Use

  • For semantic emphasis — use <strong> or <em>
  • For purely decorative highlighting — use CSS background-color
  • For inserted text — use <ins>
  • For status (build passing, tests failed) — <mark> means relevance, not state. Use <layout-badge> or a status pattern instead

Highlight Categories

Each category pairs an opaque light-dark() background token with its matching text token, so the text keeps AA contrast in light and dark mode.

Class Background Text Example use
(default) oklch(from var(--color-interactive) l c h / 0.2) var(--color-text) Search hits, general relevance
.success var(--color-success-subtle) var(--color-success-text) Agreed, approved passage
.warning var(--color-warning-subtle) var(--color-warning-text) Query, needs checking
.error var(--color-error-subtle) var(--color-error-text) Problem, must change

In forced-colors mode every <mark>, whatever its class, renders with the system Mark/MarkText pair. The category colour is lost there, which is one more reason to state the category in text, as shown under Accessibility.

CSS Reference

mark { background: oklch(from var(--color-interactive) l c h / 0.2); color: var(--color-text); padding-inline: var(--size-2xs); border-radius: var(--radius-s); } mark.success { background: var(--color-success-subtle); color: var(--color-success-text); } mark.warning { background: var(--color-warning-subtle); color: var(--color-warning-text); } mark.error { background: var(--color-error-subtle); color: var(--color-error-text); } @media (forced-colors: active) { mark, mark:is(.success, .warning, .error) { background: Mark; color: MarkText; } }

The default highlight derives from the theme's interactive colour, so it follows each theme. The category tokens are light-dark() pairs from tokens/colors.css. The journal pack maps the three classes onto its highlighter tints (mint, butter, coral).

Highlight Effect

VB's data-effect="highlight" provides an animated version of mark-style highlighting that draws in on scroll. This is a CSS animation, not the <mark> element — but they share the same visual language.

Accessibility

  • Assume <mark> is not announced. VoiceOver and JAWS with default settings say nothing about it, and NVDA says “highlighted” only in browse mode. The highlight is visual.
  • Don't rely on colour alone. Say what a highlight means in text (“3 results for …”) or with a visually hidden prefix on each category, as below.
  • Text uses theme tokens, so contrast holds in light mode, dark mode (prefers-color-scheme or data-mode="dark") and every category.
  • Forced colours draw every mark with Mark/MarkText, so categories look the same there.

Related

  • <em> — For semantic emphasis
  • <b> — Draw attention without importance
  • <ins> — For inserted text (similar appearance, different meaning)
  • <del> — For deleted text (often paired with <ins>)
  • <layout-badge> — For status labels
