When to Use

  • Displaying disk space usage
  • Password strength indicators
  • Poll results or voting percentages
  • Budget utilization
  • Score or rating displays

Use progress instead for tasks that are in progress (like file uploads or loading states).

Basic Usage

A simple meter showing a value within a range. Associate the label with for/id: <form-field> only wires up inputs, selects and textareas, so a meter inside it still needs the explicit pair.

Meter Attributes

Attribute Purpose Default
value Current value (required) -
min Minimum possible value 0
max Maximum possible value 1
low Upper bound of low range min
high Lower bound of high range max
optimum Optimal value (affects color) midpoint

Optimum Range Behavior

The meter's color changes automatically based on where the value falls relative to the optimum attribute. Set optimum low for "less is better" metrics (CPU, disk usage) or high for "more is better" metrics (skills, scores). No classes or JavaScript needed — the browser handles the color logic. The colour is never announced, so say the state in the label (“good”, “poor”) as the demo does.

Labeled Meter

Use the .labeled wrapper for a header row (label + value) above the meter. The <label for> names the meter and aria-describedby points at the <output> that shows the human-readable value. The class only applies to a wrapper whose direct child is a <meter>.

Accessibility Notes

  • Include fallback text: Content between tags is shown if meter is not supported
  • Label every meter: <label for> + id, or aria-labelledby/aria-label. A <label> next to a meter without for labels nothing
  • Provide context: Include units or percentages in visible text, and point aria-describedby at it
  • Don't rely on color alone: The optimum/suboptimum colour is not exposed to assistive technology; state it in text
  • Screen reader support varies: Most combinations announce the meter's role and current value, but wording (percentage, “X out of Y”, or the raw number) differs by screen reader and browser
  • Visible track: The track has a 1px border at 3:1 against the surface so the range extent is perceivable (WCAG 1.4.11)
  • Forced colors: The track draws in CanvasText; optimum fills with Highlight, suboptimum with diagonal Highlight stripes and even-less-good with CanvasText bars, so the three states stay distinct
