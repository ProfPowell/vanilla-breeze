Description

The <menu> element represents a group of commands or options. Browsers expose it to assistive technology exactly like <ul>: as a list (HTML-AAM maps <menu> to role="list"). Nothing tells a screen reader that the items are commands, and it is not an ARIA menu or toolbar. Choose it for readable markup; add roles yourself when the group is a real toolbar (see Accessibility).

In Vanilla Breeze, <menu> is styled as a flexible container with variants for toolbars, context menus, vertical menus, and icon button groups.

When to Use

  • Toolbars: Groups of action buttons in editors or applications
  • Context menus: Dropdown menus with actions
  • Action lists: Vertical lists of commands
  • Button groups: Related buttons that function as a unit
  • Filter controls: Pill-style toggles for filtering content

When Not to Use

  • For navigation links — use <nav>
  • For content lists — use <ul> or <ol>
  • For dropdown selection — use <select>
  • For full dropdown components — use <drop-down>

Variants

Default Menu

The default menu displays as a horizontal flexbox container.

    •

    .toolbar

    Horizontal toolbar with a raised background. Use .ghost buttons for the flat toolbar look; other button variants keep their fill, and aria-pressed="true" keeps its pressed state. Add role="toolbar" and an aria-label when the group is a real toolbar.

    •

    .context

    Dropdown-style context menu with separators. Works with both buttons and links, and sizes to its content (inline-size: fit-content, at least 10rem).

    •

    .vertical

    Vertical menu layout for sidebar or dropdown patterns. It fills its container, so put it in a sized column such as a sidebar.

    •

    .icons

    Icon-only toolbar with square icon buttons.

    • ...

    .pills

    Pill-shaped buttons for filter or toggle patterns. Mark the selected pill with aria-pressed="true" (and the others "false") so the state is both visible and announced.

    Styling

    Variant Classes Summary

    Class Description
    .toolbar Horizontal toolbar with a raised background; button variants and aria-pressed state are kept
    .context Dropdown-style menu with border, shadow and separators; sizes to its content
    .vertical Vertical stacking layout
    .icons Square icon-only buttons
    .pills Pill-shaped button items
    .compact Reduced spacing and font size

    Menu Separators

    Put role="separator" on an empty list item to divide groups. It draws a vertical rule in row menus (default, .toolbar, .pills) and a horizontal rule in column menus (.context, .vertical). The rule is a border, so it stays visible in forced-colours mode.

    Accessibility

    Semantic Structure

    <menu> is announced as a list with a count of items, like <ul>. It does not say the items are commands. Each <li> should contain a <button> or <a>, whose role and name carry the meaning.

    Toolbars

    For a real toolbar (a formatting bar, a filter group) add role="toolbar" and an aria-label that names it, and put role="none" on the item <li>s: once the menu is a toolbar it is no longer a list, so list items would be orphaned. Use aria-pressed on toggle buttons. Vanilla Breeze does not provide the arrow-key roving focus that the APG toolbar pattern describes: each button stays a separate Tab stop, which is still operable. Add your own roving tabindex script if you need the full pattern.

    For pop-up command menus with arrow-key navigation, use <drop-down> or <context-menu>, which add role="menu" and the keyboard model.

    ARIA Roles

    • role="toolbar" + aria-label — Names a group of controls as a toolbar
    • aria-pressed — Toggle and filter buttons (styled as pressed when "true")
    • role="separator" — Marks visual dividers between groups of items
    • aria-label — Required on icon-only buttons to describe the action
    • aria-disabled — For non-functional menu items

    Icon Buttons

    When using icon-only buttons, always include an aria-label for screen reader users:

    Keyboard Navigation

    Key Action
    Tab Move focus between menu buttons (no arrow-key roving is provided)
    Enter / Space Activate focused button

    Browser Support

    The <menu> element is supported in all browsers. Browsers and screen readers treat it as a list, identical to <ul>.
