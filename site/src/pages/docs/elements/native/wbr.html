Description

The <wbr> (Word Break Opportunity) element suggests where the browser may break a line if it needs to wrap. Unlike <br>, it does not force a break — the break only happens when the line needs to wrap there.

It is most useful for long URLs, compound words, technical identifiers, and long Latin tokens (URLs, file paths, product codes) embedded in Chinese or Japanese text, where you want the line to wrap at a meaningful point rather than an arbitrary one.

When to Use

  • Long URLs: Insert break opportunities after slashes
  • Compound words: Long concatenated words that overflow narrow containers
  • Technical identifiers: CamelCase class names, package paths
  • Long Latin tokens in CJK text: a URL or path inside Chinese or Japanese prose. The break between an ideograph and a Latin word is already allowed; put <wbr> inside the Latin token
  • Email addresses: Break opportunities before @ or after dots

When NOT to Use

  • For forced line breaks — use <br>
  • For hyphenation — use CSS hyphens: auto
  • When an arbitrary break point is acceptable — VB's overflow-wrap: break-word already stops the overflow (see below)
  • Between CJK characters, or between CJK and Latin text — line breaking already allows a break there

How wbr Interacts with VB's overflow-wrap

VB sets overflow-wrap: break-word on p, h1–h6, inline code and samp. So in VB a long URL never overflows its paragraph, with or without <wbr>. The difference is where the line breaks:

  • Without <wbr>: the browser finds no break opportunity in the token, so overflow-wrap breaks it at whatever character reaches the edge of the box, often mid-segment (exam / ple.com).
  • With <wbr>: the browser prefers your break points, and wraps after a slash or between word parts. overflow-wrap is only the last resort if a single segment is still too wide.

The demo above shows this: both boxes stay inside their border, but only the <wbr> version breaks at a sensible place.

Copy, Paste and Search

<wbr> adds nothing to the text: copying, find-in-page and the accessible name all see the unbroken string. Its character-based alternatives do not behave the same:

Markup When the line breaks Copied text Find-in-page
<wbr> Breaks with no visible mark Unchanged Matches the whole word
&shy; (soft hyphen, U+00AD) Shows a hyphen at the break May include the invisible U+00AD Usually matches; some tools treat U+00AD as a character
&#8203; (zero-width space, U+200B) Breaks with no visible mark Includes U+200B, which corrupts pasted URLs, identifiers and commands Splits the word, so a search for the whole word can fail

That is the main reason to prefer <wbr> for URLs and code. Use &shy; only for prose words where a hyphen at the break is wanted. In link text, <wbr> never changes the href: <a href="https://example.com/docs/guide">example.com/<wbr>docs/<wbr>guide</a> still links to the full URL.

CJK Text

Chinese and Japanese text needs no <wbr> between characters: line breaking already allows a break between any two ideographs or kana, and between an ideograph and a Latin word. VB keeps word-break: normal for CJK (and keep-all for Korean, which separates words with spaces), and adds line-break: strict for the stricter kinsoku rules. CSS Alternatives

Consider CSS solutions when <wbr> would be tedious to insert manually:

CSS PropertyEffect
overflow-wrap: break-word Breaks a word at any point, but only when nothing else fits. VB applies it to paragraphs, headings, inline code and samp
word-break: break-all Breaks between any two characters, even when a better break exists. Aggressive: it splits Latin words and URLs embedded in CJK text, so VB deliberately does not use it
hyphens: auto Insert hyphens at syllable boundaries (used by VB's p.justify)

Use <wbr> when you need precise control over where breaks can occur.

CSS Reference

wbr { display: inline; }

VB explicitly sets display: inline to ensure consistent behavior. The element is a void element (no closing tag) and inserts no visible content.

Accessibility

  • <wbr> has no effect on screen readers — it is purely visual
  • The break is invisible; it only affects where line wrapping can occur
  • Text content remains intact and continuous for assistive technologies
