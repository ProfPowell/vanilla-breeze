Overview

Vanilla Breeze provides coordinated styling for code-related elements. <code>, <pre>, <kbd> and <samp> share var(--font-mono); <var> keeps the body font and is set in italic with an accent color.

  • <code> — Inline code snippets
  • <pre> — Preformatted text blocks
  • <kbd> — Keyboard input
  • <samp> — Sample output
  • <var> — Variables

Inline Code

Use <code> for inline code within text. It displays in a monospace font with a subtle background. Long identifiers and URLs break anywhere (overflow-wrap: anywhere) rather than overflowing narrow containers.

Use the console.log() function to debug your code.

When to Use Inline Code

  • Function and method names
  • Variable and property names
  • CSS property-value pairs
  • File names and paths
  • HTML element and attribute names
  • Command-line commands

Code Blocks

Wrap <code> (or <samp> for output) inside <pre> for multi-line blocks. VB distinguishes pre:has(code, samp) (full code block treatment with background, padding, border-radius) from bare <pre> (lighter treatment for ASCII art, poetry). Both preserve whitespace exactly and scroll horizontally — see <pre>.

function greet(name) {
  return `Hello, ${name}!`;
}

console.log(greet('World'));

Syntax highlighting and languages

For highlighted, copyable code blocks use the <code-block> web component. On plain <code>, class="language-*" has no VB effect — it is only a hook for external highlighters — with one exception: class="language-math" auto-loads VB's MathML enhancement (the same one as data-math), which swaps the source for the precompiled MathML in data-mathml.

Bold in Code

Inside <code> and <pre>, <b> and <strong> get a subtle highlight background instead of relying on font weight alone. This is more visible in monospace fonts where weight differences can be subtle.

const result = calculateTotal(items);
console.log(result);

Keyboard, Output and Variables

<kbd> has a raised key-cap appearance (border plus box-shadow). <samp> is monospace with no background. <var> is italic with var(--color-interactive) to distinguish it from general italic text. Each element page lists its rules; the source is src/native-elements/code/styles.css.

Key Features

Feature Implementation
Monospace font code, pre, kbd and samp use var(--font-mono)
Nested code reset code/samp inside pre lose background and padding
pre:has(code, samp) vs bare pre Code and output blocks get full treatment; bare pre gets light styling
Inline overflow Inline code uses overflow-wrap: anywhere
Bold highlight b/strong in code get background color instead of weight
Keyboard styling kbd has border + shadow for 3D key appearance
Variable accent var uses --color-interactive to distinguish from em

Translation

Browser and machine translation tools translate code unless told not to, and there is no CSS way to tell them. Use the HTML translate="no" attribute on code that must stay verbatim (see Internationalization):

Accessibility

Screen Reader Behavior

<code>, <kbd>, <samp> and <var> are all announced as plain text. Monospace, key-cap borders, italics and color are visual only, so the surrounding prose must say what the reader is looking at ("press the Enter key", "replace id with…").

Best Practices

  • Use the right element for the content type
  • Introduce code blocks with explanatory text
  • Add tabindex="0" to scrollable <pre> for keyboard accessibility
