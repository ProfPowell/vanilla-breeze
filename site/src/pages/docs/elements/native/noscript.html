Description

The <noscript> element holds content that the browser uses only when scripting is disabled. When scripting is on, the parser treats its contents as raw text: nothing inside is rendered, run or exposed to assistive technology.

In Vanilla Breeze, <noscript> is a supplement, not the main fallback. Pages are written as working HTML first and JavaScript upgrades them (see Progressive Enhancement). Use <noscript> for the small extra message or resource that only makes sense when scripting is off.

In the head

Inside <head>, a <noscript> may contain only <link>, <style> and <meta>. It is useful for a no-JS stylesheet, or for undoing a style that assumes JavaScript will run.

For a single rule, the (scripting: none) media query in your normal stylesheet does the same job without an extra element.

noscript, data-requires-js and (scripting: none)

VB’s reset ships two attribute hooks, both scoped to @media (scripting: none):

@media (scripting: none) { [data-requires-js] { display: none !important; } [data-js-enhanced] { display: none; } }
ToolUse it for
data-requires-js A control that has no meaningful static equivalent, such as a copy button or a live filter. Hidden with !important when scripting is off, so nothing can show it again.
data-js-enhanced JS-driven internals of a component that has a static fallback, such as toggle buttons around content that is readable without them. Hidden without !important, so a component can override it.
@media (scripting: none) Your own CSS changes for the no-JS case, such as showing a hint or expanding collapsed content.
<noscript> Extra content that only no-JS users need: a message, an alternative link, a no-JS stylesheet in the head.

Prefer static HTML that works on its own over hiding things. A list of links that a component turns into tabs needs none of these tools.

VB components that cannot render without JavaScript keep a static.html fallback beside their source, and many of those use <noscript> to explain what is missing.

Caveats

  • JavaScript on, but broken. <noscript>, data-requires-js and (scripting: none) react only to scripting being disabled. If scripting is on but the bundle fails to load, is blocked or throws, none of them apply: the noscript content stays hidden and data-requires-js controls stay visible but dead. Only real HTML that JavaScript upgrades survives that case.
  • Not exposed when JS is on. With scripting enabled, noscript content is inert text. Screen readers don’t announce it, and you cannot style or query its children.
  • Not signed. VB’s canonical document for content signing skips <noscript>, like <script> and <template>. Don’t put content there that the page’s signature is meant to cover.
  • Fallback text is authored. Text inside <noscript> is plain HTML, so translate it with the rest of the page; no component localises it for you.

Attributes

This element has no attributes of its own. It supports global attributes.

Accessibility

  • When scripting is off, noscript content is ordinary page content: give it the same headings, link text and structure as anything else.
  • Don’t use <noscript> to tell users to “enable JavaScript” when the page could work without it. Users who run without scripts, often for security or assistive-technology reasons, are better served by a working fallback.
  • A control hidden with data-requires-js should leave a working alternative, such as a link, form or plain text, so the task stays possible.
