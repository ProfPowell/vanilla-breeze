When to Use

  • Comments and messages
  • Descriptions and bios
  • Address fields (multi-line)
  • Code or text snippets
  • Any free-form text longer than a single line

Basic Usage

Vanilla Breeze styles textarea as a full-width block element with a minimum height of 8rem, vertical-only resize, and shared focus/border/placeholder styles with input and select. A simple textarea with label and placeholder:

Attributes

Attribute Purpose Example
rows Initial visible lines rows="5"
cols Visible character width (overridden by VB's inline-size: 100%) cols="40"
minlength Minimum character count minlength="10"
maxlength Maximum character count maxlength="500"
required Field must have a value required
disabled Prevents editing, raised background disabled
readonly Can select but not edit readonly
placeholder Hint text when empty (muted color) placeholder="..."
wrap Text wrapping: soft (default) or hard wrap="soft"
spellcheck Enable/disable spell check spellcheck="false"

Setting Size

Control the initial height with rows. VB sets a default min-block-size: 8rem, so very small rows values may not reduce the height below that. A data-grow textarea is the exception: its minimum follows rows (default 2).

Character Limits

Use minlength and maxlength for native validation. Pair with data-count to show a live counter.

Textarea States

VB styles three states. Each has a cue that does not rely on colour alone (disabled relies on the cursor and on being skipped by Tab). The examples demo above shows all three in its States section.

State Selector Appearance
Disabled :disabled Raised background, not-allowed cursor. Not focusable and not submitted.
Read-only :read-only --input-readonly-bg background and a dashed border (--input-readonly-border-style). Focusable, selectable and submitted, but not editable.
Invalid [aria-invalid="true"], :user-invalid Error border colour plus a thick inline-start edge. In forced colors the whole border becomes a thick double line.

:user-invalid only matches after the user has interacted with the field, so a required textarea is not shown as invalid on page load.

With form-field

Use the form-field custom element for CSS-only validation with an output message.

Resizing Behavior

VB sets resize: vertical by default so textareas fill their container width while allowing the user to adjust height. Override with CSS if needed:

CSS Property Behavior
resize: vertical Can resize height only (VB default)
resize: horizontal Can resize width only
resize: both Can resize in both directions
resize: none Cannot be resized

Character / Word Count (data-count)

Add data-count to any textarea to show a live character or word count. Works with native maxlength for character mode and data-maxwords for word mode. The counter changes colour at 80% (warning) and 100% (error, also bold), using the --color-warning-text and --color-error-text tokens, which meet AA contrast in light and dark mode. Screen readers hear the count only near or over the limit, after typing pauses.

Character Count

The default mode counts characters. Pair with maxlength to show "42 of 500 characters". Numbers are formatted with Intl.NumberFormat for the nearest [lang], so a German page shows "1.234 of 2.000".

Word Count

Set data-count="words" and data-maxwords for word-based counting.

Two limits apply to word mode:

  • The word limit is advisory. Unlike maxlength, data-maxwords does not stop typing and does not make the field invalid. Validate it on the server (or with setCustomValidity()) if it must hold.
  • Words are split on whitespace. Languages written without spaces between words (Chinese, Japanese, Thai) count each unbroken run as one word. Use character mode for them.

Counter Text and Localisation

Override the counter text with data-label-* templates. {count} and {max} are replaced with formatted numbers. Plural variants are picked with Intl.PluralRules for the nearest [lang]: add a suffix for each category the language uses (-zero, -one, -two, -few, -many, -other).

Attribute Values Description
data-count "", "words" Enable counter. Empty for characters, "words" for word mode.
data-maxwords number Max word count (word mode only). Advisory: not enforced and not a validity state.
maxlength number Native limit; sets the character-mode maximum and is enforced by the browser.
data-label-limit, data-label-limit-<category> template Counter text when a limit applies. Default "{count} of {max} characters" (or words). The plural category is chosen from {max}.
data-label-characters, data-label-characters-<category> template Counter text with no limit, character mode. Default "{count} character" / "{count} characters".
data-label-words, data-label-words-<category> template Counter text with no limit, word mode. Default "{count} word" / "{count} words".

Reset and Programmatic Values

The counter and data-grow update on every input event and after the owning form is reset. Setting .value from script fires no event, so dispatch one afterwards. The same event refreshes both enhancements:

textarea.value = draft; textarea.dispatchEvent(new Event('input', { bubbles: true }));

Auto-Expand (data-grow)

Add data-grow to a textarea to make it automatically expand as the user types. Uses CSS field-sizing: content where supported, with a JS scrollHeight fallback. It starts at rows lines (default 2) instead of VB's usual 8rem minimum, and the manual resize handle is removed. Set data-max-rows to cap the height.

Max Rows

Set data-max-rows to limit growth. The cap counts text lines and adds the padding and border, so 10 rows shows 10 full lines. Once the limit is reached, the textarea scrolls normally.

Combined with Count

data-grow and data-count work together seamlessly.

Attribute Values Description
data-grow — Enable auto-expanding behavior.
data-max-rows number Maximum rows before scrolling.

Accessibility Notes

  • Always use a label: Every textarea needs an associated label
  • Don't disable resize: Allow users to resize for their needs when possible
  • Provide character limits: If using maxlength, show remaining characters with data-count
  • Use aria-describedby: Link to help text or validation messages
  • Placeholder is not a label: Placeholders disappear when typing
  • Spell checking: Keep spellcheck enabled for prose, disable for code

CSS Reference

From src/native-elements/input/styles.css. Textarea shares its base rule with text inputs and select.

textarea { display: block; inline-size: 100%; padding-block: var(--input-padding-inline); padding-inline: var(--input-padding-inline); min-block-size: var(--input-height); border: var(--border-width-thin) solid var(--input-border); border-radius: var(--input-radius); background: var(--input-bg); color: var(--input-text); caret-color: var(--caret-color); font: inherit; transition: border-color var(--duration-fast) var(--ease-default); /* The halo is decoration; the transparent outline carries focus in forced colors, where box-shadow is dropped */ &:focus { outline: 2px solid transparent; outline-offset: 2px; border-color: var(--input-border-focus); box-shadow: 0 0 0 3px oklch(from var(--input-border-focus) l c h / 0.15); } &::placeholder { color: var(--input-placeholder); } &:disabled { background: var(--color-surface-raised); cursor: not-allowed; } /* Readonly: dashed border is the non-colour cue */ &:read-only:not(:disabled) { background: var(--input-readonly-bg); border-style: var(--input-readonly-border-style); } /* Invalid: thick inline-start edge is the non-colour cue */ &:is([aria-invalid="true"], :user-invalid) { border-color: var(--color-error); border-inline-start-width: var(--border-width-thick, 4px); } @media (forced-colors: active) { &:focus { outline: 2px solid Highlight; } &:is([aria-invalid="true"], :user-invalid) { border-style: double; border-width: var(--border-width-thick, 4px); } } } textarea { min-block-size: 8rem; resize: vertical; } /* data-grow starts at its rows (field-sizing ignores rows) */ textarea[data-grow] { min-block-size: calc( var(--grow-rows, 2) * 1lh + 2 * var(--input-padding-inline, 0.5rem) + 2 * var(--border-width-thin, 1px) ); }
