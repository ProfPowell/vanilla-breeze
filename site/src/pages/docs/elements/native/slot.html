Description

A <slot> lives inside a shadow root. It marks where the host element's own children (its light DOM) are displayed. A child with slot="name" goes to <slot name="name">; every other child goes to the unnamed default slot. Children are displayed in the slot, but they are not moved: they stay in the light DOM, where page CSS and scripts still reach them.

Outside a shadow root, a <slot> does nothing. The browser treats it as display: contents, and its children render as if it were not there.

Example: Declarative Shadow DOM

A <template shadowrootmode="open"> attaches a shadow root while the HTML is parsed, with no JavaScript. The shadow root's styles are scoped to it. Here, two named slots and a default slot place the light-DOM children, and the role slot shows fallback content when nothing is assigned to it.

Shadow roots can be attached to custom elements and to a fixed list of native elements, including article, section, aside, header, footer, main, nav, p, span, blockquote and h1-h6.

Slots in Vanilla Breeze

Most VB components render into the light DOM: no shadow root, so no <slot>. Page CSS, themes and data-* attributes reach every part of them.

slot="…" as a styling hook

Some light-DOM components still read the slot attribute, as a CSS hook rather than for projection. <layout-card> switches to its structured layout when it has a slot="header", slot="content" or slot="footer" child (or a header/section/footer child). It does this with :has() and child selectors; nothing is projected.

Components with a shadow root

A few components use shadow DOM and render real <slot>s for your children:

  • <icon-wc> - default slot: light-DOM content inside the element shows when the icon cannot be loaded
  • <audio-player> and <video-player> - default slot for the native media element and its sources/tracks
  • <score-card> - named slots title, value, change, sparkline, description, icon
  • <geo-map> - default slot for the map caption

chart-wc and audio-visualizer also attach a shadow root but render no slots.

Styling Slotted Content

Slotted children keep their page styles. Inside the shadow root, ::slotted(selector) can style them too, but only the top-level slotted elements (not their descendants), and the page's own rules win over it.

/* inside the shadow root */ ::slotted(img) { border-radius: var(--radius-m); } ::slotted([slot="name"]) { font-weight: 700; }

Scripting: slotchange and assigned nodes

A slot fires slotchange when its assigned nodes change. assignedElements() and assignedNodes() return what is currently assigned; pass { flatten: true } to include fallback content and nested slots.

const slot = this.shadowRoot.querySelector('slot[name="icon"]'); slot.addEventListener('slotchange', () => { this.toggleAttribute('data-has-icon', slot.assignedElements().length > 0); });

Attributes

Attribute Description
name Slot name. Host children with a matching slot attribute are assigned here. Omit it for the default slot.

The element also accepts the global attributes. The slot attribute that targets a slot is a global attribute set on the host's children.

Accessibility

  • The accessibility tree follows the rendered (flattened) tree: slotted content is read where its slot sits, not where it appears in the light-DOM source. Keep slot order in the shadow root matching a sensible reading order, and avoid CSS reordering on top of it.
  • A <slot> is display: contents and adds no role or name. It does not remove its content from the accessibility tree.
  • Headings, labels and landmarks in slotted content keep their meaning. ID references (aria-labelledby, for) do not cross the shadow boundary, so keep a label and its control on the same side.
  • Fallback content inside a slot is real content: give it the same care as the assigned content it stands in for.
