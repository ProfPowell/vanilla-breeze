Description

The <samp> element represents sample output from a computer program. VB styles it in var(--font-mono) at 0.9em. It is part of VB's code-family elements alongside <code>, <kbd>, and <var>. Browser translation tools will translate it unless you add the HTML translate="no" attribute (see Internationalization).

When to Use

  • Command output: Results from terminal commands
  • Error messages: System error text
  • Status messages: Build output, test results
  • API responses: Showing what a system returns

When NOT to Use

  • For code the user writes — use <code>
  • For keyboard input — use <kbd>
  • For variables — use <var>

Examples

The command returned: Hello, World!

Error message: File not found: config.json

 
$ npm install
added 125 packages in 3.2s

$ npm run build
Build completed successfully.
Output: dist/bundle.js (45.2 KB)

Mixed with kbd

Pair <kbd> (user input) with <samp> (system response) to document command-line workflows:

Type git status and the system responds with On branch main.

CSS Reference

samp { font-family: var(--font-mono); font-size: 0.9em; overflow-wrap: break-word; /* long paths, URLs and hashes wrap */ } /* Inline code and output keep their own direction on RTL pages */ :is(code, samp):not(pre *) { unicode-bidi: plaintext; }

Unlike <code>, <samp> has no background or padding — output text should feel like raw system text, not highlighted code.

Long unbroken output such as file paths, URLs or hashes wraps inside narrow containers instead of overflowing. Inside a <pre> block the output keeps its exact line breaks.

On a right-to-left page, inline <samp> and <code> are isolated from the surrounding text and take their direction from their own content. Without this, output such as File not found: config.json. could have its edge punctuation moved to the wrong end. Block output in <pre> is always left-to-right unless the <pre> has its own dir.

Accessibility

  • Screen readers read <samp> as regular text — the monospace styling is visual only
  • Provide context: "The system responded with..." or "Error:" before the output
