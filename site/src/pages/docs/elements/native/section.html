Usage

Use the <section> element for:

  • Chapters or thematic groups within an article
  • Each panel in a tabbed interface
  • Major sections of a homepage (hero, features, testimonials)
  • Numbered or labeled sections in documentation

A section should have a heading that identifies its content. If it has no heading, it is not a section: in VB, group the content with a layout element (<layout-stack>, <layout-cluster>, …) or put data-layout on the parent, rather than reaching for a <div>.

Page-Band Attributes

For landing pages built from stacked full-width bands, sections also take a few data attributes.

data-padding

Fluid block padding that scales with the viewport. Bare data-padding is the normal step; small, xsmall and none step down. data-padding-start="none" and data-padding-end="none" drop one side so neighbouring bands butt together.

Container Behavior

Every <section> (like main, article and most asides) is a size query container: VB gives it container-type: inline-size. Two consequences:

  • Container units and queries resolve against the section. cqi units and @container queries inside it measure the section, not the viewport.
  • A content-sized section can collapse. Size containment ignores the section's content when working out its width. As a flex or grid item that is sized by its content (a display: flex row, an align-items: center column, an auto track), the section shrinks to zero width. VB already undoes this inside layout-cluster, layout-reel, centred layout-cover and aligned layout-stack.

Elsewhere, opt out by setting container-type: normal on the section in your own CSS, or give it an explicit size. Inside the layouts above, add data-container to a section to keep it as a container on purpose.

/* a section sized by its content in your own flex row */ .toolbar > section { container-type: normal; }

Accessibility

  • A <section> is a region landmark only when it has an accessible name, e.g. aria-labelledby pointing at its heading (or aria-label). A heading alone does not make it a landmark.
  • Name only the few sections a user would want to jump to. Naming every section floods the landmark list and makes it less useful.
  • Always include a heading (h2-h6) so the section shows up in heading navigation
  • Use appropriate heading levels - don't skip levels for visual styling
  • If a section has no meaningful heading, it is not a section: use a VB layout element or data-layout on the parent
  • Hero sections should still have a proper h1 for the page title
  • Grid sections should use semantic elements (like <article>) for grid items when appropriate
  • In forced-colors mode backgrounds are flattened, so .alt sections gain a system-colour border to stay distinct
