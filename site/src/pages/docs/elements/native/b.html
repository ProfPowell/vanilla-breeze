Description

The <b> element draws attention to text without conveying extra importance or urgency. It is styled with font-weight: 600 and includes typographic refinements: font-synthesis: weight style lets the browser synthesize bold when the font has no bold face, and font-optical-sizing: auto enables optical size adjustments.

A real face always wins: if the font has a face at weight 600 or heavier (or a variable weight axis), that is used. Only when it does not (for example, a web font loaded only in its regular weight) does the browser synthesize a faux bold, so <b> never renders at plain body weight. Load a bold face for the best letterforms.

In Vanilla Breeze, <b> also has special behavior inside code blocks — bold text gets a subtle highlight background instead of relying on weight alone, which is more visible in monospace fonts.

When to Use

  • Product names in reviews or listings
  • Keywords in paragraph summaries or abstracts
  • Lead sentences in news articles

When NOT to Use

  • For important or urgent text — use <strong>
  • For emphasis that changes meaning — use <em>
  • For headings — use <h1>–<h6>
  • Purely for visual styling — use CSS font-weight instead

b vs strong

Both render as bold, but they carry different semantics:

Element Semantics Accessibility tree
<b> Draw attention — no extra importance No role (generic)
<strong> Strong importance or urgency strong role

By default, major screen readers read both elements exactly like the surrounding text; neither is announced or voiced differently unless the user turns on font or emphasis reporting. Choose between them for meaning, and make sure the words themselves carry any warning.

Bold in Code Blocks

Inside <code> and <pre>, bold text gets a subtle highlight background (using var(--color-interactive) at 12% opacity) instead of relying on font weight alone. This is more visible in monospace fonts where weight differences can be subtle.

Combined Bold + Italic

Nesting <b> and <i> (or <strong> and <em>) combines the two through ordinary inheritance: the inner element inherits weight 600 and adds italic. Both elements set font-synthesis: weight style, so a bold-italic face (or variable weight and italic axes) is used when the font has one, and the browser synthesizes the missing weight or slant when it does not.

CSS Reference

strong, b { font-weight: 600; font-synthesis: weight style; /* real face wins; synthesize if missing */ font-optical-sizing: auto; } /* Nested bold + italic. Re-states values the inner element already inherits, so it has no visual effect on its own. */ :where(b i, i b, strong em, em strong) { font-weight: 600; font-style: italic; font-synthesis: weight style; } /* Bold in code — highlight background instead of just weight */ :where(code, pre) :where(b, strong) { background-color: oklch(from var(--color-interactive) l c h / 0.12); border-radius: var(--radius-s); padding-inline: var(--size-2xs); }

Key Styling Features

Feature Implementation Purpose
font-synthesis: weight style Applied to b, strong, i, em Uses the font's real bold/italic face when present; otherwise the browser synthesizes one, so emphasis is never invisible
font-optical-sizing: auto Applied to b, strong Enables optical size adjustments in variable fonts
Code highlight background-color in code/pre More visible bold in monospace contexts

Accessibility

  • <b> has no role and conveys no importance in the accessibility tree
  • Use <strong> when the text is genuinely important, but do not expect screen readers to voice it differently — by default they read <strong> and <b> like any other text
  • Do not rely on bold alone to convey meaning — combine with context or additional markup

Related

  • <strong> — Strong importance, seriousness, or urgency
  • <em> — Emphasis that changes meaning
  • <i> — Alternate voice (technical terms, thoughts, ship names)
  • <mark> — Highlight for relevance (search results, references)
