Description

The <em> element marks text with stress emphasis — the kind that changes the meaning of a sentence when spoken aloud. Moving the emphasis to a different word changes what the sentence communicates.

VB styles <em> with font-synthesis: none to prevent browsers from generating faux italic glyphs, and font-optical-sizing: auto for proper rendering in variable fonts.

The catch with font-synthesis: none: if the active font has no italic face, the browser will not fake one, so the emphasis renders upright and is invisible. Load an italic face for every text font you use. CJK fonts almost never ship italics, so VB swaps italic for emphasis marks in those languages (see CJK emphasis).

When to Use

  • Stress emphasis: When the emphasis changes meaning — "I love chocolate" vs "I love chocolate"
  • Corrective emphasis: "Do not press that button"
  • Contrastive stress: "It's not the what, it's the how"

When NOT to Use

  • For alternate voice, foreign words, thoughts, ship names — use <i>
  • For importance or urgency — use <strong>
  • For defining terms — use <dfn>
  • For work titles — use <cite>
  • Purely for visual styling — use CSS font-style: italic

em vs i

Both render as italic, but carry different semantics:

Element Semantics Screen Reader
<em> Stress emphasis — changes meaning Usually not conveyed by default
<i> Alternate voice — no meaning change Not announced differently

Emphasis in Italic Contexts

Italic emphasis inside text that is already italic would disappear. VB uses the classic typographic toggle: <em> and <i> inside an italic context — <blockquote>, <cite>, <dfn>, <var>, or another <em>/<i> — switch back to upright. The toggle goes one level deep.

Only contexts that are actually italic count:

  • <address> and <cite data-variant="quoted"> are upright, so <em> inside them stays italic.
  • A blockquote's attribution line (blockquote > footer, blockquote > cite) is upright, so <em> there is italic again — unless another italic context sits between the attribution and the emphasis.
  • Themes with an upright blockquote (brutalist, cyber, super2026, swiss) re-assert italic inside it; the editorial theme's italic <h1> and <h3> toggle like a blockquote does.
  • The dyslexia theme makes <em> upright and semibold instead of italic.

CJK Emphasis

Chinese, Japanese and Korean fonts generally have no italic face, so with font-synthesis: none an italic <em> would look like plain text. When the content language is zh, ja or ko (set via lang), VB draws emphasis marks instead: sesame dots over the characters for Japanese and Korean, and filled dots under the characters for Chinese. Emphasis marks are reserved for <em>: <i> gets a calligraphic face with a dotted underline, <dfn> a heavier weight and <cite> a wavy underline.

Romanised text (lang="ja-Latn", zh-Latn, ko-Latn) is Latin script and keeps the real italic.

When an <em> contains <ruby>, the ruby text already occupies the space above the characters, so the marks move underneath. Without this, Safari drops the marks entirely and other browsers stack them above the ruby.

Code inside a CJK <em> (<code>, <kbd>, <samp>, <var>) gets no marks: Japanese typography does not put emphasis dots on Latin identifiers. The surrounding CJK text keeps them.

em, i { font-style: italic; font-synthesis: none; /* prevent faux italic */ font-optical-sizing: auto; } /* Combined bold + italic */ :where(b i, i b, strong em, em strong) { font-weight: 600; font-style: italic; font-synthesis: none; } /* Toggle: emphasis inside an italic context is upright */ :where(blockquote, cite:not([data-variant~="quoted"]), dfn, var, em, i) :is(em, i) { font-style: normal; } /* Upright islands (attribution, quoted cite) restore italic */ :where(blockquote > :is(footer, cite), cite[data-variant~="quoted"]) :is(em, i):not( :where(blockquote > :is(footer, cite), cite[data-variant~="quoted"]) :where(em, i, cite:not([data-variant~="quoted"]), dfn, var) * ) { font-style: italic; } /* CJK: emphasis marks instead of a missing italic (i18n styles); romanised -Latn tags keep the real italic */ em:is(:lang(zh), :lang(ja), :lang(ko)):not(:lang(zh-Latn), :lang(ja-Latn), :lang(ko-Latn)) { font-style: normal; text-emphasis: filled sesame; text-emphasis-position: over right; } em:lang(zh):not(:lang(zh-Latn)) { text-emphasis: filled dot; text-emphasis-position: under right; } /* Ruby holds the space above: marks go under */ em:is(:lang(zh), :lang(ja), :lang(ko)):not(:lang(zh-Latn), :lang(ja-Latn), :lang(ko-Latn)):has(ruby) { text-emphasis-position: under right; } /* No 圏点 on code or Latin identifiers */ em:is(:lang(zh), :lang(ja), :lang(ko)):not(:lang(zh-Latn), :lang(ja-Latn), :lang(ko-Latn)) :is(code, kbd, samp, var) { text-emphasis: none; }

Accessibility

  • Most screen readers do not convey <em> by default; a few can be configured to announce emphasis or change voice, but you cannot count on it
  • Treat <em> as meaning for authors, search engines and reading tools — the visual style is what most users get
  • Nesting <em> increases the degree of emphasis (VB shows the inner level upright)
  • Do not rely on emphasis alone to convey critical meaning — combine with context

Related

  • <i> — Alternate voice (foreign words, thoughts, ship names)
  • <strong> — Strong importance or urgency
  • <b> — Draw attention without importance
  • <cite> — Titles of creative works (also italic)
  • <dfn> — Defining instance of a term (italic + semi-bold)
