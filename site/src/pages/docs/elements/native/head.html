Description

The <head> element holds document metadata. For a Vanilla Breeze page it is also where the stylesheet, the JS bundle and a tiny inline boot script go. This page describes the recommended head for a VB page: what is required, what VB reads, and what is optional.

Required Elements

Element Purpose
<meta charset="UTF-8"> Character encoding. Must appear within the first 1024 bytes of the document.
<meta name="viewport" ...> Viewport configuration for responsive layout: width=device-width, initial-scale=1.0. Do not disable zoom.
<title> Page title, announced first by screen readers and shown in tabs and search results. Page Title | Site Name gives both the page and the site.

Strongly recommended: <meta name="color-scheme" content="light dark"> tells the browser before any CSS arrives that the page supports both schemes, so a dark-mode visitor gets a dark canvas and dark form controls from the first paint instead of a white flash. <meta name="description"> is the summary search engines and social previews show.

Loading Vanilla Breeze

CSS

File (/cdn/) npm specifier Contents
vanilla-breeze.css vanilla-breeze/css Everything: native elements, layouts, all component styles, the bundled themes (modern, minimal, classic, a11y-*)
vanilla-breeze-core.css vanilla-breeze/core-css Same foundation with core component styles only; pair with vanilla-breeze-core.js
themes/<name>.css vanilla-breeze/themes/<name> One decorative theme. Optional: the JS bundle loads it on demand when data-theme names it, but a <link> avoids the late repaint and works without JS.

Link order between VB files does not matter. Every theme file declares @layer bundle-theme itself and starts with VB's layer-order statement, so a theme linked before or after the main stylesheet lands in the same layer. Your own unlayered CSS beats all VB layers.

JavaScript

File (/cdn/) npm specifier Contents
vanilla-breeze-autoload.js — Core components up front; every other component loaded the first time it appears on the page. The easiest choice.
vanilla-breeze-core.js vanilla-breeze/core-js Core components only; add vanilla-breeze-extras.js (vanilla-breeze/extras-js) for the rest
vanilla-breeze.js vanilla-breeze, vanilla-breeze/js Every component in one file

All three are ES modules (type="module", deferred by default), and all three start the theme system on load. Load one of them, not several.

Theme Flash Prevention

The bundles are modules, so they run after first paint. A returning visitor who chose dark mode or a brand theme would see one frame of the defaults first. A small classic inline <script> placed before the stylesheet applies the saved preferences to <html> synchronously.

Preferences are stored by VBStore under vb:{namespace}:{key}, each value wrapped as { "data": …, "timestamp": … }:

Preference Storage key → field Applied as
Light/dark mode vb:theme:current → mode data-mode
Brand theme vb:theme:current → brand data-theme
Accessibility themes vb:settings:a11y (array)
Accent, fluid, border style, icon set, backdrop vb:theme:current → accent, fluid, borderStyle, iconSet, backdrop, backdropChrome data-accent, data-fluid, data-border-style, data-icon-set, data-backdrop, data-backdrop-chrome
Reduced motion vb:settings:extensions → motionFx === false data-motion-reduced
Sticky header vb:settings:sticky = "on" data-sticky

A page that authors data-mode="light" or "dark" keeps it until the visitor picks a mode; a mode change from another tab does not show while the page forces its own. On a page with data-theme-source="site" the first data-theme id is the brand (default is valid) and the site's brand beats a stored one; other ids survive.

A root-attribute field that is null or missing means "no choice": the attribute you authored on <html> stays. The snippet records your authored values in window.__vbAuthoredRoot before writing, so ThemeManager can restore them on reset.

A decorative brand theme saved by the visitor still needs its CSS: either link the themes you offer up front, or let the JS bundle fetch it (one repaint). The VB documentation site's own copy of this script (site/src/includes/head.html in the repository) additionally writes the theme <link> during parsing and hides the body until it loads.

Theme Color

<meta name="theme-color"> tints the browser's address bar and tab strip. Give one value (or a media-scoped light/dark pair) as the default. Once the JS bundle runs, ThemeManager sets every theme-color meta to the page's actual background colour after each mode or theme change, removing the media attributes: the mode is known by then.

Metadata VB Reads

Several components read standard metadata from the head rather than asking you to repeat it in attributes: <page-info> reads author, last-modified, license, Open Graph article dates and the vb:* provenance fields; <site-index> aggregates keywords and article:tag; the topic and analytics systems read repeated <meta name="concept">. The principle is public standards first, with vb:* names only for what no standard covers. The field families are summarised on Document provenance.

Content Security Policy

Under a CSP without 'unsafe-inline', the inline boot script needs a nonce (or a 'sha256-…' hash of its exact text) in script-src, and so does any inline <style> in style-src. VB's own files need only 'self' (or the CDN origin you serve them from) for script-src, style-src and font-src; no third-party origins are involved.

Content-Security-Policy: script-src 'self' 'nonce-r4nd0m'; style-src 'self'; font-src 'self'

Components and ThemeManager change styles through the CSSOM (element.style.setProperty), which style-src does not block.

Permitted Child Elements

The <head> element may only contain metadata content:

Element Purpose
<title> Document title (exactly one required)
<meta> Metadata: charset, viewport, description, theme-color, etc.
<link> External resources: stylesheets, favicons, preconnects, canonical URLs
<style> Inline CSS (prefer external stylesheets; use for critical CSS or page-specific overrides)
<script> JavaScript (VB recommends one inline script for theme flash prevention; the bundles themselves are modules)
<base> Base URL for relative links (rarely needed)
<noscript> Fallback content when JavaScript is disabled

Accessibility

  • lang on <html>: set on the parent <html> element (not <head>); screen readers use it to pick pronunciation rules.
  • Title: the <title> is the first thing announced when a page loads. Put the page-specific part first: Page Title | Site Name.
  • Viewport: never add maximum-scale=1 or user-scalable=no; zoom is how many low-vision users read.
  • color-scheme meta: lets dark-mode users get a dark canvas and native controls from the first paint, avoiding a bright flash.
