Description

The <audio> element embeds audio content with native browser playback controls. Vanilla Breeze styles audio players to be block-level and full-width by default, with variants for compact and minimal layouts.

Audio handling follows a progressive enhancement approach with four layers — each functional on its own:

  1. Layer 1 — Native <audio> with <source> fallback chain
  2. Layer 2 — CSS styling: accent-color, border-radius, color-scheme
  3. Layer 3 — Track listing via <details> + <ol class="track-list">
  4. Layer 4 — <audio-player> web component with custom controls

When to Use

  • Podcasts — Episode players with playback controls
  • Music players — Song or album playback
  • Sound effects — UI feedback or game audio
  • Voice recordings — Interviews, voicemail, audio messages
  • Audiobooks — Narrated content

Layer 1: Native Baseline

Works everywhere with no CSS or JS. Always include at least one <source> with a type attribute and a download link as the ultimate fallback.

Layer 3: Track Listing

The track list itself is HTML + CSS: <details>/<summary> shows and hides it natively, and on its own each track link simply navigates to the audio file. The .audio-standalone contract

  • Structure — the container holds one <audio> and one .track-list (usually inside <details>). Each track is an <li> with an <a href> pointing at its audio file. Containers without both are left alone.
  • Click — clicking a track link sets the audio source to the link's URL, moves data-audio-active to that <li> and starts playback. A refused play() (autoplay policy, unloadable file) is caught, never thrown.
  • Ended — the finished track gets data-audio-played and keeps data-audio-active; the next track in list order then starts. After the last track playback stops and that track stays active. A native <audio loop> repeats the current track instead (it never ends).
  • Once only — an enhanced container is marked data-audio-playlist-init. Containers added to the page later are enhanced automatically.
  • Not inside <audio-player> — the component runs its own playlist with the same click and ended behavior (it shares the track-activation code), and adds shuffle and list looping.

Text Tracks

Captions

<audio> accepts <track> children, but browsers do not render text tracks for audio — there is no video surface to draw cues on, so a kind="captions" track is parsed and then never shown. The cues are still available through the textTracks API, so displaying them requires a custom renderer that listens for cuechange and writes the active cue into the page.

For most content, prefer one of these instead:

  • A full text transcript next to the player (the most robust option, and what WCAG asks for prerecorded audio)
  • A <video> element, which does render caption tracks natively, if synchronised on-screen captions are required

Accessibility

Transcripts

Provide text transcripts for audio content so deaf users and those who cannot play audio can access the information.

Best Practices

  • Always provide a text transcript for important audio
  • Never autoplay audio — it is disruptive and inaccessible
  • Ensure controls are visible and keyboard accessible
  • Provide context about what the audio contains
  • Include duration information when available
