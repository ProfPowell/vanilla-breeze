When to Use

  • Submitting or resetting a form
  • Triggering actions on the current page (opening dialogs, toggling states)
  • Any interactive element that performs an action rather than navigation

When NOT to Use

Do not use <button> for navigation. Use <a> instead. If you need a link that looks like a button, apply class="button" to an anchor element.

Style Variants

Visual variants communicate hierarchy and importance. Use primary for the main action, secondary for supporting actions, and ghost for tertiary or de-emphasized actions.

Class Appearance Use Case
(default / primary) Solid --btn-color background (defaults to --color-interactive); text colour picked with contrast-color() where supported, else --color-text-on-primary Primary action. Use sparingly, typically once per section
.secondary Transparent with a --btn-color border and text Supporting action that pairs with primary
.ghost No background, transparent border, text-only Tertiary or de-emphasized actions

Sizes

Size variations accommodate different contexts, from compact inline actions to full-width form submissions.

Class Padding Font Size Use Case
.small xs / s sm Compact interfaces, inline actions
(default) s / m inherit Standard actions
.large m / l lg CTAs, hero sections
.full-width (inherits) (inherits) Full-width buttons, mobile form submit

Custom Colour

Set --btn-color to recolour a button. Hover and active shades are derived from it, the secondary and ghost variants follow it, and on browsers with contrast-color() the primary text switches between black and white to stay readable. The same contract applies to <a class="button"> and <input type="submit">.

Upgrade

Property Default Effect
--btn-color var(--color-interactive) Base colour for every variant; hover and active shades derive from it
--btn-padding-block var(--size-s) Top and bottom padding (also the side padding of icon-only buttons)
--btn-padding-inline var(--size-m) Left and right padding

--btn-letter-spacing normal Label tracking

The .small and .large classes set padding directly, so the padding properties apply to the default size.

Button Types

The type attribute determines the button's behavior within a form. A button with no type, or an unrecognised value, is a submit button: put a type-less button inside a form and clicking it submits the form. Always write type="button" for buttons that run scripts or open dialogs.

Type Behavior When to Use
button No default behavior JavaScript actions, dialogs, toggles
submit Submits the form it belongs to. The default when type is missing or invalid Form submission
reset Resets form fields to initial values Clear form data

<input type="submit">, <input type="button"> and <input type="reset"> get the same styling and variant classes as <button>. Prefer <button>, which can hold icons and markup.

Attributes

Attribute Purpose
form Associates the button with a form by id, so it can sit outside the <form> element
formaction, formmethod, formenctype, formtarget Override the form's action, method, enctype and target for this submit button only
formnovalidate Skip constraint validation when this button submits (e.g. "Save draft")
name, value Sent with the form data when this button submits it, so the server knows which button was used. With command="close" on a dialog, value becomes the dialog's returnValue
popovertarget, popovertargetaction Toggle, show or hide a [popover] element by id (toggle is the default action)
commandfor, command Invoker commands: run command on the element named by commandfor. Built-in values: show-modal, close, request-close (dialogs) and toggle-popover, show-popover, hide-popover (popovers). Custom commands start with -- (e.g. --rotate) and fire a command event on the target for your script to handle
disabled Not focusable and not clickable. See aria-disabled for a focusable alternative

Buttons with Icons

Buttons can include icons using the icon-wc component. The button's inline-flex layout with gap: var(--size-xs) automatically handles alignment.

For icon-only buttons, always include aria-label to provide an accessible name. An icon-only button (an <icon-wc> as its only child, plus aria-label, aria-labelledby or title) gets equal padding on all sides so it renders square.

Dialog Triggering

Buttons can open and close dialogs declaratively using the Invokers API. Point commandfor at the dialog's id and set command to show-modal or close. No JavaScript required.

Buttons in Forms

Buttons work seamlessly within form elements. Group actions in a <footer class="actions end"> to right-align them. For enhanced form fields, see the form-field custom element.

Loading State

Add data-loading to show a spinner, set aria-busy and block double submits while an action runs. Without JavaScript the button behaves normally.

aria-disabled

The disabled attribute removes a button from the tab order, so keyboard and screen reader users may never learn it exists or why it is unavailable. aria-disabled="true" keeps the button focusable and announced as disabled; Vanilla Breeze styles it exactly like :disabled and turns off its hover and active states.

aria-disabled does not stop clicks. Your script must ignore activation while it is set.

aria-pressed (Toggle Buttons)

A button with aria-pressed is a toggle. When aria-pressed="true", a primary button shows its active shade with an inset shadow, and secondary and ghost buttons fill with --btn-color. Toggle the attribute from your script; the label should stay the same in both states.

Button-Styled Links

Need a link that looks like a button? Use class="button" on an <a> element. All variants and sizes apply: .secondary, .ghost, .small, .large, .full-width.

Accessibility

  • Always include text: Buttons should have visible text. For icon-only buttons, add aria-label
  • Use native buttons: Avoid <div onclick> patterns. Native buttons are keyboard accessible by default
  • Visible focus: The :focus-visible outline is essential for keyboard navigation. Do not remove it. Its width and offset follow --focus-ring-width and --focus-ring-offset, which grow under prefers-contrast: more
  • Disabled state: Disabled buttons are not focusable. Use aria-disabled="true" or keep buttons enabled with validation messages instead
  • Forced colors: In Windows High Contrast every variant keeps a system-coloured border, disabled buttons use GrayText and pressed buttons use the selection colours
  • Touch: Hover styles only apply on devices that can hover, so they do not stick after a tap
  • Minimum touch target: Buttons enforce a minimum size of var(--size-touch-min) (44x44px) for touch accessibility

CSS Reference

The full stylesheet is src/native-elements/button/styles.css. The rules apply to button, .button and input[type="submit" | "button" | "reset"]. Customise buttons through the custom properties rather than overriding these rules.

button, .button, input:where([type="submit" i], [type="button" i], [type="reset" i]) { --_color: var(--btn-color, var(--color-interactive)); --_text: var(--color-text-on-primary, white); /* contrast-color(var(--_color)) where supported */ display: inline-flex; align-items: center; justify-content: center; gap: var(--size-xs); padding-block: var(--btn-padding-block, var(--size-s)); padding-inline: var(--btn-padding-inline, var(--size-m)); min-block-size: var(--size-touch-min); min-inline-size: var(--size-touch-min); background: var(--_color); color: var(--_text); border: var(--border-width-thin) solid transparent; border-radius: var(--radius-m); font-weight: var(--btn-font-weight, 500); @media (hover: hover) { &:hover:where(:not(:disabled, [aria-disabled="true"])) { background: var(--_hover); } } &:active:where(:not(:disabled, [aria-disabled="true"])) { background: var(--_active); } &[aria-pressed="true"] { background: var(--_active); box-shadow: var(--shadow-inner); } &:focus-visible { outline: var(--focus-ring-width) solid var(--_color); outline-offset: var(--focus-ring-offset); } &:is(:disabled, [aria-disabled="true"]) { opacity: 0.5; cursor: not-allowed; } &.secondary { background: transparent; color: var(--_color); border-color: currentColor; } &.ghost { background: transparent; color: var(--color-text); } &.small { padding-block: var(--size-xs); padding-inline: var(--size-s); font-size: var(--font-size-s); } &.large { padding-block: var(--size-m); padding-inline: var(--size-l); font-size: var(--font-size-l); } &.full-width { inline-size: 100%; } } @media (forced-colors: active) { button, .button { border-color: ButtonBorder; } button:disabled { color: GrayText; border-color: GrayText; opacity: 1; } }
