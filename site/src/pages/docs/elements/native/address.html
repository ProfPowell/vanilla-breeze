Usage

Use the <address> element to provide contact information for:

  • The author of an article (when inside <article>)
  • The owner/maintainer of the document (when in body or <footer>)
  • Business contact information in site footers

Note: The address element is for contact info related to the document or article, not for arbitrary postal addresses in content.

Examples

Default

Base styling removes italic font-style and displays as a block.

hello@example.com
+1 (555) 123-4567

.card

Card-style with padding and raised background.

Acme Corporation
123 Business Street
San Francisco, CA 94102
contact@acme.com

.inline

Inline display so the address runs on within surrounding text. <address> is flow content, so it cannot sit inside a <p> (the parser closes the paragraph before it). Use it in a container that accepts flow content and loose text, such as an article <footer> or an <li>.

Notes on Typesetting

Hand-set type rewards patience more than speed.

Written by Jane Doe, who can be reached at
jane@example.com
.

.compact

Single-line compact layout with flexbox. Separators between items are generated by CSS, so the markup contains only the contact items themselves.

hello@example.com +1 (555) 123-4567 San Francisco, CA

.footer

Styled for footer placement with muted text.

Vanilla Breeze - A layered HTML component system

support@example.com

.contact

Grid layout for contact cards. Each link is a flex row, so a leading <icon-wc> lines up with its text; the icon also replaces the auto-detected mail/phone/external glyph.

hello@example.com +1 (555) 123-4567 example.com

Variants

Class Description
.card Adds padding, raised background, and rounded corners
.inline Displays inline for use within text flow
.compact Flexbox single-line layout with smaller font and CSS-generated separators between items
.footer Smaller, muted styling for footer placement
.contact Grid layout for structured contact information

Accessibility

  • <address> has no special screen reader announcement: it maps to a generic group, not a landmark, so its contents are read as ordinary text. Give it context with a visible heading or label (for example, "Contact us") rather than relying on the element alone
  • Use meaningful link text for contact methods (e.g., email addresses, not "click here")
  • Include proper href protocols: mailto: for email, tel: for phone
  • The .compact separators are generated content with empty alternative text, so they are not read out

Related
