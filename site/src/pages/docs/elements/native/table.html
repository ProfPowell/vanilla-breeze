Description

The <table> element displays tabular data arranged in rows and columns. Vanilla Breeze styles tables with full-width layout (inline-size: 100%), collapsed borders, and font-variant-numeric: tabular-nums so digits align properly in columns. Column header cells get a raised surface background with a medium bottom border; row headers (<th scope="row">) read like data cells so row tints reach them. Body rows include automatic hover states for improved scannability.

Footer rows (<tfoot>) are styled with bold text and a raised background to visually separate summary data from detail rows.

When to Use

  • Data comparison: when users need to compare values across rows or columns
  • Structured records: data with clear header-to-value relationships (reports, statistics, inventories)
  • Schedules and timetables: time slots related to activities or resources

When Not to Use

  • Key-value pairs: use <dl> for definition/description lists
  • Card grids: use <layout-grid> for responsive card layouts
  • Page layout: never use tables for visual layout; use CSS Grid or Flexbox
  • Interactive data grids: for sorting, filtering, and pagination use the <data-table> web component

Basic Usage

A well-structured table includes a <caption> for accessibility, <thead> for column headers with scope attributes, <tbody> for data rows, and optionally a <tfoot> for summary rows. Use data-numeric on cells containing numbers to align them to the inline end (right in left-to-right text, left in right-to-left) and enable tabular numerals.

Variants

Variants are data attributes on the <table> and combine freely. For a low-ink look use data-variant="minimal".
Attribute Effect
data-striped Alternating backgrounds on odd visible body rows (filtered, paged and detail rows are skipped). The stripe is the --color-row-stripe token, a light text-tinted wash distinct from the hover colour, shared with dl[data-striped]. Selected and highlighted rows keep their state tint over the stripe.
data-bordered Full borders on every cell using var(--border-width-thin) and --color-border
data-density compact or comfortable cell padding (below)

Restyle the stripe for every striped table and description list at once by setting the token, for example :root { --color-row-stripe: var(--color-primary-subtle); }. Stripes are kept when printing. In forced-colours mode the system removes them, which is fine: they are a scanning aid, not information.

data-sticky

Keeps the header row, the first column, or both in view while the table scrolls. The header pins below a coordinated sticky site header (it offsets by --sticky-offset); inside a scroll region it pins to the region instead. Frozen cells are opaque but repeat the row's hover, stripe or state tint, and the frozen edge flips side in right-to-left text. (Page-level sticky headers, footers and sidebars use a different data-sticky.)

data-sticky-column="2"

Freezes the first two columns (for example an ID and a name). The second column is offset by the first column's width, which you set with --_sticky-col-1-width (default 8rem) in your stylesheet. This switches the table to border-collapse: separate so the frozen cells keep their borders while scrolling.

Scroll region: data-table-scroll

Wide tables scroll inside a wrapper, not on the table itself. Make the wrapper a focusable, named region so keyboard users can scroll it with the arrow keys and screen reader users hear what it holds: a <section> with data-table-scroll, tabindex="0", and aria-labelledby pointing at the table's caption. (A named <section> is a region; on another element add role="region".)

Because the wrapper is the scroll container, a sticky header pins to the wrapper, not the page. Use data-table-scroll="block" to cap the wrapper's height (--table-scroll-max-block, default 70dvh) so the header has something to stick within. In print the wrapper expands and every column prints.

data-responsive="card"

When the table's container is narrower than 500px, each body and footer row becomes a card and each cell shows its column name as a label. The header row is hidden visually but stays in the accessibility tree, and VB's card script restores explicit table roles (changing the display of rows and cells drops them in some browsers) and fills any missing data-label from the column header text. Set data-label on a cell only to override that label. The container can be a <data-table> or any element with container-type: inline-size (VB sections and articles have it).

Not to be confused with img[data-responsive], the responsive-image helper that shares the attribute name.

data-variant="minimal"

A low-ink table: no header band, no hover, thin rules between rows, and small uppercase muted column headers. Useful for dense numeric reports where the data should carry the page.

data-align

Set on individual <th> and <td> cells: start, center or end. Logical values, so end is the left edge in right-to-left text. Put it on the cells, not on <col>: CSS ignores text alignment on table columns.

data-numeric

Applied to individual <th> and <td> cells to align content to the inline end (right in LTR, left in RTL) and enforce font-variant-numeric: tabular-nums for proper digit alignment.

data-sort

Marks a sortable column, but on its own it does nothing: sorting comes from <data-table> or the data-sortable attribute. Both keep the <th> as a column header with aria-sort and wrap its text in a real <button>; VB styles that button and draws the ⇅ / ↑ / ↓ glyph. Note the attribute's value means different things to the two (sort type vs column key); see th: Sortable Headers.

Row States

Data attributes on <tr> elements control visual row states without JavaScript class toggling. They are visual only: say the state in the row too (text or a checkbox), and add inert to a disabled row.

Attribute Effect
data-selected (data-state-selected from <data-table>) Interactive tint at 15% plus an inline-start bar; Highlight in forced colors
data-highlight Warning tint at 15% plus an inline-start bar; Mark in forced colors
data-disabled Muted text colour (AA-safe, no opacity). Pair with inert

CSS Reference

The full stylesheet is src/native-elements/table/styles.css. All values use design tokens, so tables adapt to any theme. The hooks worth knowing when you override it:

/* Row paint: set --_row-bg on a tr instead of background, so frozen (sticky) cells repeat the tint */ tr { background: var(--_row-bg); } tbody tr:hover { --_row-bg: var(--color-hover-bg); } /* State bar on the first cell (flips in RTL via --_x) */ tr > :first-child { box-shadow: var(--_row-bar), var(--_edge, 0 0 #0000); } /* Sticky header clears the coordinated site header */ table:is([data-sticky="header"], [data-sticky="both"]) thead th { inset-block-start: var(--sticky-offset, 0px); } /* Second frozen column offset */ table[data-sticky-column="2"] { --_sticky-col-1-width: 8rem; } /* Scroll region height cap */ [data-table-scroll="block"] { max-block-size: var(--table-scroll-max-block, 70dvh); }

Accessibility

  • Always include a <caption>: provides context for screen reader users navigating to the table
  • Use <th> with scope: define whether headers apply to columns (scope="col") or rows (scope="row")
  • Structure with <thead>, <tbody>, <tfoot>: helps assistive technologies understand table regions
  • Empty cells are fine: screen readers announce them as "blank". Avoid a bare "-", which is read as "dash" or skipped; for a visible mark use an em dash with visually hidden "No data"
  • Scrolling tables: wrap them in a focusable, named [data-table-scroll] region so keyboard users can scroll
  • Card mode keeps semantics: data-responsive="card" hides the header row visually only and restores table roles
  • Row states aren't colour-only: selected and highlighted rows add an edge bar and switch to system colours in forced-colors mode
  • Keep tables simple: avoid complex merged cells when possible; use scope="colgroup" for multi-level headers
