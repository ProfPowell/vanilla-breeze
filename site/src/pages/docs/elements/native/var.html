Description

The <var> element represents a variable in a mathematical expression or programming context. VB styles it in italic, the mathematical convention, in the surrounding text colour. It deliberately does not use the link colour: where links are not underlined (navigation, cards, a.plain) a coloured variable looked clickable. A theme can tint variables with the --var-color custom property. Unlike the rest of the code family it keeps the body font (no monospace). Add the HTML translate="no" attribute when a variable name must survive browser translation (see Internationalization).

When to Use

  • Mathematical variables: x, y, n in equations (not constants such as π or e)
  • Programming variables: Variable names referenced in prose
  • Placeholders: User-supplied values in instructions (e.g., your-api-key)

When NOT to Use

  • For emphasis — use <em>
  • For code identifiers (function names, classes) — use <code>
  • For keyboard input — use <kbd>
  • For program output — use <samp>

var vs em vs code

<var> and <em> share the italic, so they look alike unless a theme sets --var-color. The difference is semantic: a variable is a name for a value, emphasis changes how a sentence is read. <code> renders distinctly:

Element Rendering Use Case
<var> Italic, text colour (or --var-color) Variables, placeholders
<em> Italic only Stress emphasis
<code> Monospace + background Code identifiers, inline code

CSS Reference

var { font-style: italic; font-synthesis: weight style; color: var(--var-color, currentColor); } /* Chinese, Japanese, Korean: no synthesised slant */ var:is(:lang(zh), :lang(ja), :lang(ko)):not(:lang(zh-Latn), :lang(ja-Latn), :lang(ko-Latn)) { font-style: normal; text-decoration: underline dashed var(--color-text-muted); text-underline-position: under; text-decoration-thickness: from-font; }
Custom property Default Effect
--var-color currentColor Text colour of every <var>. If you set it, check it reaches 4.5:1 contrast and is not your link colour.

Italic on single-face fonts: font-synthesis: weight style keeps a synthesised slant when the theme font ships no italic face, the same as <em> and <i>. A real italic face always wins when the font has one.

CJK text: most Chinese, Japanese and Korean fonts have no italic, and the browser would slant the glyphs artificially. In lang="zh", ja or ko text <var> stays upright and takes a dashed underline instead. That line differs from the CJK cues on <u> (solid), <i> (dotted) and <cite> (wavy). Romanised tags such as zh-Latn keep the italic.

To stop browser translation from mangling variable names, put translate="no" on the element (or an ancestor) in your HTML: <var translate="no">maxRetries</var>.

Accessibility

  • Screen readers announce <var> as plain text — the italic is not conveyed
  • The italic is a visual cue only — context should make the variable clear
  • VB keeps variables out of the link colour, so they are never mistaken for links
  • For complex math where variables are critical, consider MathML or aria-label
