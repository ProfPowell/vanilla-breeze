Description

The <search> element is a semantic landmark that identifies content related to searching or filtering. It's the recommended way to mark up search functionality, replacing the older pattern of <form role="search">.

As a landmark element, <search> allows screen reader users to quickly navigate to search functionality using landmark navigation.

When to Use

  • Site-wide search: Main search functionality in headers
  • Page search: Search within specific content (tables, lists)
  • Filter controls: Filter interfaces that narrow displayed content
  • Search results pages: Wrap the search input on results pages

When Not to Use

  • For login forms - use <form> with appropriate labels
  • For general data input - use standard form elements

Variants

Every variant styles the input and button as children of <search> or of its direct <form> child (:is(search, search > form) > input). Use the form version whenever there is a submit button: a <button type="submit"> does nothing without a form.

.inline

Search input with button side-by-side using flexbox.

.compact

Smaller search for headers or sidebars.

.rounded

Pill-shaped search input.

.expanded

Full-width search input.

.header

Constrained width for header placement.

.with-icon

A decorative icon positioned at the inline start of the input. The icon is a sibling placed before the input (svg, .icon or <icon-wc>), and the input gets extra start padding. Combine with .rounded for a pill field.

Styling

Each variant matches controls that are direct children of <search> or of its direct <form>. Abridged from src/native-elements/search/styles.css:

search { display: block; } /* Inline variant: the search, or its form, lays out in a row */ search.inline { &, & > form { display: flex; gap: var(--size-xs); } & > form { flex: 1; } & > input, & > form > input { flex: 1; } } /* Expanded variant */ search.expanded { inline-size: 100%; & > input, & > form > input { inline-size: 100%; } } /* Compact variant */ search.compact { &, & > form { display: flex; gap: var(--size-2xs); } & > input, & > form > input { padding-block: var(--size-xs); font-size: var(--font-size-s); } & > button, & > form > button { padding-block: var(--size-xs); padding-inline: var(--size-s); font-size: var(--font-size-s); } } /* With icon: icon sits over the input's inline-start padding */ search.with-icon { position: relative; & > form { position: relative; } & > input, & > form > input { padding-inline-start: var(--size-xl); } & > :is(svg, .icon, icon-wc), & > form > :is(svg, .icon, icon-wc) { position: absolute; inset-inline-start: var(--size-s); inset-block-start: 50%; transform: translateY(-50%); pointer-events: none; } } /* Rounded variant */ search.rounded { & > input, & > form > input { border-radius: var(--radius-full); padding-inline-end: var(--size-m); } &:not(.with-icon) > input, &:not(.with-icon) > form > input { padding-inline-start: var(--size-m); } } /* Header variant */ search.header { max-inline-size: 300px; }

Form Patterns

GET Form for Server Search

Use GET method so search queries appear in the URL and can be bookmarked/shared.

Client-Side Filtering

For client-side filtering, omit the form and handle input events directly.

Accessibility

Landmark Navigation

The <search> element is a landmark, meaning screen reader users can jump directly to it using landmark navigation. This replaces the older pattern of <form role="search">.

Labeling

Always provide a label for the search input. Options include:

  • Visible <label> element
  • Visually hidden <label> using .visually-hidden
  • aria-label attribute on the input

input[type="search"] vs input[type="text"]

Always use type="search" for search inputs. It provides:

  • Clear button in some browsers
  • Appropriate keyboard on mobile (search button instead of enter)
  • Semantic meaning for assistive technologies
  • Search-specific styling opportunities

Keyboard Support

Key Action
Enter Submit the search form (when in form context)
Escape Clear the search input (browser-dependent)

Site Search Component

<site-search> builds a full search experience (dialog, keyboard shortcut, results) on top of this element. For its no-JavaScript fallback, use a plain <search><form action="/search" method="get"> that submits to your search page, so the landmark and the form work before the component upgrades (not the older <form role="search">). Use <search> on its own for simple GET forms and filters; use <site-search> when you want the instant-results dialog.

Browser Support

The <search> element is supported in all modern browsers. For older browsers, it degrades gracefully as a generic container while still functioning correctly.
