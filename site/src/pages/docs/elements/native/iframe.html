Description

The <iframe> element embeds another HTML document within the current page. VB removes the default border, makes the frame block-level and never wider than its container, and offers variant classes, a data-ratio attribute for proportional sizing, and ratio wrappers for common embeds.

When to Use

  • Video embeds: YouTube, Vimeo, and other video platforms
  • Maps: OpenStreetMap and other map embeds (or <geo-map> for a tile map you control)
  • Social widgets: Timelines and posts
  • Payment forms: Hosted checkout fields
  • Third-party tools: Calendars, forms, surveys
  • Untrusted HTML: User-supplied markup rendered with sandbox and srcdoc

When to Use Other Elements

  • Use <video> for self-hosted video files
  • Use <audio> for self-hosted audio
  • Use <dialog> for modal content on your own page
  • Use <object> for PDFs that need a download-link fallback

Responsive Sizing with data-ratio

An iframe has no natural aspect ratio, so its width and height attributes don't scale together: on a narrow screen max-inline-size clamps the width and leaves the full height, giving a tall letterbox. Put data-ratio on the iframe itself and the block size follows the used width instead.

  • A width attribute stays the preferred (maximum) width; without one the iframe fills its container.
  • Keep integer width/height as the no-CSS fallback.
  • Values: 1:1, 4:3, 3:2, 16:9 (default), 21:9, 2:3, 3:4, 9:16, and page (1 : 1.414, a portrait document page). The same vocabulary works on <embed> and <object>.

The data-media wrapper

When an embed needs a caption, rounded corners, or a wrapper you can lay out, use a [data-media] ratio box. Its child iframe fills the box. On a <figure> with a <figcaption>, the ratio moves to the iframe and the caption flows below it (see figure).

Legacy .embed-responsive wrapper

The .embed-responsive class works the same way as [data-media] and accepts ratio modifier classes. Prefer data-ratio for new markup.

The allow attribute (Permissions Policy)

allow takes a semicolon-separated list of features the framed document may use. Each feature defaults to the frame's own origin (src); add an origin list or * to widen it.

Use allow="fullscreen" rather than the legacy allowfullscreen attribute. Both work today; allowfullscreen is the older boolean form (equivalent to allow="fullscreen *"), and when allow also names fullscreen the allow value takes precedence. Keep to one vocabulary.

Security

The sandbox Attribute

Restricts iframe capabilities. Start with an empty value (most restrictive) and add tokens only as needed.

Never combine allow-scripts and allow-same-origin for content from your own origin. A same-origin document that may run scripts can reach into its parent, remove the sandbox attribute from its own iframe and reload itself unsandboxed: the sandbox is no protection at all. The pair is only meaningful for a cross-origin src, where the same-origin policy still separates the frame from your page. For untrusted HTML, use srcdoc or a separate origin with sandbox="allow-scripts" alone.

Content Security Policy

List exactly the origins you embed. The privacy-enhanced YouTube host is www.youtube-nocookie.com, not www.youtube.com.

Content-Security-Policy: frame-src 'self' https://www.youtube-nocookie.com https://player.vimeo.com;

To control who may frame your pages, send Content-Security-Policy: frame-ancestors from the embedded site; it can't be set from a meta tag.

Performance

Lazy Loading

Defer loading of below-the-fold iframes. Third-party embeds often pull in megabytes of script, so this is one of the cheapest wins on a page. Don't lazy-load an embed that is visible on first paint.

Give lazy iframes a size (width/height or data-ratio) so the space is reserved and nothing shifts when they load.

Printing

Browsers print only the visible part of an iframe, cropped to its box; scrolled-away content and video are lost. If the embedded content matters on paper, follow the frame with a link or summary that prints instead.

See Printing for how VB prints embedded media.

Accessibility

Title Attribute

Every iframe must have a title attribute that describes its content for screen readers.

Best Practices

  • Always provide a descriptive title attribute
  • Ensure embedded content is itself accessible; you can't fix it from the parent page
  • Provide alternative content (a link, transcript or summary) for critical information
  • Consider that some users block third-party content
  • Don't put tabindex="-1" on an interactive embed; keyboard users need to reach its controls
