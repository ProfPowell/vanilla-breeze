Description

The <dialog> element provides a native way to create modal dialogs, confirmation prompts, and slide-in drawer panels. It handles complex accessibility requirements automatically: focus trapping, ESC to close, role="dialog", and inert background.

There are two ways to open a dialog:

  • HTML Invokers API (recommended) — command="show-modal" / command="close"
  • JavaScript — showModal() / show() / close()

In Vanilla Breeze, dialogs also serve as drawer panels via data-position, and are used internally by web components like <command-palette>, <short-cuts>, and <settings-panel>.

When to Use

  • Confirmation dialogs: Confirm destructive actions before proceeding
  • Form dialogs: Collect user input in an overlay
  • Alert messages: Important information requiring acknowledgment
  • Media lightboxes: Images or videos in a focused overlay
  • Drawer panels: Slide-in navigation, settings, or filters (via data-position)

When Not to Use

  • For inline expandable content — use <details>
  • For tooltips or popovers — use <tool-tip>
  • For toast notifications — use <toast-msg>
  • For dropdown menus — use <drop-down> or <context-menu>
  • For non-blocking information — avoid interrupting user flow

Invokers API (Declarative)

The Invokers API lets you open and close dialogs with HTML attributes alone — no JavaScript required.

Browser Support

The command / commandfor attributes ship in Chrome and Edge 135+, Firefox 144+ and Safari 26.2+, so no polyfill is needed. In older browsers the buttons do nothing; if you must support them, open the dialog from a click handler (dialog.showModal()) instead.

Variants

Basic dialog, confirmation prompt, and form dialog all use the same structure with different content.

Form method="dialog"

Forms inside dialogs can use method="dialog" to close the dialog on submit, passing the submit button's value as dialog.returnValue.

The form can wrap the whole dialog — header, body and footer. VB styles dialog > form > header and dialog > form > footer exactly like their direct-child counterparts: the form itself gets no padding, the footer border spans the full width, and the body between them scrolls when it is long. A form that contains only fields (no header or footer) is treated as a padded body instead.

Drawer Variants

Use data-position to turn any dialog into a slide-in drawer panel. No additional JavaScript required — drawers inherit all dialog features: Invokers API, ESC to close, focus trapping, backdrop.

Bottom Sheet

The bottom drawer variant (data-position="bottom") acts as a mobile-native bottom sheet — ideal for action menus, share sheets, and quick option lists. It automatically includes safe-area padding for devices with home indicators.

Dialog Structure

For consistent styling, use <header>, one body element, and <footer>. An open dialog is a flex column: the header and footer keep their size and the body (<p>, <section>, <article> or <form>) scrolls when the content is taller than the dialog's max-block-size (85dvh). Put long content in a single <section> so it scrolls as one region; the actions in the footer stay visible, and the top of the body stays reachable even when a footer button has autofocus.

Structural CSS

dialog { inline-size: min(90vw, 32rem); max-inline-size: min(90vw, 32rem); max-block-size: 85dvh; padding: 0; /* transparent border: shows as CanvasText in forced-colors mode */ border: var(--border-width-thin) solid transparent; border-radius: var(--radius-l); background: var(--color-surface-overlay); color: var(--color-text); box-shadow: var(--shadow-xl); overflow-y: auto; /* fallback only — the body normally scrolls */ overscroll-behavior: contain; } dialog[open] { display: flex; flex-direction: column; } dialog > header, dialog > form > header { flex-shrink: 0; padding: var(--size-m) var(--size-l); border-block-end: var(--border-width-thin) solid var(--color-border); } /* The body: padded, shrinks and scrolls */ dialog > :is(p, section, article, form), dialog > form:has(> header, > footer) > :not(header, footer) { padding: var(--size-l); min-block-size: 0; overflow-y: auto; } /* A form wrapping header/body/footer becomes the column itself */ dialog > form:has(> header, > footer) { display: flex; flex-direction: column; min-block-size: 0; padding: 0; } dialog > footer, dialog > form > footer { flex-shrink: 0; padding: var(--size-m) var(--size-l); border-block-start: var(--border-width-thin) solid var(--color-border); display: flex; flex-wrap: wrap; gap: var(--size-s); justify-content: flex-end; } /* Background scroll lock while a modal is open */ html:has(dialog:modal) { overflow: hidden; }

Background Scroll Lock

While a modal dialog is open, VB sets overflow: hidden on <html> via html:has(dialog:modal), so the page behind the backdrop does not scroll. Non-modal dialogs opened with show() leave scrolling alone. With classic (non-overlay) scrollbars the page can shift by the scrollbar's width when the lock applies; add html { scrollbar-gutter: stable; } to your site styles to prevent that.

Backdrop Styling

The ::backdrop pseudo-element styles the overlay behind modal dialogs. VB defaults to a semi-transparent dark background with a subtle blur, both controlled by tokens so themes can change them.

dialog::backdrop { background: var(--color-backdrop); /* default oklch(0% 0 0 / 0.5) */ backdrop-filter: blur(var(--backdrop-blur)); /* default 2px */ }

Animation

Dialogs animate both in and out with CSS transitions. The transition is declared on dialog itself (not only dialog[open]), so on close display and overlay are held with allow-discrete until the exit finishes; @starting-style supplies the entry starting point. Each variant sets its hidden transform through one custom property: modals scale, drawers slide from their edge. Under prefers-reduced-motion the movement is dropped and only a fade remains; the theme picker's reduced-motion toggle removes the fade too.

dialog { --_dialog-hidden: scale(0.95); opacity: 0; transform: var(--_dialog-hidden); transition: opacity var(--motion-exit-duration) var(--ease-in), transform var(--motion-exit-duration) var(--ease-in), display var(--motion-exit-duration) allow-discrete, overlay var(--motion-exit-duration) allow-discrete; } dialog[open] { opacity: 1; transform: none; transition-duration: var(--motion-enter-duration); transition-timing-function: var(--ease-out); } @starting-style { dialog[open] { opacity: 0; transform: var(--_dialog-hidden); } } @media (prefers-reduced-motion: reduce) { dialog { --_dialog-hidden: none; } /* fade only */ }

Drawer Animations

/* Drawers reuse the same transition with a directional transform */ dialog[data-position="end"] { --_dialog-hidden: translateX(100%); } dialog[data-position="end"]:dir(rtl) { --_dialog-hidden: translateX(-100%); } dialog[data-position="start"] { --_dialog-hidden: translateX(-100%); } dialog[data-position="start"]:dir(rtl) { --_dialog-hidden: translateX(100%); } dialog[data-position="bottom"] { --_dialog-hidden: translateY(100%); } dialog[data-position="top"] { --_dialog-hidden: translateY(-100%); }

Backdrop Click to Close

By default a modal dialog does not close when the backdrop is clicked. The native closedby attribute controls this declaratively:

  • closedby="any" — closes on backdrop click (light dismiss), Escape, or a close command
  • closedby="closerequest" — Escape or a close command only (the default for modals)
  • closedby="none" — only an explicit close command or close()

Details

Click outside to dismiss.

closedby ships in Chrome and Edge 134+ and Firefox 141+, but not yet in a released Safari. Until it does, add a small feature-detected fallback:

// Only needed where closedby is unsupported (Safari at the time of writing) if (!('closedBy' in HTMLDialogElement.prototype)) { document.addEventListener('click', (e) => { const dialog = e.target; if (dialog instanceof HTMLDialogElement && dialog.getAttribute('closedby') === 'any') { dialog.close(); // a click on the dialog box itself, not its content } }); }

The check works because a click on the backdrop targets the <dialog> element itself, while a click on its content targets a child. VB dialogs have no padding and their header, body and footer fill the box, so content clicks never land on the dialog element.

Accessibility

Native Features

The <dialog> element provides these accessibility features automatically:

  • Focus trapping: Tab key cycles through focusable elements inside the dialog
  • Focus restoration: Focus returns to the triggering element when closed
  • Inert background: Background content is non-interactive when modal is open
  • ESC to close: Standard keyboard dismissal (can be prevented via cancel event)
  • ARIA semantics: Automatically has role="dialog"

Best Practices

  • Include a visible close button
  • Give every dialog an accessible name: put an id on its heading and point aria-labelledby at it (<dialog aria-labelledby="dlg-title">). Use aria-label only when there is no visible heading. Screen readers announce this name when the dialog opens
  • A <dialog> does not scope <header> and <footer>, so (per HTML-AAM) they can map to banner/contentinfo landmarks. When a page has several dialogs, keep those landmarks distinguishable without inventing labels: name the header by its own heading (<header aria-labelledby="dlg-title">) and give the footer a short purpose label (aria-label="Delete item actions"). Avoid labels that just restate the element, such as "… heading"
  • Keep long content in a single body element so it scrolls with the header and actions still in view
  • Keep dialogs focused — don't include unrelated content
  • Provide keyboard alternatives for all actions
  • Avoid nesting dialogs inside dialogs

Keyboard Support

Key Action
Tab Move focus between focusable elements (trapped inside modal)
Shift + Tab Move focus backwards (trapped inside modal)
Escape Close the modal dialog

Print Behavior

Dialogs are hidden entirely in print stylesheets — they are transient UI and should not appear on paper.

/* Print: dialogs are hidden entirely */ @media print { dialog { display: none; } }

Browser Support

The <dialog> element is supported in all modern browsers.

  • Invokers API (command/commandfor): Chrome and Edge 135+, Firefox 144+, Safari 26.2+.
  • closedby: Chrome and Edge 134+, Firefox 141+; not yet in a released Safari (see the fallback above).
  • @starting-style and transition-behavior: allow-discrete: all current engines. Older browsers open and close the dialog without animation.
  • backdrop-filter: All modern browsers. The blur effect on the backdrop degrades gracefully.
