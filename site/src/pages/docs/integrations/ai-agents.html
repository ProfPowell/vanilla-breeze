AI Agents

Documentation written for a coding agent to read before it writes Vanilla Breeze markup, and vb-check, a command that tells it (or you) what it got wrong.

What is published

Every file is generated at build time from the component manifests that also produce the attribute tables in these docs, so the two cannot disagree. Each file carries the version it was built from.
File Contents
/llms.txt How to load Vanilla Breeze, the rules for writing markup, and one line per pattern, layout and component linking to its file.
/cdn/llms/components/<tag>.md One component: an example, its attributes and allowed values, child structure, events, methods, properties and keyboard behaviour. For example tab-set.md.
/cdn/llms/patterns/<name>.md One page pattern from the patterns section: the markup, and the small CSS where a pattern needs it, for a site header, hero, pricing table, contact form, footer and so on. For example navigation-navbar.md.
/cdn/llms/themes.md Every theme and accent with a one-line character, how to load one, and the design tokens to use in your own rules.
/cdn/llms/attributes.md Attributes that work on any element, grouped by purpose, each linking to its page here.
/cdn/llms/native-elements.md Native elements with a dedicated page.
/llms-full.txt All of the above in one file, for tools that take a single document.

Use the copy that matches your version

The files on this site describe the latest release. An agent working in a project should read the files for the version that project has installed, which ship inside the npm package.

 node_modules/vanilla-breeze/dist/cdn/llms/llms.txt node_modules/vanilla-breeze/dist/cdn/llms/llms-full.txt node_modules/vanilla-breeze/dist/cdn/llms/components/tab-set.md

The package exports them as vanilla-breeze/llms.txt, vanilla-breeze/llms-full.txt and vanilla-breeze/llms/*. Links inside the packaged files are relative, so they work offline.

A page that loads Vanilla Breeze from a CDN has no node_modules. Use the same path under the version you load:

 https://unpkg.com/vanilla-breeze@VERSION/dist/cdn/llms/llms.txt

vb-check

vb-check validates HTML against the same component manifests: every element, attribute and allowed value, plus the conventions a manifest cannot express. It needs no configuration file. It ships with the package and uses html-validate, an optional peer dependency you install beside it.

 npm install vanilla-breeze npm install --save-dev html-validate npx vb-check page.html npx vb-check src/ --quiet # a directory, errors only npx vb-check page.html --json page.html:5:4 error

The exit code is 1 when there are errors, 0 otherwise; warnings alone do not fail. A file that contains <html> is also checked as a whole document (language, title, landmarks).
Rule Level Reports
no-unknown-elements Error A custom element that Vanilla Breeze does not define.
attribute-allowed-values Error A value an attribute does not accept, on components and on data-layout attributes anywhere.
vb/layout-attribute Error A data-layout-* attribute that no layout defines.
vb/no-div Error A <div>, with the semantic element or layout to use. The group <div> inside <dl> is allowed.
vb/no-inline-style Error A style attribute, unless it only sets a documented layout custom property such as --layout-min.
vb/icon-wc-required Error An inline <svg> with neither role="img" nor aria-hidden="true".
vb/known-data-attribute Warning A data-* attribute on a Vanilla Breeze element that nothing in Vanilla Breeze reads.
vb/no-class-for-state Warning A state word used as a class, such as class="active".
vb/use-form-field Warning A form control with validation outside <form-field>.

Heading order, permitted content and the rest of html-validate's recommended rules run too. If you already use html-validate, load the same rules from your own configuration:

 { "plugins": ["vanilla-breeze/html-validate"], "extends": ["html-validate:recommended", "vanilla-breeze:recommended"] }

The agent skill

The package also ships a skill in the Agent Skills format, at skills/vanilla-breeze/SKILL.md. It is a procedure, not a reference: read the installed documentation, start from the page patterns, write the native HTML first, add layout, components and a theme, run vb-check and fix what it reports, look at the rendered page, then check it without JavaScript.

Install it into a project with the skills command, which supports Claude Code, Codex, Cursor and other agents:

 npx skills add ProfPowell/vanilla-breeze --skill vanilla-breeze

Or copy node_modules/vanilla-breeze/skills/vanilla-breeze/ into your agent's skills directory, which keeps the skill at the version you have installed.

Prompting an agent

Without the skill, point the agent at the index and tell it to read the component files it needs before writing anything. The index tells it not to invent tags, attributes or values.

 Build this page with Vanilla Breeze. First read node_modules/vanilla-breeze/dist/cdn/llms/llms.txt and follow its rules, then read the component file for each component you use. When you are done, run npx vb-check on the files you wrote and fix what it reports.
