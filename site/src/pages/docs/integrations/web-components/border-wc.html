border-wc

<border-wc> draws one of 34 decorative border effects around its content, using SVG, canvas or layered CSS that a plain border cannot produce. It names no Vanilla Breeze tokens itself: it uses the text color and corner radius it inherits, and you pass theme tokens in through its custom properties.

Install

From a CDN. The package has no stylesheet to load. Each effect is a separate file that the element fetches the first time it is used.

To apply effects with a data-border-effect attribute and no wrapper element, load the binder instead.

Or with npm:

npm install @profpowell/border-wc import '@profpowell/border-wc'; // Optional: the data-border-effect attribute binder import '@profpowell/border-wc/attr';

Both entry points do nothing when imported on a server, so a framework that renders on the server can bundle them.

Attribute binder

The binder applies the same 34 effects to any element that carries data-border-effect, and watches the page for elements that are added, changed or removed. The attribute may hold several space-separated values; the binder uses the first one it knows and ignores the rest. Options come from the --border-wc-* custom properties.

The module also exports bindBorderEffects(root), which scans a subtree on demand, and stopWatching(), which stops the binder from reacting to later page changes.

With Vanilla Breeze

border-wc does not name any Vanilla Breeze token. It picks up the theme through three things it reads from the page.

What it readsWhere Vanilla Breeze sets itDrives
The inherited text color (currentColor)--color-text, or whatever color applies to the elementDefault stroke color.
The element's computed border-radiusAny rule you write, for example with --radius-mDefault corner radius of the drawn border.
data-motion-reduced on <html>The Vanilla Breeze motion settingStill borders in place of animated ones.

For color, thickness, speed and radius the element uses the first of these that has a value: the --border-wc-* property, then the attribute, then the built-in default. To follow the theme, point the properties at Vanilla Breeze tokens, for all borders or for one.

border-wc { --border-wc-color: var(--color-primary); border-radius: var(--radius-m); } .featured-card { --border-wc-color: var(--color-accent); --border-wc-thickness: 4; }

The element reads these values when it draws the effect. If a theme switch changes them, call refresh() to redraw.

border-wc or data-border-effect

Vanilla Breeze has its own CSS-only data-border-effect attribute with six values: spin, pulse, march, hue-cycle, breathe and trace. Use those for light, always-on motion that needs no script. Use border-wc when you need an effect that CSS alone cannot draw.

The two share the attribute without conflict. The border-wc binder ignores the six Vanilla Breeze values, and Vanilla Breeze's CSS has no rules for the 34 border-wc names.

Accessibility

  • Reduced motion. With motion="auto", the default, effects draw without animation when the operating system asks for reduced motion, and also when Vanilla Breeze's own setting puts data-motion-reduced on <html>. If either changes while the page is open, the effect is drawn again to match.
  • Overriding. motion="reduce" forces a still border. motion="force" animates regardless of the reader's setting, so keep it for content where the motion is the point.
  • Pointer and keyboard. The drawn layer ignores pointer events and takes no focus. Links and controls inside the element work as usual.
