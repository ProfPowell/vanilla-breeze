browser-window

A web component that draws a browser window, or a phone or tablet, around a demo page or any HTML you put inside it. The Vanilla Breeze stylesheet sets the frame's colors, fonts and corner radius from the active theme.

At a glance

Package@profpowell/browser-window, version 1.4.9
Elements<browser-window>
Renders inShadow DOM. Content you place inside stays in the light DOM and is slotted into the frame. A page named by src loads in an iframe.
Sourcegithub.com/ProfPowell/browser-window, based on @zachleat/browser-window
Documentationprofpowell.github.io/browser-window
LicenceMIT
In Vanilla BreezeNot bundled. Vanilla Breeze lists it as a development dependency and imports it only in src/doc-extras.js, a bundle built for this docs site and left out of the npm package. You load the component yourself. The VB stylesheet does include the rules that theme it.

Install

Load the component from a CDN. It is one file with no stylesheet.

Or install it from npm and import it in your own script.

npm install @profpowell/browser-window import '@profpowell/browser-window';

Demo

Two windows on a Vanilla Breeze page: one around inline content, one loading another page. The frame you are looking at is itself a <browser-window>.

Usage

Load a page into the frame with src. This also adds a view-source button, a download link and a share menu with a CodePen export.

Or put content between the tags. The url attribute only sets the text in the address bar.

Set device to draw a phone or tablet instead of a browser window.

The window can be resized by dragging its bottom-right corner. Set a starting size in CSS.

browser-window { inline-size: 40rem; block-size: 25rem; }

With Vanilla Breeze

A token is a CSS custom property that holds one design value, such as --color-surface. Two things connect the component to Vanilla Breeze tokens.

First, the component itself reads seven VB tokens as fallbacks.

VB tokenDrives
--color-surfaceWindow background, address bar background and content background
--color-surface-raisedHeader background
--color-borderBorder
--color-textText
--color-text-mutedMuted text, such as the address
--radius-mOuter corner radius
--radius-sRadius of the address bar and buttons

Second, the VB stylesheet contains a token bridge: a rule with the selector browser-window that sets the component's --browser-window-* properties from VB tokens. It ships in vanilla-breeze.css and vanilla-breeze-core.css, so there is no extra file to load and no attribute to add. Besides the tokens above, the bridge sets these.

VB tokenSet on
--color-surface-sunkenAddress bar background
--color-surface-altButton hover background
--color-interactiveAccent color
--color-error, --color-warning, --color-successThe close, minimize and maximize buttons
--font-sans, --font-monoInterface font and the font of the source view

For each color the order is: the --browser-window-* property if it is set, then the VB token, then the component's built-in color. With VB loaded, the bridge is what sets the --browser-window-* properties.

Light or dark is chosen separately. With no mode attribute, the component follows the nearest data-mode on itself or an ancestor, then page-level signals such as data-theme on <html>, then the operating system preference. When the framed page is on the same origin, it sets that page's color-scheme to match.

The bridge sits in a cascade layer, so any rule you write outside a layer wins. To change one window, set the property on it.

browser-window[url*="staging"] { --browser-window-header-bg: var(--color-warning); --browser-window-border-radius: 0; --browser-window-shadow: var(--shadow-m); }

This docs site also styles the element with a data-demo-height attribute. That comes from the site's own stylesheet and is not part of the component.

Accessibility

  • Every control is a button with an ARIA label and a visible focus indicator, and can be reached with the keyboard.
  • A maximized window has role="dialog" and aria-modal. Escape restores it, and also closes the share menu.
  • Animations are turned off when the reader has asked for reduced motion.
  • On touch devices the control buttons get larger touch targets, 44 pixels where there is room.
  • Give the iframe a clear name with iframe-title when the visible title is not enough for screen-reader users.
