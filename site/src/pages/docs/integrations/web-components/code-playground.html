code-playground

A web component with editors for HTML, CSS and JavaScript, a preview that runs the code in a sandboxed iframe, and a console that shows what the code logs. It reads Vanilla Breeze tokens directly, so its toolbar, panels and console match the active theme with no extra CSS.

Install

Load the component from a CDN. The script fetches a second file from the same folder, editor-runtime-B2MdwU5J.js, which holds the CodeMirror editor.

Or install it from npm and import it in your own script.

npm install @profpowell/code-playground import '@profpowell/code-playground';

Until the script has run, the source textareas are ordinary visible form fields. Add this rule to a stylesheet in the <head> to hide them and reserve the space.

code-playground:not(:defined) { display: block; min-block-size: 31rem; } code-playground:not(:defined) > * { display: none; }

Demo

A playground on a Vanilla Breeze page. Edit any tab and the preview runs again. Press the button in the preview, then open the console bar to see the log.

Usage

Give the starting code in textareas, one per slot: html, css, js, and optionally head for extra tags in the preview's <head>. With persist, a reader's edits are saved in their browser under that key.

Or load the starting code from files.

For a short example inside a tutorial, fit-preview makes the preview as tall as its content instead of filling a fixed pane.

By default the playground picks its own height. Set a height on the element and the layout fills it, with the editor scrolling inside.

code-playground { block-size: 70vh; min-block-size: 30rem; }

With Vanilla Breeze

A token is a CSS custom property that holds one design value, such as --color-surface. The component defines each of its own --cp-* properties from a VB token, with a built-in value for pages that do not use Vanilla Breeze.

VB tokenDrives
--color-surfacePlayground background
--color-surface-raisedToolbar and panel backgrounds
--color-surface-sunkenEditor background
--color-backgroundBackground behind the preview
--color-border, --color-border-subtleBorders and dividers
--color-text, --color-text-mutedText and secondary text
--color-interactive, --color-interactive-hoverAccent color, used for the Run button, active controls and the editor selection, and the Run button's hover color
--color-text-on-interactive-auto, then --color-text-on-primaryText on the Run button
--color-focus-ringFocus outline
--color-info-text, --color-warning-text, --color-error-text, --color-success-textConsole colors for log and info, warn, error, and debug entries
--radius-m, --radius-sOuter and inner corner radius
--font-sans, --font-monoInterface font and editor font
--shadow-mShadow of the actions menu

The order is: a --cp-* property you set on the element, then the VB token, then the built-in value. No token bridge is needed. A token bridge is a stylesheet rule that copies VB tokens onto a component's own properties, and this component already reads the tokens itself. The editor's syntax colors do not come from VB tokens. Set the --cp-token-* properties to change them.

Light or dark follows the page when mode is auto: the component watches data-mode, data-theme and the dark class on <html> and <body>, and the page's computed color-scheme.

The preview is a separate document in a sandboxed iframe. It does not load the Vanilla Breeze stylesheet, so VB tokens are not defined inside it. The inherit-theme attribute only copies the page's data-theme and data-mode values onto the preview's <html> element. To style the preview with Vanilla Breeze, add the VB stylesheet link through the head slot or head-src.

To change one playground, set the property on it.

code-playground[persist="intro-demo"] { --cp-accent: var(--color-success); --cp-radius: 0; --cp-editor-bg: var(--color-surface); }
