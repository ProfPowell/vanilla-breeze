http-component

A set of elements that display HTTP messages the way they travel on the wire: a request line or status line, then headers, then a body. It does not read Vanilla Breeze tokens: it has its own light and dark palettes, which you can override with CSS custom properties.

Install

From a CDN. One script defines every element. There is no stylesheet to load.

Or from npm:

npm install @profpowell/http-component import '@profpowell/http-component';

Demo

A request and its response in one <http-transaction>, then four requests on a timeline in <http-waterfall>. All of the data is written in the page; nothing is fetched.

Usage

Show a request and response pair by setting the data property of <http-transaction>. A body is a string; when the Content-Type header is JSON, HTML, CSS or JavaScript the body is syntax highlighted.

Without JavaScript of your own, pass the same objects as JSON in the request and response attributes. Use highlight to mark a part and box to draw a labeled border around it.

Show one message alone with <http-request> or <http-response>. Here the section names have no request- or response- prefix.

Show several requests on a timeline by setting the exchanges property of <http-waterfall>. Each exchange is a request, a response and a timing object in milliseconds.

With Vanilla Breeze

Version 0.3.0 reads no Vanilla Breeze token. Every color is a fixed value in one of two built-in palettes, and the fonts are fixed too (Courier New for messages, the system sans-serif stack for the waterfall).

The palette is chosen in this order:

  1. The theme attribute, when it is light or dark.
  2. Otherwise the operating system color preference, read once when the element is added to the page.

The elements do not look at the data-mode attribute that Vanilla Breeze uses to force light or dark mode. If your page sets data-mode, copy it to the theme attribute yourself:

const mode = document.documentElement.dataset.mode; // "light", "dark" or undefined if (mode) { document .querySelectorAll('http-transaction, http-request, http-response, http-waterfall') .forEach((el) => el.setAttribute('theme', mode)); }

To use Vanilla Breeze colors, set the component's custom properties on the element from page CSS. A rule in the page wins over the defaults the element sets on itself.

http-request, http-response { --bg-secondary: var(--color-surface); --border-color: var(--color-border); --text-primary: var(--color-text); --header-value: var(--color-text); --text-empty: var(--color-text-muted); }

This reaches <http-request> and <http-response> that you write in the page. It does not reach the ones inside <http-transaction> or <http-waterfall>: those live in a shadow tree and set the same properties again on themselves. On <http-transaction> only the outer --bg-primary can be changed this way. For full control of colors, place a request and a response side by side yourself.

Accessibility

  • Messages are rendered as text in a <pre> element, so they can be read, selected and copied. Highlighted sections use <mark>.
  • The waterfall's view switch, pause, clear, expand and request builder controls are native <button>, <select> and <input> elements, so they work from the keyboard.
  • The pause, clear and row expand buttons show a symbol only. Pause and clear have a title; the expand button has no text label in this version.
  • The active view is shown by color alone, and new captured requests are not announced to screen readers.
  • The colored timing phase bars are hidden from assistive technology with aria-hidden; the same numbers appear as text when a row is expanded.
  • The "Capturing" indicator pulses. The component has no prefers-reduced-motion rule, so the pulse does not stop for readers who ask for less motion.
