json-viewer

An element that shows a JavaScript value as a tree you can expand, collapse, search and copy from. Its colors and spacing come from --json-viewer-* custom properties, which you point at Vanilla Breeze tokens with a few lines of CSS.

Install

From a CDN. There is no stylesheet to load.

Or from npm:

npm install @profpowell/json-viewer import '@profpowell/json-viewer';

Demo

An order record shown as a tree, two levels open, with item counts. The viewer's colors, radius, font and spacing are mapped to Vanilla Breeze tokens in the page's CSS.

Usage

Write the JSON inside the element. The viewer reads its own text content when it has no data or src.

{ "order": 1042, "paid": true, "items": [ { "sku": "TEA-001", "qty": 2 }, { "sku": "MUG-014", "qty": 1 } ] }

Set the data property from JavaScript. This accepts any value, including ones JSON cannot hold: Map, Set, Date, BigInt and objects that refer to themselves. Set it after the element is defined, as here.

Load JSON from a URL with src. The viewer fetches it and shows the result, or an error object if the fetch fails.

Methods and properties

A path names one node: users[0].name for objects and arrays, cache@0 for the first entry of a Map or Set, and $ for the root. In a pattern, * matches one segment and ** matches any number.

MemberPurpose
dataThe value to show. Setting it removes the data attribute and renders again.
expand(matcher), collapse(matcher)Open or close the branches that match. The matcher is a path, a pattern with * or **, a RegExp, or a function that receives a path and returns true or false.
expandAll(), collapseAll()Open or close every branch.
search(query, options)Finds the query in keys and values, opens and scrolls to the first match, and returns an object with next(), prev(), current and count. Options: regex and caseSensitive, both off by default.
entryAt(path)Returns { key, value } for a path. For a Map entry the key is the original key object, not a string.
copy(text)Writes the text to the clipboard. With no argument it copies the whole value as JSON, writing each BigInt as a string ending in n.

With Vanilla Breeze

Each value in the viewer is resolved in three steps:

  1. The public hook, for example --json-viewer-surface.
  2. A fallback named --vb-*, for example --vb-surface.
  3. A built-in value, written with light-dark() for colors.

The package README calls step 2 the Vanilla Breeze fallback. In version 0.1.0 the literal names it reads are --vb-surface, --vb-text, --vb-text-muted, --vb-border, --vb-accent, --vb-radius, --vb-font-mono, --vb-space-1 to --vb-space-4, and --vb-json-key, --vb-json-string, --vb-json-number, --vb-json-boolean, --vb-json-null, --vb-json-punct.

Vanilla Breeze does not define any of those names. Its tokens are --color-*, --size-*, --font-* and --radius-*. So on a Vanilla Breeze page step 2 never matches, and the viewer shows its built-in colors unless you set step 1 yourself. This table gives the mapping:

Set this hookTo this VB tokenDrives
--json-viewer-surface--color-surfaceBackground.
--json-viewer-text--color-textMain text.
--json-viewer-text-muted--color-text-mutedSecondary text.
--json-viewer-border--color-borderBorders and dividers.
--json-viewer-accent--color-interactiveFocus, pressed and match colors.
--json-viewer-radius--radius-mCorners.
--json-viewer-font-mono--font-monoFont.
--json-viewer-space-1 to -4--size-2xs, --size-xs, --size-s, --size-mGaps and padding. These four tokens have the same default sizes as the viewer's built-in values.

Put the mapping in page CSS. A rule on json-viewer covers every instance; a rule on an id or other selector covers one.

json-viewer { color-scheme: inherit; --json-viewer-surface: var(--color-surface); --json-viewer-text: var(--color-text); --json-viewer-text-muted: var(--color-text-muted); --json-viewer-border: var(--color-border); --json-viewer-accent: var(--color-interactive); --json-viewer-radius: var(--radius-m); --json-viewer-font-mono: var(--font-mono); --json-viewer-space-1: var(--size-2xs); --json-viewer-space-2: var(--size-xs); --json-viewer-space-3: var(--size-s); --json-viewer-space-4: var(--size-m); } /* One instance: a taller limit and a different key color */ #order { --max-height: 24rem; --json-viewer-key: var(--color-primary); }

The color-scheme: inherit line matters when the page forces a mode with data-mode. The viewer sets color-scheme: light dark on itself, which makes every light-dark() value inside it follow the operating system preference. That includes its built-in value colors (keys, strings, numbers) and any Vanilla Breeze token whose value is a light-dark() pair. Inheriting the scheme from the page keeps them in step with the mode the page is showing.

Accessibility

  • Each branch is a native <details> element, so Enter or Space on its summary opens and closes it. Branches below the starting depth are built the first time they open.
  • Keys are buttons. They can be reached with Tab, and activating one shows its path.
  • Press / while focus is in the viewer to open search. In the search field, Enter goes to the next match, Shift + Enter to the previous one, and Escape closes search.
  • The toolbar has role="toolbar" and each button has an aria-label. The Search and Raw buttons report their state with aria-pressed.
  • The tree area has role="tree" and each node has role="treeitem". The match count and the path bar are polite live regions, so changes are announced.
  • The per-row copy buttons appear on hover or focus within the row and are left out of the Tab order. The toolbar's Copy button is reachable by keyboard.
  • With prefers-reduced-motion: reduce the disclosure arrow does not animate. Moving to a search match still scrolls smoothly.
  • Links in the data (strings that start with http:// or https://) open in a new tab.
