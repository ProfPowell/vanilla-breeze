pattern-grid

An element that fills itself with a set number of empty cells and leaves every visual decision to your CSS. It has no theming of its own, so the cells take whatever Vanilla Breeze tokens you use in the rules you write.

Install

From a CDN. The script is all you need. The stylesheet is optional: it sets up the grid layout for you, as described under Usage.

npm install @profpowell/pattern-grid import '@profpowell/pattern-grid'; // Optional import '@profpowell/pattern-grid/css'; import '@profpowell/pattern-grid/seed-context'; import '@profpowell/pattern-grid/paint-worklet';

Demo

Two grids colored only with Vanilla Breeze tokens: a ramp where each cell's color depends on its position, and a seeded random texture that is the same on every load.

Usage

The element creates the cells and nothing else. On its own it shows nothing: the cells are empty <i> elements with no size or color. This CSS makes the grid visible. The element sets --pg-cols and --pg-rows on itself for your rules to use.

The CSS functions sibling-index() and sibling-count() give a cell its position and the number of cells, but not every browser has them. Add shim="sibling" and the element writes the same numbers as custom properties: --i on each cell, counting from 1, and --n on the grid.

Wrap a grid in <seed-context> to give every cell random numbers. Each cell gets --rand-0 to --rand-7, each between 0 and 1, and --randi-0 to --randi-7, whole numbers from 0 to 99. The same seed produces the same numbers on every load.

Do not combine shim="sibling" with <seed-context> on the same grid. In version 0.3.0 the seed context replaces each cell's inline style, which removes --i.

To skip writing the layout rules, load the optional stylesheet. It makes the element a grid of square cells and reads four custom properties: --pg-gap, --pg-bg, --pg-cell-aspect and --pg-aspect.

With Vanilla Breeze

pattern-grid has no theming of its own. It reads no Vanilla Breeze token and has no fallback order, because it ships no colors, fonts or spacing. The cells are plain light DOM elements, so page CSS reaches them directly and Vanilla Breeze tokens work in it like anywhere else.

VB tokenA use in a pattern
--color-primary, --color-accentThe colors a pattern is mixed from. They change with the theme.
--color-surface, --color-surface-sunkenThe quiet end of a ramp, so cells fade into the page in light and dark mode.
--size-3xs, --size-2xsGap between cells.
--radius-s, --radius-mCorner radius of cells or of the whole grid.

Style all grids with a rule on pattern-grid, and one grid with an id or other selector:

pattern-grid { display: grid; grid-template-columns: repeat(var(--pg-cols), 1fr); gap: var(--size-3xs); } pattern-grid > i { aspect-ratio: 1; border-radius: var(--radius-s); background: var(--color-surface-sunken); } /* One instance: a ramp from the surface color to the theme's primary color. Needs shim="sibling" on the element for --i and --n. */ #ramp > i { background: color-mix( in oklch, var(--color-primary) calc(var(--i) / var(--n) * 100%), var(--color-surface) ); }

Because the colors are tokens, the pattern changes when the theme or the light and dark mode changes, with no script.

Accessibility

  • The generated cells are empty and carry no role, label or keyboard behavior. A grid used as decoration should be hidden from assistive technology with aria-hidden="true".
  • If a pattern carries meaning, give that meaning in text next to it. Color in empty cells is not available to a screen reader.
  • The element adds no motion. Any animation comes from your CSS, so wrap it in a prefers-reduced-motion query.
  • <seed-context> fades cells in over 220 milliseconds when it fills them. Version 0.3.0 does not turn that fade off for reduced motion.
