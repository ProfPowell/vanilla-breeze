The approach

A page on a content site carries facts about itself: who wrote it, when it changed, what it is about, what it replaced. Vanilla Breeze asks you to state those facts once, in standard HTML, and gives you components that read them.

The facts live in three places. <meta> and <link> tags in the <head> describe the page. Elements and attributes in the body (<ins>, <del>, <dfn>, rel, headings with ids) describe its parts. A JSON file that your build writes describes the whole site. Nothing here needs a particular content management system or site generator. Any tool that can write those tags and that file will do.

From task to component

Start from what you want a reader to be able to do.

What is handled and what you provide

The components display and navigate content. They do not store it, build it or publish it.

Area The library handles You provide
Page metadata Reading the tags and rendering them: the provenance panel, reading time, word count, relative dates The <meta> and <link> tags, written by hand or by your build
In-page navigation A contents list with scroll tracking, heading permalinks and generated heading ids, a progress bar, numbered footnotes Headings in order, and the footnote text
Site-wide views Filtering, grouping and switching between views of a list of pages The list: a JSON file with one record per page, and a Pagefind index for search
Provenance and integrity Styles for declared provenance, the trust badge, checking a signature in the browser Honest declarations, a signing key and a signing step in your build, if you want signatures
Changes and versions Styles for <ins> and <del>, view toggles, a version picker, a line diff between two versions of a page The marked-up edits, the list of versions and the archived pages
Reader annotations Highlights and private notes kept in the reader's browser Nothing, unless you want to copy them to a server
Discussion The thread display, the comment form, reaction chips, and events for each action Storage, accounts and moderation. No comment is saved unless your code saves it.

The library does not produce feeds, an XML sitemap or a search index. This site builds its own with scripts that are not part of the package.
