Three parts

A working glossary has three parts: the page that holds the definitions, the mark-up that says where a term is defined, and the links from prose to the definition. HTML covers all three with <dl>, <dfn> and <a>. Vanilla Breeze styles them and adds two components that make a glossary page easier to use.

PartMarkupThe library adds
The glossary page A <dl> of terms and definitions <glossary-index> or <glossary-wc>: a filter box and letter navigation
The defining use <dfn> An italic, medium-weight style. A <dfn> with an id is outlined when a link targets it.
Links from prose <a href="/glossary/#term-..."> Nothing beyond link styling. The pop-up definitions on this site come from its own build (see below).

The glossary page

Write the glossary as sections by letter, each holding a <dl>. Give every <dt> an id so prose can link to it. This is a complete page without script. Wrapping it in <glossary-index> adds a filter box above the list and marks the current letter in the jump row as the reader scrolls.

Glossary

  1. P
  2. S

P

proving
The final rise of shaped dough before it is baked.

S

starter
A culture of flour and water kept alive to raise bread.

Add the permalinks attribute to give each term a link that copies its address. It is off by default, since most readers arrive at a term and do not need to share it.

Terms in prose

<dfn> marks the place where a term is defined, not every place it is used. In an article, that is the first use that explains the term. Link it to the glossary entry so a reader can get the full definition.

Leave the shaped loaf for its final proving, the last rise before baking.

A cold kitchen slows proving by hours.

Bakers write DDT on the mixing sheet.
  • Use <dfn> once per term per page. Later mentions are plain links.
  • Link a term when you mean the glossary's sense of it, not every time the word appears. One or two linked terms in a paragraph is enough.
  • Do not link a term inside a heading, inside <code> or <pre>, or inside another link.
  • For a short form, wrap the link in <abbr> with the full term in title.

When the reader follows the link, the glossary scrolls to the entry, and the term and its definition are tinted with a bar on the leading edge so the reader can see which entry they landed on.

How this site does it

The rest of this page describes this documentation site's build. None of it is in the vanilla-breeze package. It is here for people who write for this site, and as one worked design for a larger glossary.

One vocabulary file

Every term lives in site/src/_data/vocabulary.json as a SKOS concept with an @id, a skos:prefLabel, a skos:definition and optional skos:altLabel entries. The build makes three things from it: the glossary page, where each entry has the id term-{@id}; a /definitions.json file; and the topic pages. To add a term, add it to that file and rebuild.

The data-concept attribute

A term link on this site carries data-concept with the concept's @id.

progressive enhancement

A small script that the build writes looks for a[data-concept]. On a plain click it shows the definition in a native popover beside the term, fetching /definitions.json once and keeping it for the browser session. A click with a modifier key, or a middle click, follows the link as usual. So does every click in a browser without the Popover API, and a click on a term whose entry is on the current page.

Automatic linking

A build plugin links terms for you on the Architecture, Content Management, Extensibility, Interaction and Process guides and on the element, attribute, pattern, integration and snippet pages. You do not need to write term links by hand on those pages.

  • The first occurrence of a concept's preferred label is wrapped in <dfn><a data-concept>. Later occurrences get a plain link.
  • At most one link is added per paragraph, list item, table cell or definition.
  • Text inside links, code, headings, <dfn>, <abbr>, code blocks and demo windows is never touched.
  • Alternative labels are not linked unless the concept opts in with "vb:autoLink": { "altLabel": true } in the vocabulary file. This keeps common words such as review from being linked everywhere.
To stop automatic linkingWrite
On a whole pageautolink: false in the front matter
In one part of a pagedata-no-glossary on an element around it
For one concept on a pageA link with that data-concept by hand, anywhere on the page. Yours is kept and no others are added.

If a page is about a concept, list the concept in the page's concepts front matter as well. That writes the <meta name="concept"> tag described in Page Metadata.
