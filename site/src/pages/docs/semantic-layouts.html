Two forms, one set of rules

Most layouts can be written as an element or as an attribute. The element form adds a wrapper. The attribute form goes on an element that is already there for its meaning: a <nav>, a <ul>, an <article>.

Each layout is defined once in the stylesheet, for both forms, as :is(layout-grid, [data-layout="grid"]). The modifiers (data-layout-gap, data-layout-min and the rest) are the same on both.

    What differs between the forms

    The layout rules are shared. The attribute form also carries everything that belongs to its host element.

    Element form Attribute form
    Meaning None. A <layout-*> element has no role. The host keeps its role: a list is announced as a list, a nav as navigation.
    Host styles None besides the layout The host keeps its own styles. A <ul> keeps its bullets and indent (add class="unstyled"); a <nav> or <header> keeps whatever the library gives that element.
    Container queries Not a query container <main>, <article>, <section> and <aside> are query containers, so a container query or a cqi unit inside measures the host.

    Sectioning elements as children

    The container difference also affects children. A query container takes its width from its parent and has none of its own. In a layout that sizes children by their content (a cluster, a reel, a centered cover, a stack aligned to the start, center or end) an <article> or <section> child would collapse to nothing. The library turns containment off for those children so they keep their width.

    If you need such a child to be a query container, add data-container and give it a width. Responsive Behavior lists every case.

    When to use which form

    Situation Use Why
    The right element already exists (<nav>, <ul>, <article>, <form>) The attribute, on that element No extra wrapper, and the element keeps its meaning
    You need a wrapper that has no meaning The element <layout-stack> says what the wrapper is for. A <div> does not.
    The children are sectioning elements sized by their content Either, with data-container where a child must stay a container See Sectioning elements as children
    A surface: a card, a badge The element <layout-card> and <layout-badge> have no attribute form
    A raised sheet on an element you already have data-canvas The canvas is the one surface with an attribute form

    Accessibility

    • Landmarks come from elements, not layouts. <main>, <nav> and <aside> are landmarks wherever they are. <header> and <footer> are the banner and content information landmarks only when they are not inside an <article>, <aside>, <main>, <nav> or <section>. A <section> is a region landmark only when it has an accessible name, for example aria-labelledby pointing at its heading.
    • Keep the source in reading order. Layouts can change where things appear: a reversed media object, a reversed switcher, a sidebar on the end side. Keyboard focus and screen readers follow the source.
    • Use lists for lists. A grid or cluster on a <ul> or <menu> lets a screen reader announce how many items there are.
