Philosophy

Internationalization is not a feature you add — it is a constraint you respect from the start. VB treats i18n the same way it treats semantic HTML: build it in, don't bolt it on.

The web platform already has most of what you need: the lang attribute, CSS :lang(), logical properties, the Intl API, the translate attribute, and ruby HTML elements. VB uses them correctly and consistently.

Script-Specific Typography

Set lang on any element and VB automatically applies the right font family, line height, letter spacing, and word-breaking rules. This works via CSS :lang() which inherits through the subtree.

VB provides custom properties for each script family. Override them to load your preferred fonts:

:root { --font-cjk: "Noto Sans CJK SC", "PingFang SC", system-ui, sans-serif; --font-arabic: "Noto Sans Arabic", "Segoe UI", system-ui, sans-serif; --font-hebrew: "Noto Sans Hebrew", "Segoe UI", system-ui, sans-serif; --font-thai: "Noto Sans Thai", "Leelawadee UI", system-ui, sans-serif; --font-devanagari: "Noto Sans Devanagari", system-ui, sans-serif; }

Translate Conventions

Machine-translation opt-out is an HTML attribute, not CSS — there is no stylesheet rule that can do it (the CSS translate property is a transform). VB therefore cannot protect code for you: add translate="no" to <code>, <kbd>, <samp>, <pre> and <var> content that must stay verbatim, and to brand names, identifiers, and technical terms:

Locale Resolution (JS)

VB provides a centralized getLocale() function that all format utilities share. The priority chain:

  1. <html lang> attribute
  2. navigator.language
  3. 'en' fallback

Individual elements can override via data-locale:

1.234,56 1,234.56

Components that read the nearest lang (<calendar-wc>, <week-view>, <day-view>, <date-picker>) pass it through usableLocale() first. A malformed tag such as the POSIX-style lang="en_US" makes every Intl constructor throw, so those components fall back to en-US rather than failing to render. Write BCP 47 tags with hyphens: en-US, ja-JP.

Alternate Calendars

Locales are passed straight to Intl, so a BCP 47 calendar extension works with no extra configuration. Setting lang="ja-JP-u-ca-japanese" on <html> switches every VB date utility to the Japanese era calendar (和暦) at once:

<html lang>data-format-datedata-format-date="short"
ja-JP2026/10/212026/10/21
ja-JP-u-ca-japanese令和8年10月21日R8/10/21

The extension is invisible to everything else that reads lang. :lang(ja) still matches, so the CJK typography and ruby rules apply unchanged, and Intl.RelativeTimeFormat and Intl.NumberFormat ignore the calendar and keep working. To use the era calendar for one element only, put the same tag in its data-locale (format utilities) or lang (<date-picker>).

令和8年10月21日 R8/10/21

Intl formats era dates but cannot parse them. <date-picker> accepts typed era dates (令和8年10月21日, 令和元年5月1日, R8/10/21) as well as the Gregorian 2026年10月21日 form.

JS Utilities

Import locale utilities for custom components:

import { getLocale, usableLocale, isRTL, usesRuby, primarySubtag } from './lib/i18n.js'; getLocale(); // 'en-US' (from html[lang] or navigator) usableLocale('en_US'); // 'en-US' (malformed tags fall back instead of throwing) isRTL('ar'); // true usesRuby('ja'); // true primarySubtag('zh-TW'); // 'zh'

VbI18n String Swap

For application-level translation, VB exports a VbI18n class. It is not auto-initialized — you instantiate and configure it with your own message maps.

import { VbI18n } from './lib/i18n.js'; const i18n = new VbI18n({ locale: 'fr', messages: { en: { 'nav.home': 'Home', 'actions.close': 'Close' }, fr: { 'nav.home': 'Accueil', 'actions.close': 'Fermer' }, } }); // Swap all [data-i18n] elements i18n.apply(); // Listen for locale changes i18n.watch();

Logical Properties

VB uses CSS logical properties throughout (465+ instances). RTL layout works automatically when you set dir="rtl" on <html>. No additional CSS is needed.

/* VB never writes this: */ .card { padding-left: 1rem; margin-right: auto; } /* VB always writes this: */ .card { padding-inline-start: 1rem; margin-inline-end: auto; }
