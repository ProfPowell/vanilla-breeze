Principles

Vanilla Breeze is an HTML-first framework. HTML is the atom of a site or app, whether a server emits it or the browser enhances it. CSS and JavaScript are optional layers on top of it.

Statement

Markup starts with elements. A class varies an element's look, an attribute configures it, and data-* attributes hold its state and data. CSS binds to elements first, uses classes for variation and reads state from attributes. JavaScript is encapsulated in components that communicate through state and use the web platform wherever it can.

CSS and JavaScript are optional, and each is added as a progressive enhancement. Presentation is separate, layered and flexible, so look and feel are easy to change and themes are first class. Execution is kept minimal for performance and reliability.

The framework is opinionated. Its defaults come from experience, and every one of them can be overridden. The goal is the web for all: accessibility, performance and internationalization are designed in at all times.

One grammar, three languages

The same four parts of speech mean the same thing in HTML, CSS and JavaScript. Learn the table once and every element, attribute and component in the library reads the same way.

Part Says In HTML CSS JavaScript
Element What it is <nav>, <form-field>, <tab-set> Binds here first Defines components
Class Which look class="secondary" Varies the element's look Leaves classes alone
Attribute How it is configured data-layout-gap="m", filter="topic" Selects on the value Reads on connect and on change
data-* state What is true right now data-state="open", data-loading Styles the state Reads and writes

Why some attributes carry data- and some do not

HTML does not allow new attributes on its own elements, so anything Vanilla Breeze adds to a native element is a data-* attribute. An element the library defines can declare attributes of its own.

Eight principles

1. HTML is the atom

Every feature starts as markup that a browser can read with nothing else loaded. A server can emit it or a script can enhance it, and in both cases the markup is the source of truth. An accordion is a <details> first.

2. One grammar across HTML, CSS and JavaScript

Elements say what a thing is, classes vary its look, attributes configure it and data-* holds state. Names describe purpose and never appearance: class="secondary", --color-text-muted, <layout-sidebar>. See Attributes and the class page.

3. CSS and JavaScript are optional

Each layer improves the page and none is needed to read it. Layout elements such as <layout-stack> are styled by CSS alone and are never registered with JavaScript. A web component styles its unregistered form, so the content is usable while the script loads and if it never arrives.

/* Script not loaded: every panel is visible, stacked */ tab-set:not(:defined) { display: block; } /* Script loaded: the tab interface takes over */ tab-set:defined { display: grid; }

The Resilience Matrix records what each component does without JavaScript and without CSS.

4. Behavior lives in components

JavaScript is encapsulated in web components. They communicate through attributes, state and events, and they use the platform before any package: <dialog>, popover, form validation, ElementInternals, view transitions. The library ships with no runtime dependencies. See the Data API for how a component accepts both markup and properties.

5. Presentation is separate, layered and themeable

Styles are ordered by cascade layers and written against semantic tokens, so a theme changes the look of every element without touching markup. Themes are first class. See Tokens, Themes and Overrides.

color: var(--color-text-muted); background: var(--color-surface); border-color: var(--color-border);

6. Do the minimum

Code that does not run cannot be slow and cannot fail. The library prefers HTML to CSS and CSS to JavaScript, loads components only when a page uses them and keeps each bundle within a budget. See Performance.

7. Opinionated defaults, all overridable

A page with no classes and no configuration should already look finished. The defaults come from experience, and each is a token, a layer or an attribute that you can change. See Overrides.

8. The web for all

Accessibility, performance and internationalization are part of every element from the start. Styles use logical properties so layouts follow the writing direction. Components carry their roles, labels and keyboard behavior, and their text can be translated. See Accessibility and i18n.

What enforces them

A principle that nothing checks will drift. These run on every change, and a failure blocks the release.

Principle Check
HTML is the atom Conformance rules reject <div> wrappers and broken heading order in every demo, and require <form-field> around form controls.
One grammar A conformance rule flags state written as a class. A lint rejects classes in the documentation that the library does not define. Each component's documented attributes are compared with its code.
Optional layers The Resilience Matrix is generated from data kept beside each component.
Behavior in components The package declares no runtime dependencies.
Themeable presentation Token lints reject undefined tokens and literal colors, and check that every theme covers the semantic tokens. A conformance rule rejects inline styles.
Do the minimum A size budget fails the build when a bundle grows past its limit.
The web for all Component tests check contrast under each theme, keyboard behavior and right-to-left layout.

What we won't do

  • Require a build step. Link a stylesheet and a script and the library works.
  • Ship utility classes. Layout and spacing belong to elements and attributes. A class names a look.
  • Add runtime dependencies. Development tools exist for building and testing, and none of them reach your users.
  • Replace a native element that already does the job. The library styles and extends <dialog>, <details> and popover. It does not rebuild them.
  • Make JavaScript a condition for reading content.

Architecture Decisions gives the reasoning for each choice, the failure it prevents and the cost it accepts.
