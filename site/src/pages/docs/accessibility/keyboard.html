The focus ring

Every focusable element shows an outline when it takes keyboard focus. The rule uses :focus-visible, so a mouse click on a button does not draw it and a Tab press does. Three tokens set its look everywhere at once.

:root { --focus-ring-width: 2px; --focus-ring-offset: 2px; --focus-ring-color: var(--color-primary); }

The high contrast theme and the system's increased-contrast setting both widen the ring to 3px. Do not remove the outline. If it clashes with a design, change the tokens.

Skip link

A reader using a keyboard should not have to tab through the whole header on every page. A skip link is the first focusable element in <body>. It stays off screen until it takes focus, and it moves focus to the main content.

The .skip-link class is part of the core stylesheet. Two details make it work:

  • The target takes focus. <main> is not focusable by default. tabindex="-1" lets the browser move focus there, so the next Tab continues from the content and not from the top.
  • It comes first. Anything focusable before it has to be passed to reach it.

A page with several large regions can have more than one. They stack in source order.

Landmarks such as <main> and <nav> let screen reader users jump between regions, but they give sighted keyboard users nothing. A page needs both.

Tab order

Focus follows source order. Layout elements such as <layout-sidebar> place content with CSS and never reorder the keyboard path, so write the markup in reading order and let the layout arrange it.

To do thisUse
Make an element focusable from script, but not a tab stoptabindex="-1"
Add a custom control to the tab ordertabindex="0", and only when no native element fits
Take a region out of the tab order while it stays visibleinert
Remove content for everyonehidden

Never use a positive tabindex. It pulls the element out of source order and every later change to the page has to account for it.

Keeping focus inside

A modal <dialog> opened with showModal() contains focus, closes on Esc and returns focus to the element that opened it. The browser does all three. Use it for anything modal.

For a region that is not a dialog, such as an inline editing panel, add data-focus-trap. Tab and Shift+Tab then cycle inside it.

With an empty value the trap also moves focus to the first control, or to the one marked autofocus, as soon as it is found. no-autofocus leaves that to you, which suits a panel that is in the page from the start and hidden. Whichever you use, give the reader a way out: a cancel button and Esc, and return focus to the control that opened the panel.

Shortcuts

data-hotkey on a <kbd> shows a key combination the way the reader's platform writes it, Ctrl+K for example, and gives screen readers the spelled-out names. <short-cuts> lists every shortcut a page defines in a dialog opened with ?.

A shortcut made of a single character can fire by accident for people who use speech input. Keep single-key shortcuts to a component that has focus, or let readers turn them off.
