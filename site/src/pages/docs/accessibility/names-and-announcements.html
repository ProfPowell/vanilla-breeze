Accessible names

Every control needs a name that a screen reader can speak and that voice control can target. Visible text is the best name, because every reader gets the same one. Where a design has no room for text, the name still has to exist in the markup.

Press the button in the demo to draw the names that are present but not displayed.

Need Use Why
Name an icon-only button aria-label on the button The shortest form. Use a .visually-hidden span when the name contains markup or has to pass through the same translation step as the page text.
An icon beside visible text Nothing The text names the control. <icon-wc> hides itself from screen readers unless you give it a label.
Label an input that has no visible label <label class="visually-hidden"> A placeholder is not a label. It disappears on input and many screen readers do not read it as the name.
Name a group of radios or checkboxes <legend>, hidden with .visually-hidden if the design has no place for it A <fieldset> without a legend has no name.
Give a section a heading that only screen readers need <h2 class="visually-hidden"> Screen reader users move through a page by heading. An aria-label on the section does not appear in that list.
Say that a link opens a new tab or downloads a file A .visually-hidden span inside the link Sighted readers get the icon. Everyone else needs the words before they follow the link.

Hiding text visually

.visually-hidden is in the core stylesheet. It removes an element from the display and keeps it in the accessibility tree.

Never put aria-hidden="true" on something focusable. The reader can still tab to it and hears nothing.

Announcing changes

When content changes without a page load, a sighted reader sees it and a screen reader user does not, unless the change happens inside a live region. Changing the text of a live region is the whole mechanism.

Two rules keep announcements reliable:

  • The region is in the page before its text changes. A region inserted with its message already in it is often not announced.
  • Polite is the default. An alert cuts off whatever is being read. Use it for a failure the reader has to act on, and for little else.

The shared live region

Components and utilities announce through one function, and your code can use it too. It keeps one region per politeness level in the document, so the region exists before the first message, and it repeats a message that is sent twice.

import { announce } from 'vanilla-breeze'; announce('Copied to clipboard'); announce('Upload failed', { politeness: 'assertive' });

Roles and states by component

Each component sets the roles and states its pattern needs. This table lists them, names the pattern, and says what is left to you. It is generated from the data kept beside each component, and a release check compares it with the component's code.

A pattern name that begins with Native means the component adds little or no ARIA, because the element underneath already carries the role. Patterns that link out follow the ARIA Authoring Practices Guide.

For the states the library styles on your own markup, such as aria-pressed, aria-expanded and aria-busy, see ARIA states.
