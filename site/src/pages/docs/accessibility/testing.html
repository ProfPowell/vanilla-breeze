A ten-minute manual pass

The library's parts are tested before release. Your pages combine them with your content, and that combination is what readers meet. These checks need no tools and find the problems that matter most.

  1. Put the mouse away. Tab from the top of the page to the bottom. Can you reach and operate everything, and can you always see where focus is?
  2. Try the skip link. The first Tab should show it, and Enter should land you in the main content.
  3. Open and close everything. Dialogs, menus and panels should take focus when they open and give it back when they close. Esc should close them.
  4. Zoom to 200%. Then narrow the window to 320 pixels. Nothing should be cut off or need sideways scrolling to read.
  5. Read the headings alone. Do they outline the page, in order, with no level skipped?
  6. Read the links alone. Does each one say where it goes without the sentence around it?
  7. Look at each image. Does its alt say what the image is for, or is it empty because the image is decoration?
  8. Submit each form wrong. Is the error next to the field, in words, and does it say how to fix it?
  9. Turn on reduced motion and forced colors. Is every control and state still visible?
  10. Switch the theme. Check light, dark and high contrast.

Emulating preferences

Browser developer tools can switch each preference without changing your system settings. In Chrome or Edge, open DevTools, press Ctrl+Shift+P and type Rendering to show the Rendering panel.

Setting in the Rendering panelTests
Emulate CSS media feature prefers-reduced-motionAnimations and transitions stop
Emulate CSS media feature prefers-contrastBorders and muted text strengthen
Emulate CSS media feature forced-colorsControls and states survive the reader's palette
Emulate CSS media feature prefers-color-schemeLight and dark
Emulate vision deficienciesWhether meaning depends on color alone

Firefox has the color scheme switch and a contrast checker in its Accessibility panel. Safari has the color scheme and reduced motion overrides in the Elements tab of Web Inspector.

Screen readers

Test with at least one. Each screen reader is developed against a particular browser, and results in other pairings are less reliable.

Platform Screen reader Browser Start and stop
macOS VoiceOver, built in Safari Cmd+F5
Windows NVDA, free Firefox or Chrome Ctrl+Alt+N
Windows JAWS Chrome or Edge From the Start menu
iOS VoiceOver, built in Safari Settings, Accessibility
Android TalkBack, built in Chrome Settings, Accessibility

A first session can be short. Move through the page by heading, then by landmark, then tab through the controls. Listen for three things: each control says what it is, what it is called and what state it is in.

Automated tools

Automated checkers are fast and repeatable, and they find a minority of problems. They can tell that an image has no alt. They cannot tell that the alt is wrong. Run one in development and one in your build, and do the manual pass as well.

  • axe DevTools, a browser extension, for the page in front of you
  • WAVE, a browser extension that marks problems on the page itself
  • Lighthouse, in Chrome DevTools
  • Pa11y or axe-core, from the command line and in continuous integration

What the library tests

Each component has browser tests for its keyboard operation, its roles and states and its focus handling. Pages are measured for contrast under every bundled theme, in light and dark. Layouts and components are run right to left, with reduced motion and with forced colors. Markup rules reject skipped heading levels and unlabelled form controls in every demo. What holds it in place has the list.

None of that tests your content. The manual pass above does.
