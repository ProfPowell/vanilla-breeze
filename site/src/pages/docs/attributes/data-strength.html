Overview

data-strength adds a strength meter and a rules checklist under a password input. Each rule in data-rules counts equally; the share of rules met gives the level: weak, fair, good or strong. The meter is a native <meter>, the level is also written as text, and each rule says whether it is met.

The input must be inside <form-field>; a bare input is not enhanced. The rules are advisory unless you add data-strength-min.

Usage

Every input[type="password"] inside <form-field> also gets a show/hide button automatically; there is no attribute to add. The meter and the toggle work together.

Options

AttributeValuesDefaultEffect
data-strengthboolean, on the input—Adds the meter, level text and rules checklist.
data-rulescomma-separated rules (below)length:8The rules to check. Unknown rules are skipped with a console warning.
data-strength-minfair, good, strongnone (advisory)A non-empty password below this level is invalid: the input gets a custom validity message and the form will not submit. An empty value is left to required.

An empty input has no level. The value is checked when the field is set up (so prefilled or browser-restored values show at once), on every input, and after a form reset.

Events

No custom events. Listen for the native input event and read the generated meter: .strength-meter carries data-level (weak, fair, good, strong or empty) and its <meter> holds the number of rules met.

const input = document.querySelector('#password'); const field = input.closest('form-field'); // Listen on the field: the bubbling event reaches it after the meter's own // listener on the input has updated the level. field.addEventListener('input', () => { const wrap = field.querySelector('.strength-meter'); const meter = wrap.querySelector('meter'); console.log('Level:', wrap.dataset.level, 'Rules met:', meter.value, 'of', meter.max); });

Styling

No custom properties. The script inserts this after the input (or its show/hide wrapper):

Fair
  • At least 8 characters: met
  • One special character: not met

The bar is the standard VB <meter> (size s, with a bordered track), so its fill colours come from the meter tokens --meter-fill-even-less-good, --meter-fill-suboptimum and --meter-fill-optimum. The shipped rules for the text:

form-field .strength-meter[data-level="weak"] .strength-label { color: var(--color-error-text); } form-field .strength-meter[data-level="fair"] .strength-label { color: var(--color-warning-text); } form-field .strength-meter[data-level="good"] .strength-label { color: var(--color-info-text); } form-field .strength-meter[data-level="strong"] .strength-label { color: var(--color-success-text); } form-field .strength-rules { list-style: none; padding: 0; font-size: var(--font-size-s); color: var(--color-text-muted); } /* ::before draws a circle (unmet) or a check (met) */ form-field .strength-rules li[data-met] { color: var(--color-success-text); }

Accessibility

  • The meter is a native <meter> named "Password strength" whose aria-valuetext is the level name, so it is read as "Fair", not "3".
  • Level changes are announced through a polite, visually hidden role="status" region, about half a second after typing pauses, so each keystroke does not interrupt.
  • The rules list is linked to the input with aria-describedby, and every rule ends in hidden "met" / "not met" text, so the state does not rely on the icon or colour.
  • The level text colours use the status *-text tokens, which keep 4.5:1 against the surface in light and dark mode. In forced-colours mode the rule icons use system colours.
  • The rules are advice. With data-strength-min, the browser's validation message explains why the form will not submit.
  • The input needs a visible <label>; use autocomplete="new-password" so password managers can suggest a strong one.
  • Without JavaScript the input is a normal password field.
