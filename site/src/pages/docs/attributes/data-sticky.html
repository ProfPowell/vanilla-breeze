Overview

data-sticky works at two levels:

  • Standalone — <header data-sticky> or <footer data-sticky> sticks on its own. No other attribute or script is needed.
  • Coordinated — <html data-sticky> turns on StickyManager. It marks the banner header sticky, measures its live height into --sticky-offset on :root, and enables the sidebar rules (data-layout-sticky), so every sticky region lines up below the header without a hardcoded offset.

Sidebars (<nav> / <aside>) do not take data-sticky. They opt in with data-layout-sticky, which only works in coordinated mode.

Not to be confused with <table data-sticky="header|column|both">, a separate attribute that freezes a table's header row and/or first column (plus data-sticky-column="2" for two frozen columns). See <table>.

Standalone sticky header and footer

A header or footer with data-sticky is always sticky: position: sticky at the top (header) or bottom (footer), z-index: 100, and an opaque surface background. It stays sticky at every viewport width.

The banner header is the first <header> that is not inside an article, aside, main, nav or section (or their ARIA-role equivalents), so a card or article header is never made sticky.

Toggle the system from script with document.documentElement.toggleAttribute('data-sticky'). The <settings-panel> has a Sticky Navigation toggle that does this and remembers the choice.

Where data-layout-sticky applies

In coordinated mode, data-layout-sticky pins these regions:

  • <nav> / <aside> that are direct children of a <layout-sidebar> or data-layout="sidebar" element.
  • <nav> / <aside> / <header> that are direct children of a data-page-layout element.

For a sidebar inside a sidebar or page layout, use data-layout-sticky instead of writing this by hand.

What triggers a re-measure

  • Header size changes — a ResizeObserver on the banner header (banners appearing, responsive reflow, wrapping nav).
  • Window resize — passive resize listener.
  • Fonts loaded — document.fonts.ready (header height often changes once webfonts arrive).
  • Toggle events — a document-level, capturing toggle listener, so any <details> or popover opening or closing anywhere on the page.
  • Initial mount — an immediate measure plus a follow-up in the next animation frame.

Accessibility

  • Sticky chrome covers content. Coordinated mode sets scroll-padding-block-start on :root to --sticky-offset + --sticky-gap, so in-page links and focused elements scrolled into view land below the header (WCAG 2.4.11 Focus Not Obscured). For a standalone header, set --header-sticky-size if it is taller than the default.
  • Keep sticky headers short. On small screens a tall pinned header can leave little room for content, which is why coordinated mode un-sticks it below 48rem; standalone headers do not, so keep them compact or use coordinated mode.
  • Sticky sidebars scroll on their own when taller than the viewport, so every link stays reachable by scrolling and by keyboard.
  • Users can switch the coordinated system off from the <settings-panel> Sticky Navigation toggle.
  • Print: src/utils/print.css returns sticky headers, footers and table cells to normal flow.

When NOT to use

  • Inside scrollable subregions — the coordination system measures against the viewport; a sticky element inside an overflowing container sticks to that container instead.
  • Tables — use the table's own data-sticky (see the note above).
