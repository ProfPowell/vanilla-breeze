Overview

The data-sticky attribute on <html> turns on VB's sticky coordination system. Behind it, StickyManager measures the live sticky-header height and writes it to --sticky-offset on :root. Every sticky sidebar, TOC, scroll-padding setting, and "scroll into view" behavior reads that variable, so they all line up correctly without you hardcoding a header offset anywhere.

On <header> and <footer>, data-sticky marks the element as sticky. The first <header> in the document picks it up automatically when the system is active. Sidebars opt in with data-layout-sticky instead. Nothing sticks unless <html> has data-sticky: sticky is an enhancement, not a default.

Toggle the whole system from script with document.documentElement.toggleAttribute('data-sticky'). The <settings-panel> has a Sticky Navigation toggle that does this and remembers the choice.

Two roles

OnEffect
<html data-sticky> Enables the system. StickyManager.init() runs; auto-applies data-sticky to the first <header> if not already present; sets up resize + fonts.ready + toggle listeners to keep --sticky-offset current.
<header data-sticky> Header opts in (or is auto-applied). Becomes position: sticky at top: 0; its height is what StickyManager measures.
<footer data-sticky> Sticks to the bottom of the viewport.
<nav data-layout-sticky> / <aside data-layout-sticky> Not data-sticky: sidebars use data-layout-sticky, as direct children of a data-page-layout body or a sidebar layout. They stick at var(--sticky-offset) + var(--sticky-gap), are capped at the remaining viewport height, and scroll on their own when their content is taller.

The CSS variables it provides

VariableSet byUse for
--sticky-offsetStickyManager (px; 0px until measured)Top offset for any other sticky element so it stays below the header.
--sticky-gap theme / authors (default var(--size-2xs))Breathing room between the header and sticky sidebars or TOC.
--z-sticky-headertokens (default 200)Header stacking, above other sticky elements so dropdowns are not clipped by the TOC.
--z-stickytokens (default 100)Footer and other sticky regions.
aside[data-sticky] { position: sticky; inset-block-start: var(--sticky-offset, 0); max-block-size: calc(100dvh - var(--sticky-offset) - var(--sticky-gap, 1rem)); overflow-y: auto; }

What triggers a re-measure

  • Window resize — resize listener on window (passive).
  • Fonts loaded — document.fonts.ready resolves and triggers a re-measure (header height often changes once webfonts arrive).
  • Toggle events — any <details> opening / closing inside the header.
  • Initial mount — immediate measure plus a follow-up in the next requestAnimationFrame after layout settles.

Composition

  • <page-toc> — the TOC sidebar reads --sticky-offset for its own positioning.
  • data-page-layout — its nav / aside regions take data-layout-sticky.
  • scroll-padding-block-start on :root — set to var(--sticky-offset) + var(--sticky-gap) while the system is on, so anchor-link jumps land below the sticky header.
  • Below 48rem the sticky header is switched off (back to position: static) to save screen space.
  • Print stylesheet — src/utils/print.css disables sticky behavior automatically.

When NOT to use

  • Pages with no sticky chrome — the system measures and sets variables every resize; that's cheap but pointless if nothing's sticky.
  • Inside scrollable subregions — data-sticky on a child of an overflowing container won't measure correctly; coordinate with the parent's scroll state instead.
  • Tables — <table data-sticky="header|column|both"> is a separate attribute for sticky rows and columns; see <table>.
