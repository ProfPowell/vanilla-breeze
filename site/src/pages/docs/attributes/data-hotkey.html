Overview

The data-hotkey attribute enhances native <kbd> elements with platform-aware key rendering. On Mac, modifier keys display as symbols; on other platforms, as text labels with + separators.

Ctrl+K

How It Works

  1. Reads the data-hotkey attribute value (e.g., "meta+k")
  2. Detects the user's platform (Mac vs. other)
  3. Maps modifier names to platform-appropriate symbols or labels
  4. Generates an aria-hidden <kbd> cap for each key in the combo
  5. Adds a visually hidden <span> with the spelled-out combo (for example "Command Shift P") for screen readers
  6. Replaces the element's content with the caps and the spoken text

Re-running the enhancement (for example after the element is moved) is a no-op. If data-hotkey has changed, the caps are rebuilt from scratch, never appended.

The original text content (e.g., "Ctrl+K") serves as a no-JS fallback. Nested <kbd> inside <kbd> is valid HTML for key combinations per the spec.

Attributes

Attribute Type Description
data-hotkey string Key combination string. Keys separated by +. Modifiers: meta (alias cmd), alt (alias option), shift, ctrl (alias control). Write the plus key as plus or as a trailing + (ctrl++).
data-label-key string Override the label and spoken name of one key, e.g. data-label-ctrl="Strg". Read from the element or any ancestor, so it can be set once on <html>. On Mac, modifier glyphs stay and only the spoken name changes.
data-hotkey-init string Set automatically to the rendered combo to prevent double-enhancement. Do not set manually.

Modifier Key Mapping

Modifier keys are automatically translated based on the user's platform:

Key name Mac Windows/Linux
meta, cmd ⌘ (spoken "Command") Ctrl (spoken "Control")
alt, option ⌥ (spoken "Option") Alt
shift ⇧ (spoken "Shift") Shift
ctrl, control ⌃ (spoken "Control") Ctrl (spoken "Control")

Named keys

Named keys get short labels on every platform:

Key name Shown Spoken
escape, escEscEscape
enter, returnEnterEnter
tab, space, backspace, home, endTab, Space, Backspace, Home, Endas shown

pageup / pagedownPgUp / PgDnPage up / Page down
arrowup (up), arrowdown, arrowleft, arrowright↑ ↓ ← →Up arrow, Down arrow, …
plus (or trailing +)+Plus

Any other key is displayed in uppercase (e.g., k becomes K).

Localised key names

Key names default to English. Override any of them with data-label-key on the element or an ancestor:

Dynamic Elements

Elements added to the DOM after page load are automatically enhanced via a MutationObserver. No manual initialization is needed.

// Dynamically added elements are auto-enhanced via MutationObserver const kbd = document.createElement('kbd'); kbd.dataset.hotkey = 'meta+n'; kbd.textContent = 'Ctrl+N'; document.body.appendChild(kbd); // kbd is enhanced automatically — no manual init needed

Action Binding

When data-hotkey is placed on a non-<kbd> element (button, input, details, etc.), it binds an actual keyboard shortcut that triggers an action on the element. This upscales the native accesskey attribute with cross-platform modifier normalization and conflict detection.

Action binding attributes

Attribute Value Description
data-hotkey-action string Action type: "click" (default), "focus", "submit", "toggle".
data-hotkey-label string Description for the shortcuts dialog. Defaults to element text content.
data-hotkey-group string Group name in shortcuts dialog. Default: "Page Actions".
data-hotkey-global boolean If present, fires even when typing in an input field.

Action types

Action Behavior Use Case
click Triggers .click() Buttons, links
focus Moves focus to element Search inputs
submit Submits closest form Save shortcuts
toggle Toggles open or hidden Panels, drawers

Shortcuts dialog integration

All hotkey-bound elements automatically appear in the <short-cuts> overlay (press ? to open). Add <short-cuts></short-cuts> once in your page to enable it.

Accessibility

  • The visible caps are aria-hidden; a visually hidden span carries the spelled-out combo ("Command Shift P"), because screen readers read the Mac glyphs inconsistently and aria-label is prohibited on <kbd> (generic role)
  • Uses semantic <kbd> elements which are recognized by assistive technology
  • Nested <kbd> inside <kbd> is valid HTML for key combinations per the spec
  • The original text content serves as a no-JS fallback
  • The caps keep left-to-right order in right-to-left pages
  • On Mac, separators between keys are omitted since the symbols are self-explanatory; on other platforms, + separators are included for clarity
