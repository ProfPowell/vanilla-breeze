Overview

The data-visible attribute controls element visibility based on viewport width. It eliminates the need for custom @media queries when toggling between desktop and mobile layouts.

  • data-visible="desktop" — visible at 48 rem and above, hidden below
  • data-visible="mobile" — visible below 48 rem, hidden at 48 rem and above

The breakpoint is --bp-m (48 rem, src/tokens/breakpoints.css), a typical tablet/desktop threshold. There are only these two values; for another breakpoint (a tablet tier at --bp-l, say) write your own @media rule.

How It Works

Two media queries set display: none !important on the opposite breakpoint:

@media screen and (width >= 48rem), print { [data-visible="mobile"] { display: none !important; } } @media screen and (width < 48rem) { [data-visible="desktop"] { display: none !important; } }

Works on any element — not just navigation. A hamburger button, a bottom nav, a sidebar, a CTA banner, or any content block can use data-visible.

It always wins

The rules sit in the lowest framework layer (reset, next to [hidden]) with !important. An important declaration in an earlier layer beats every normal declaration and every later layer's important ones, so a hidden variant stays hidden even on components that lock their own display (<content-swap>'s display: grid !important) and against your own unlayered display rules. To show the element, remove or change the attribute.

Viewport, not container

data-visible measures the viewport. Inside a narrow sidebar or card on a wide screen, mobile content stays hidden. For “narrow container” behaviour make the region a query container with data-container and write an @container rule.

In print

The queries are screen-only. Printed, the page box (about 42 rem on A4 or Letter) would otherwise pick the mobile variant, so print always shows the desktop variant and hides the mobile one. Use data-print-only / data-screen-only for content that differs between screen and paper.

Accessibility

  • Elements hidden with display: none are removed from the accessibility tree — screen readers will not announce them
  • Ensure equivalent content is available at both breakpoints; hiding a desktop nav is fine when a mobile nav provides the same links
  • Do not use data-visible to hide content that has no mobile equivalent — that would reduce accessibility on narrow screens
  • The hamburger button should include an aria-label since it typically contains only an icon
  • At 400% zoom a 1280 px desktop is about 20 rem wide, so zoomed-in users get the mobile variant. Keep the two variants equivalent so nothing is lost on reflow (WCAG 1.4.10)
