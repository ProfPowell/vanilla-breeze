Overview

The lang attribute declares the language of an element's content. Screen readers use it to pick a voice and pronunciation rules; browsers use it for hyphenation, quotation marks and font fallback; Vanilla Breeze uses it for script-specific typography and for formatting numbers and dates. It is inherited, so set it on <html> for the page and on any element whose language differs.

Applies to: every element (it is a global attribute).

She said the order shipped.

Sie sagte die Bestellung ist unterwegs.

Elle a dit la commande est partie.

彼女は注文は発送されましたと言いました。

Summe: €48,200.50, versandt am Nov 4, 2026

Die Donaudampfschifffahrtsgesellschaft veröffentlichte ihren Jahresbericht …

Values

A BCP 47 language tag: a language subtag, optionally followed by script, region and other subtags, separated by hyphens. Matching is case-insensitive.

ValueMeaning
en, fr, ja, ar…Language only.
en-GB, pt-BR, es-MX, fr-CALanguage and region. :lang(en) still matches en-GB.
zh-Hans, zh-Hant, sr-Latn, ja-LatnLanguage and script, e.g. Simplified or Traditional Chinese, or romanised Japanese.
"" (empty)The language is unknown. Screen readers fall back to their default voice.
AbsentInherited from the parent. With nothing set anywhere, the language comes from a Content-Language HTTP header if there is one, otherwise it is unknown.

Changes of language

Mark every passage, phrase or quotation in another language. Without it, a screen reader reads bonjour with English pronunciation.

The French word bonjour means "hello".

Die Grenzen meiner Sprache bedeuten die Grenzen meiner Welt.

A quotation inherits the language of its paragraph. Only set lang on the <q> when the quotation itself is in a different language.

Code

Code is not natural language. lang="" marks it as unknown language, which does not stop screen readers reading it; it only stops them applying the page language. To keep code out of machine translation, use translate="no".

Styling by language: q:lang()

:lang() matches an element's resolved language, including inherited lang, which [lang="…"] does not. Put it on the element you style: q:lang(fr), not :lang(fr) > q. The compound form also honours lang set on the <q> itself and on a <q lang="en"> nested inside Japanese text. VB already ships these rules (below), so you only need this for your own components.

q:lang(fr) { quotes: "\00AB\202F" "\202F\00BB" "\2039\202F" "\202F\203A"; } /* Override a VB script font instead of redeclaring font-family */ :root { --font-cjk: "Noto Sans JP", "Hiragino Sans", system-ui, sans-serif; }

In Vanilla Breeze

  • Script typography. :where(:lang(zh), :lang(ja), :lang(ko)) and the Arabic, Hebrew, Thai and Devanagari equivalents set font-family from --font-cjk, --font-arabic, --font-hebrew, --font-thai and --font-devanagari, plus line height and line-breaking rules. They have zero specificity, so element and component styles still win (src/native-elements/i18n/styles.css). Override the tokens to change fonts.
  • CJK inline semantics. In Chinese, Japanese and Korean, <em> becomes emphasis dots, and <i>, <cite>, <dfn>, <u> and <var> use script-appropriate substitutes instead of a synthesised italic. Romanised tags (ja-Latn) keep Latin styling. p.indent indents by one full-width character.
  • Quotation marks. <q> (and cite[data-variant="quoted"]) start from quotes: auto and pin marks for English, British English, German, Swiss German, French (with narrow no-break spaces), Italian, Spanish, Portuguese, Polish, Japanese, Simplified and Traditional Chinese, Korean, Russian and Arabic. See the table in the i18n guide.
  • Ruby. data-ruby="auto" shows annotations only when the <rt>'s own language is CJK.
  • Hyphenation. p.justify, article.blog and article[data-prose] set hyphens: auto, which only hyphenates when the browser knows the language (src/native-elements/paragraph/styles.css, article/styles.css).
  • Formatting uses the nearest lang. data-format-number, data-format-date and data-format-bytes resolve their locale as: the element's data-locale, then the nearest ancestor with lang, then <html lang>, then the browser language (src/lib/number-format.js, getLocale(el) in src/lib/i18n.js). Counts in data-select-all, data-paged and data-sortable, range values and the <video-player> use the same lookup, and data-sortable collates text in the container's language.

Accessibility

  • WCAG 3.1.1 Language of Page requires lang on <html>.
  • WCAG 3.1.2 Language of Parts requires lang on passages and phrases in another language. Proper names, technical terms and words that have become part of the surrounding language are exempt.
  • Use the right tag. An English page wrongly marked lang="fr" is read with French pronunciation throughout.

Gotchas

  • [lang] selectors miss inheritance. [lang="de"] q works, but q[lang="de"] misses quotes that inherit German. Use :lang().
  • Spell-check dictionaries. Browsers check spelling in the languages the user has configured. Do not rely on lang to switch the dictionary.
  • CJK glyph variants. The same character can look different in Chinese and Japanese fonts. The right lang lets the browser and VB's tokens pick the right face.
  • Hyphenation needs a dictionary. hyphens: auto does nothing for a language the browser has no hyphenation dictionary for.

Which to choose

  • lang — what language the content is in. Always.
  • data-locale — format one number or date in a different locale from its surrounding text, without claiming the text is in that language.
  • translate="no" — text that must not be translated, whatever its language.
