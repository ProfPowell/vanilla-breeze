Overview

The data-format-bytes attribute enhances native <data> elements by replacing their text content with a human-readable file size string. Uses binary math (÷1024) by default, with unit labels localised by Intl.NumberFormat (kB, MB, GB in English; ko, Mo, Go in French).

1 MB

How It Works

  1. Reads the value attribute from the <data> element and parses it as bytes. A missing, empty or non-numeric value leaves the text as written.
  2. Divides by 1024 (or 1000 for decimal) to find the best unit, from bytes up to petabytes
  3. Formats value and unit with Intl.NumberFormat's unit style, so digits, separators and unit labels follow the locale
  4. Replaces the text with the result (no title is added: the visible text is the size)
  5. Formats again whenever value, data-format-bytes, data-unit, data-locale or a lang attribute changes

Values below one byte stay in bytes (0.5 bytes), zero is 0 bytes, and negative values keep their sign (-1.5 MB), which suits size differences.

Attributes

Attribute Type Description
data-format-bytes string Decimal places for the formatted value, 0–20 (out-of-range values are clamped). Default "0" (no decimals). Use "1" or "2" for more detail.
value string The raw byte count. Standard HTML value attribute on <data>.
data-unit string "decimal" to use ÷1000 instead of ÷1024. Default is binary.
data-locale string Optional locale override (e.g., "de-DE"). Defaults to the nearest [lang], then <html lang>, then the browser locale.
data-format-bytes-init boolean State hook, set once the element is enhanced. Read it for styling or tests; do not set it. Enhancement is tracked internally, so a cloned element is still formatted when it is inserted.

Precision

The attribute value controls decimal places in the output:

1 MB 1.5 MB 5.00 GB

Binary vs. Decimal

By default, data-format-bytes uses binary math (÷1024), matching how most operating systems report file sizes. Add data-unit="decimal" to use ÷1000 (how storage manufacturers report capacity).

Both modes use the same labels. Intl has no binary units (KiB, MiB), so binary sizes are labelled kB, MB… the way file managers label them. If the distinction matters in your interface, say which one you use next to the figures.

Locale Override

Use data-locale (or a lang attribute on the element or an ancestor) to format number and unit in a specific locale:

1,5 MB 1,5 Mo

Common Use Cases

File List

Display file sizes in a table. The font-variant-numeric: tabular-nums CSS ensures columns align:

FileSize
photo.jpg 3.0 MB
document.pdf 512.0 kB
video.mp4 1.0 GB

Dynamic Elements

Elements added to the DOM after page load are automatically enhanced via a MutationObserver. No manual initialization is needed. Changing value (or any formatting attribute) re-formats the element, and a cloned element is formatted like a new one.

// Dynamically added elements are auto-enhanced via MutationObserver const el = document.createElement('data'); el.value = '2147483648'; el.dataset.formatBytes = '1'; el.textContent = '2.0 GB'; document.body.appendChild(el); // el is enhanced automatically — no manual init needed

Progressive Enhancement

The <data> element's original text serves as a fallback when JavaScript is unavailable. Write a reasonable pre-formatted value as the text content.

Accessibility

  • Unit labels are abbreviations; screen readers usually read "MB" as letters or "megabytes". Bytes use the long form ("512 bytes").
  • The semantic <data> element with value attribute provides machine-readable byte counts
  • Falls back to the original text content when JavaScript is unavailable
  • No wrapper element — the <data> is the enhanced element, keeping the accessibility tree clean

Related

  • <data> — the element this attribute enhances.
  • data-format-number — plain numbers, currency, percentages and compact notation. Use it for counts; use data-format-bytes for sizes.
  • data-format-date — the same locale-aware formatting for dates.
  • lang — the attribute the formatter reads for its locale when data-locale is not set.
