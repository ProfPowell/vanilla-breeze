Overview

The autocorrect attribute controls whether editable text is corrected automatically as the user types: misspelled words replaced, punctuation adjusted. What gets corrected, and how, depends on the browser and the device's text services (for example the replacements configured in macOS or a phone keyboard). Correction helps in prose and does damage in codes, usernames and identifiers.

Applies to: <input> (except password, email and url, which are never corrected), <textarea>, elements with contenteditable, and <form>, where it sets the default for the form's controls.

Values

ValueMeaning
on or "" (empty)Correction is enabled.
offCorrection is disabled.
Any other valueTreated as on.
AbsentA control inside a form uses the form's autocorrect if the form sets one. Otherwise correction is on.

Excluded input types: password, email and url are always off. Setting the attribute on them changes nothing.

Inheritance: only through the form owner. Controls without their own value (<input>, <textarea>, <select>, <button>, <fieldset>, <output>) take the value set on their <form>.

Examples

When to turn it off

Turn correction off wherever the value is not dictionary language:

  • usernames and handles (xKoder99)
  • product codes, invite codes, serial numbers (WX-4829-BLK)
  • CSS selectors, shell commands, file paths typed in a text field
  • domain-specific abbreviations and surnames

A whole form off, one field on

In Vanilla Breeze

  • No styles depend on it, and VB does not add it to authored fields.
  • <site-search> turns correction, capitalization and spellcheck off on the input it builds, so search terms are sent as typed (src/web-components/site-search/logic.js).

Accessibility

  • Leave it on for prose. Correction helps people with motor impairments or dyslexia produce accurate text with less effort.
  • Unwanted corrections are hard to notice. A changed username or code may only surface as a failed login. Turn correction off for exact values.
  • No effect on screen readers. The field is announced the same way.

Browser support

Baseline 2026, newly available since September 2026: Chrome 153, Edge 153, Firefox 136, Safari 14.1 (iOS 14.5). It is defined in the WHATWG HTML standard. Older Chrome and Firefox versions ignore the attribute and leave correction to the operating system.

Gotchas

  • The device decides what "correction" means. With on, nothing may happen if the OS offers no replacements.
  • All or nothing per field. You cannot protect some words while correcting others.
  • It does not affect spell-check underlines. Use spellcheck="false" for those.

Related

Which to choose

  • autocorrect="off" — the value must be kept exactly as typed.
  • spellcheck="false" — the value is not prose and the underlines are noise.
  • Both, plus autocapitalize="none" — usernames, codes and identifiers.
