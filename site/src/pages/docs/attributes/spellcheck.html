Overview

The spellcheck attribute says whether the browser may check an element's editable text for spelling mistakes. When checking is on, misspelled words get a wavy underline and the context menu offers suggestions. It is a hint: browsers are not required to check, and most do not check text that is not editable.

Applies to: every element (it is a global attribute). It has a visible effect on <input> text fields, <textarea> and contenteditable regions, and it is inherited, so you can set it on a form or container.

Values

ValueMeaning
true or "" (empty)Check spelling where the browser can.
falseDo not check spelling.
Absent or any other valueDefault: inherited from the nearest ancestor that sets it. With no such ancestor the browser decides; text areas and contenteditable are usually checked, single-line inputs vary by browser.

Examples

When to turn it off

  • code editors and fields that take CSS, HTML or commands
  • usernames, product codes, serial numbers, API keys
  • fields that may hold sensitive data, because some browsers' enhanced spell-checking sends text to a server

Set once, override per field

Editable regions

In Vanilla Breeze

  • No styles depend on it. The underline and suggestions are drawn by the browser and cannot be styled with the attribute.
  • Components set it for you:
    • <markdown-editor> turns spell-checking on for its textarea unless you set spellcheck yourself (src/web-components/markdown-editor/logic.js).
    • <emoji-picker>, <color-picker> and <site-search> turn it off on their inputs, where words are search terms or colour values.
  • The <u> element looks like a spelling mark. VB styles <u> with a red wavy underline, the convention for flagged words, so you can show a misspelling in static text (src/native-elements/inline-semantics/styles.css). In Chinese, Japanese and Korean text <u> is a plain proper-name underline instead.
  • No data-spellcheck. VB adds nothing on top of the native attribute.

Accessibility

  • Leave it on for prose. Spell-checking helps everyone, including people with dyslexia, catch mistakes before they submit.
  • Underlines are visual. Screen readers do not announce flagged words as you type; some can list them on request.
  • Do not turn it off page-wide. Turn it off only on fields that do not hold prose.

Security

The spec does not say how spell-checking is done. Some browsers offer an "enhanced" mode that sends field contents to a cloud service. Set spellcheck="false" on fields that may contain secrets, personal identifiers or medical details. Password fields are not checked.

Gotchas

  • The dictionary is the user's. Browsers check against the languages the user has configured. Setting lang on a field is still right for screen readers and hyphenation, but do not count on it to switch the spell-check dictionary.
  • Timing varies. Some browsers only mark words after the field has been focused or edited.
  • No script access. You cannot read which words are flagged or add words to the dictionary.

Which to choose

  • spellcheck="false" — hides underlines on text that is not prose.
  • autocorrect="off" — stops the text being changed. Use both for identifiers.
  • <u> — shows a spelling mistake in static text, such as a proofreading example.
