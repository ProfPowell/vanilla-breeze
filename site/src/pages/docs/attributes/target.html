Overview

The target attribute names the browsing context (tab, window or frame) where a navigation happens: following a link or showing a form's response. It takes a keyword or any name you choose; a named context is reused if it exists and created otherwise.

Applies to: <a>, <area>, <form> and <base> (page-wide default). Submit buttons can override a form's target with formtarget.

The chapter links load into the iframe named reader, and the page inside reports that name through window.name. The last link opens a new tab, where window.opener is null.

Values

ValueOpens in
_selfThe current browsing context. The default when target is absent or empty (unless <base target> sets another default).
_blankA new, unnamed tab or window. Implies rel="noopener".
_parentThe parent frame; _self if there is none.
_topThe top-level page, leaving all frames; _self if not framed.
nameThe frame or window with that name (an iframe's name, or a window opened with that name). A new tab if none exists.

Keywords are case-insensitive. Other names starting with _ are reserved; do not use them for your own windows or frames.

In Vanilla Breeze

  • noopener made explicit. Any page with an a[target="_blank"] loads src/utils/links-init.js, which adds rel="noopener" to such links that declare no opener policy (and noreferrer as well under <html data-link-privacy="strict">).
  • No new-tab styling. VB does not style [target="_blank"]. Its automatic arrow marks external links (a[href^="http"] and rel~="external", in src/native-elements/anchor/styles.css and src/utils/links.css), whatever their target. An <icon-wc> inside the link replaces the arrow.
  • <image-map> honours target="_blank" on its areas and opens them with noopener.

Accessibility

  • New tabs break the Back button and can disorient screen-reader and low-vision users. Use _blank only with a reason (leaving would lose work, or the link is to a reference the user will come back from).
  • Say that a link opens a new tab, in visible text or visually hidden text. A tooltip or icon alone is not enough (WCAG 3.2.5 recommends warning of context changes).
  • Avoid <base target="_blank">: it turns every link on the page into a new tab.

Security

  • target="_blank" no longer exposes window.opener in any current browser. Add rel="noopener" only for clarity; add noreferrer if you also want to hide your URL (a privacy choice). See rel.
  • window.open(url, '_blank') is not covered by the implicit rule; pass 'noopener' as the third argument.
  • Named targets can be reused by other pages that know the name. Do not rely on a name to keep content private.

Gotchas

  • Sandboxed frames. _top needs allow-top-navigation or, better, allow-top-navigation-by-user-activation; _blank needs allow-popups. Navigating a non-top parent is blocked from a sandboxed frame.
  • Popup blockers may stop _blank navigations that do not come from a user gesture.
  • Named windows persist. Later links with the same name reuse a window the user may have forgotten about.
  • Mobile. _blank opens a tab, not a window; named targets reuse tabs inconsistently across mobile browsers.

Which to choose

  • Most links — no target; let users choose with middle-click or a long press.
  • Leaving would lose work — _blank, announced in the link text.
  • Master/detail inside one page — a named iframe, or fetch the content into the page instead.
  • An overlay instead of a new page — a <dialog> opened with commandfor.
