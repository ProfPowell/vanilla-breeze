Overview

The autofocus attribute moves keyboard focus to an element without the user doing anything. On a page it acts once, when the page loads. Inside a <dialog> or a popover it acts each time the dialog or popover opens. It is a boolean attribute.

Applies to: every element (it is a global attribute). It only has an effect on an element that can be focused: form controls, links, buttons, <summary>, contenteditable regions, elements with tabindex, and the <dialog> itself.

Values

ValueMeaning
Present (autofocus, autofocus="")Focus this element when its scope appears: page load, dialog open or popover open.
AbsentNo automatic focus. The default.

More than one: each scope (the document, each dialog, each popover) should have at most one. If several elements carry it, the first focusable one in tree order receives focus.

Not re-run: adding the attribute later with script does nothing until the scope opens again. Call element.focus() instead.

Examples

Dialogs

showModal() and show() focus the dialog's autofocus element. Without one, the browser focuses the first focusable element inside the dialog. Choose the starting point deliberately:

  • a confirmation: the least destructive action (Cancel);
  • a form: the first field the user will edit;
  • long or dynamic content, where the first focusable element might sit below the fold: put autofocus on the <dialog> itself, so screen readers start at the top.

Popovers

A popover moves focus only when it, or something inside it, has autofocus. There is no first-focusable fallback as there is for dialogs.

Page load

Use it on page load only when entering text is the whole point of the page, as on a dedicated search or sign-in page.

In Vanilla Breeze

  • data-focus-trap moves focus into the trapped region when it activates: to its [autofocus] element if there is one, otherwise to the first focusable child. data-focus-trap="no-autofocus" traps Tab without moving focus (src/utils/focus-trap-init.js).
  • <content-swap> focuses the [autofocus] element on the face it swaps to (src/web-components/content-swap/logic.js).
  • <chat-input autofocus> focuses its textarea when it connects (src/web-components/chat-input/logic.js).
  • Untrusted HTML loses it. VB's sanitizer removes autofocus from untrusted content so injected markup cannot steal focus (src/lib/sanitize-html.js). Trusted fragments keep it.
  • Invokers need no script. commandfor / command="show-modal" opens the dialog, and the dialog's own focusing steps honour autofocus.

Accessibility

  • It skips content. Screen readers jump to the focused element and announce its label, but not the headings or instructions before it. Sighted users on small screens can miss the same context.
  • It can open the keyboard. On touch devices, focusing a text field may open the virtual keyboard and cover half the screen.
  • Dialogs are the right place. The user just asked for the dialog and expects to act in it.
  • A fragment link wins. If the URL has a fragment that matches an element, that element gets focus on load instead of the autofocus element.

Browser support

On form controls, supported everywhere for many years. As a global attribute on any focusable element: Baseline since 2023 (Chrome 79, Firefox 110, Safari 15.4).

Gotchas

  • The first one wins. A second autofocus in the same scope is ignored, and the spec makes it a conformance error.
  • It scrolls. An autofocused element below the fold scrolls into view. If you need focus without scrolling, use element.focus({ preventScroll: true }).
  • Back/forward navigation. Browsers may restore the previous focus or scroll position instead of honouring autofocus.
  • Inside an iframe, browsers limit autofocus in cross-origin frames.

Which to choose

  • autofocus — the starting point inside a dialog or popover, or a single-purpose page.
  • element.focus() — focus after something happens on the page (a row deleted, a route changed).
  • data-focus-trap — an inline panel that must keep focus until it closes, then hand it back.
