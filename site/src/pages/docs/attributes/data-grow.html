Overview

The data-grow attribute makes a textarea automatically expand its height as the user types. It uses the modern CSS field-sizing: content property where supported, falling back to JavaScript scrollHeight measurement for older browsers.

How It Works

Add data-grow to any <textarea>. The CSS does the work where it can; the init script passes rows and data-max-rows to it as --grow-rows and --grow-max-rows, and runs a measuring fallback where it cannot.

Modern Browsers (CSS field-sizing)

  1. CSS sets field-sizing: content and resize: none
  2. The minimum height is rows lines plus padding and border. field-sizing ignores rows, and VB's usual 8rem textarea minimum does not apply to data-grow
  3. With data-max-rows, max-block-size is that many lines plus padding and border. Past it the textarea stops growing and scrolls (overflow-y: auto)

Fallback (JavaScript scrollHeight)

  1. Marks the textarea data-grow-init="fallback"; only this path hides overflow
  2. On each input and change event, and after a form reset, resets height to auto then sets it to scrollHeight plus the border
  3. If data-max-rows is set, caps growth at that many lines plus padding and border
  4. Switches to overflow-y: auto when content exceeds the max height

data-grow-init is set in both cases to prevent double-binding (empty on the CSS path, "fallback" on the JS path).

Attributes

Attribute Type Description
data-grow boolean Enables auto-grow behavior on a textarea.
data-max-rows number Maximum number of rows the textarea can grow to. After this, the textarea scrolls.
rows number Standard HTML attribute. Sets the minimum number of visible rows (default 2). The textarea never shrinks below this.
data-grow-init boolean Set automatically to prevent double-binding: empty on the CSS path, "fallback" on the JS path. Do not set manually.

Basic Auto-Grow

Without data-max-rows, the textarea grows indefinitely to fit its content. The rows attribute sets the initial minimum height.

Max Rows

Set data-max-rows to cap the textarea height. Once it reaches this height, the textarea stops growing and the content scrolls instead.

Min and Max Rows

Combine rows (minimum) and data-max-rows (maximum) to define a growth range. The textarea starts at the minimum and grows up to the maximum.

Combined with data-count

Use data-grow alongside data-count for a textarea that grows while showing a live character or word count. Both attributes work independently on the same element.

In a Form

Auto-grow textareas work seamlessly in forms. The textarea submits its value normally regardless of its visual height.

Shrinking Behavior

The textarea shrinks back down when content is removed. It never shrinks below the initial rows height:

  • CSS field-sizing — the browser handles shrinking automatically based on content
  • JS fallback — on each input event, the height resets to auto before measuring scrollHeight, allowing the textarea to shrink

Events

No custom events are dispatched. The textarea fires standard input and change events. You can observe height changes by reading scrollHeight or style.height on the textarea.

Setting .value from script fires no event. With field-sizing the height follows anyway; for the JS fallback (and for a data-count counter on the same textarea) dispatch an input event afterwards. Form resets are handled automatically.

textarea.value = savedDraft; textarea.dispatchEvent(new Event('input', { bubbles: true })); const textarea = document.querySelector('[data-grow]'); // The textarea fires standard events — no custom events needed textarea.addEventListener('input', () => { console.log('Height:', textarea.style.height || 'auto (CSS field-sizing)'); console.log('Scroll height:', textarea.scrollHeight); });

Styling

The sizing rules key on [data-grow] itself, so a supporting browser grows the textarea even before the script runs. Without JavaScript the minimum falls back to two rows, and without field-sizing support the textarea keeps its rows height and its resize handle.

/* native-elements/input/styles.css: start at rows, not 8rem */ textarea[data-grow] { min-block-size: calc( var(--grow-rows, 2) * 1lh + 2 * var(--input-padding-inline, 0.5rem) + 2 * var(--border-width-thin, 1px) ); } /* web-components/_shared/form-enhancements.css */ @supports (field-sizing: content) { textarea[data-grow] { field-sizing: content; resize: none; } textarea[data-grow][data-max-rows] { max-block-size: calc( var(--grow-max-rows, 999) * 1lh + 2 * var(--input-padding-inline, 0.5rem) + 2 * var(--border-width-thin, 1px) ); overflow-y: auto; } } /* JS fallback only: hide the scrollbar while measuring */ textarea[data-grow][data-grow-init="fallback"] { overflow: hidden; resize: none; }

Dynamic Elements

Textareas added to the DOM after page load are automatically enhanced via a MutationObserver. No manual initialization is needed.

// Dynamically added textareas are auto-enhanced via MutationObserver const textarea = document.createElement('textarea'); textarea.dataset.grow = ''; textarea.dataset.maxRows = '8'; textarea.rows = 2; document.querySelector('form-field').appendChild(textarea); // textarea auto-grows immediately — no manual init needed

Accessibility

  • Content remains fully accessible — the textarea grows to show all text, reducing the need for scrolling
  • No manual resize is needed — the textarea adapts to content automatically, improving usability for all users
  • The native <textarea> element is preserved, maintaining full screen reader and keyboard support
  • rows sets a visible minimum, ensuring the textarea is never unexpectedly small
  • When data-max-rows caps growth, overflow-y: auto enables scrolling with standard scroll accessibility
  • Without JavaScript, the textarea still grows where field-sizing is supported; elsewhere it renders at its rows height with the native resize handle
