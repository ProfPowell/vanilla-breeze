Overview

The data-layout attribute applies one of VB's named layout primitives to any element. It's the attribute form of the <layout-*> custom-element family — same engine, better semantics. Use <article data-layout="stack"> when the element you already have is the right semantic container; use <layout-stack> when you need a generic wrapper.

This page is the complete reference: every value, every data-layout-* modifier with its per-layout meaning, and the general-purpose layout attributes. The tables are generated from the layout CSS at build time, so they list exactly what the stylesheets implement.

Whole-page templates on <body> are a separate attribute, data-page-layout. data-layout is for components inside the page.

Usage

Put the value on the element you want to lay out; modifiers (data-layout-gap, data-layout-align, …) tune it without changing its kind.

Page templates

Holy-grail, dashboard, app-shell, sidebar and landing page templates are data-page-layout values on <body>; they are not data-layout values. Inside the page, use data-layout on the regions (for example <main data-layout="sidebar-right">).

Attribute-only layouts

split

Two columns, equal by default (gap xl, vertically centered). data-layout-ratio takes 2:1, 1:2, 3:1, 1:3 or golden; data-layout-fill makes it at least the viewport height. Stacks below a 48rem viewport unless data-layout-nowrap is set. The demo at the top of this page includes ratio and golden splits.

media

The media object: a figure, img, picture or video child (or any child with slot="figure") goes in the figure column, sized to the figure, and spans the content rows. Every other child gets its own row in the content column, in DOM order; the last row takes up the slack when the figure is taller. Up to five content children are laid out this way; more still don't overlap, but the figure stops spanning them, so wrap long content in a section. data-layout-reverse puts the figure on the end side. Stacks (figure on top, also when reversed) when its nearest query container is under 25rem.

regions

Header, content and footer rows on any element, with no visual styling: a component layout for cards, articles and panels. header, section and footer children (or slot="header|content|footer") are placed by type: it is a flex column with the header first and the footer last, whatever their DOM position, and every other child in between in DOM order. A section (or slot="content") grows to fill the free space; with no section, the footer is pushed to the bottom instead, so equal-height cards keep their footers aligned. Visual order only: keep header and footer in reading order in the DOM.

page-stack

A full-height (100dvh) column whose direct <main> child grows, so the footer sits at the bottom on short content. No modifiers. Because <main> may only sit in <body> (or a div, form or custom element), this is the one data-layout value that normally goes on <body>. It is the minimal sticky-footer shape; for named page regions (nav, aside, sidebars) use data-page-layout instead.

sidebar-left / sidebar-right on main

On <main> only: a nav (left) or aside (right) sits beside the article; without that element it is one column. The sidebar column is 16rem (data-layout-sidebar-width: 12 / 16 / 20rem), the gap m. Below a 48rem viewport it stacks in the order article, aside, nav unless data-layout-nowrap is set. For a sidebar anywhere else, use data-layout="sidebar".

Nested layouts

Modifiers apply only to the element they are on. Every layout host resets its private tokens, so a layout nested inside another starts from its own defaults: a bare data-layout="grid" inside a data-layout-gap="3xl" grid gets the default m gap, not 3xl. The --layout-min / --layout-threshold / --layout-content-min escape hatches don't inherit either.

Responsive behaviour

Most layouts respond to the space they are given, not to the viewport, so the same markup works in a sidebar or a full-width column:

  • Container / intrinsic: cluster and grid wrap by content; sidebar wraps when its content column would fall below data-layout-content-min; switcher flips at data-layout-threshold; columns drops columns; prose releases its measure in containers under 30rem; media stacks in containers under 25rem.
  • Viewport: split and main sidebar-left/right stack below 48rem (as do the data-page-layout templates). data-layout-nowrap opts out.

Under data-fluid the --size-* tokens are fluid, so data-layout-gap and data-layout-padding scale with the viewport; the breakpoints above stay fixed. See Fluid scaling.

Element vs attribute — pick what fits

Both forms feed the same rules and accept the same modifiers. Pick by the markup you already have:

  • Use data-layout when you already have a semantic element that should also be the layout container (<article>, <section>, <nav>, <ul>, <form>).
  • Use <layout-stack> / <layout-grid> / etc. when you need a generic wrapper purely for layout. See custom elements for the full family.

One difference: main, article, section and aside are container-type: inline-size query containers, whichever form they appear in. As children of content-sized layouts (cluster, reel, centered cover, a stack aligned start/center/end) they drop container-type so they don't collapse to zero width; add data-container (and an explicit width) to keep one as a query container. The Semantic Layouts guide walks through the attribute form in depth.

Accessibility

  • Visual order vs reading order. data-layout-order, data-layout-reverse (media, switcher) and the mobile collapse of main sidebar-left/right (article, then aside, then nav) change only the visual order. Screen readers and keyboard focus follow the DOM. Keep the DOM in a sensible reading order and use these only when the visual change is presentational (WCAG 1.3.2 Meaningful Sequence, 2.4.3 Focus Order). On sidebar-left, a DOM-first nav is shown last on small screens: give it a skip link or a clear heading.
  • Scroll regions. A reel whose items aren't focusable can't be scrolled with the keyboard. Add tabindex="0" and a name (<section data-layout="reel" aria-label="…" tabindex="0">).
  • Landmarks. data-layout changes no semantics. A <section> is a region landmark only when it has an accessible name (aria-labelledby); a <header> inside an article is not a banner.
  • Sticky regions. data-layout-sticky sidebars scroll on their own; their content stays in the tab order.
