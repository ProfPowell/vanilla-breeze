Overview

data-upload wraps a native <input type="file"> in a drop zone that lists the chosen files by name and size. The input stays the real control: it is stretched transparently over the zone, so a click anywhere opens the file picker, it keeps the only tab stop, and it submits with the form.

Dropped files follow the same rules as the picker: the native accept attribute filters them and, without multiple, only the first file is kept. Anything left out is announced in a status line.

Usage

After setup the input sits inside this structure (the script builds it; you do not write it):

Drag a file here or browse PDF, DOC, DOCX

    Options

    AttributeValuesDefaultEffect
    data-uploadboolean—Builds the drop zone around the file input.
    acceptnative: .ext, type/*, type/subtypeany fileFilters the picker and dropped files. Shown under the prompt (".pdf,.doc" reads "PDF, DOC"). Matching is case-insensitive.
    multiplenative booleanoffAllows several files. Without it a drop keeps only the first accepted file. Also switches the default prompt to "Drag files here or".
    data-label-promptstring"Drag a file here or" / "Drag files here or"Prompt text before the browse cue.
    data-label-browsestring"browse"The underlined browse cue.
    data-label-filesstring"Selected files"Accessible name of the file list.
    data-label-rejectedstring, {files}"Not accepted: {files}"Status text when dropped files do not match accept.
    data-label-singlestring, {file}"Only one file allowed. Kept {file}."Status text when several files are dropped on an input without multiple.

    The data-label-* attributes go on the input. File sizes are formatted with Intl.NumberFormat in the language of the closest [lang], using decimal units (1 kB = 1000 bytes).

    Behaviour

    • Selection replaces — each pick or drop replaces the previous selection, as the native input does. A drop where every file is rejected leaves the current selection alone.
    • Drag state — data-dragover is set on .upload-zone while files are dragged over it.
    • Reset — a form reset empties the file list and the status line.
    • Disabled — a disabled input ignores drops and the zone is dimmed.
    • No size or count limits — the script does not check file size or count. Enforce limits in your own change handler (with setCustomValidity) and on the server. accept is a hint the user can bypass; always validate type on the server too.

    Events

    No custom events. Picking files fires the native input and change events; a drop that accepts at least one file fires both too, after updating input.files.

    const input = document.querySelector('#resume'); input.addEventListener('change', () => { for (const file of input.files) { console.log(file.name, file.size, file.type); } });

    Styling

    No custom properties. Style the generated classes; these are the shipped rules that matter most:

    .upload-zone { border: 2px dashed var(--control-border, var(--color-border-strong)); border-radius: var(--radius-m); padding: var(--size-l); } .upload-zone:hover, .upload-zone[data-dragover] { border-color: var(--color-interactive); } .upload-zone[data-dragover] { background: color-mix(in oklab, var(--color-interactive) 5%, transparent); } /* The transparent input cannot show focus, so the zone does */ .upload-zone:has(input[type="file"]:focus-visible) { outline: var(--focus-ring-width, 2px) solid var(--focus-ring-color, var(--color-interactive)); outline-offset: var(--focus-ring-offset, 2px); } .upload-browse { color: var(--color-interactive); text-decoration: underline; } .upload-status { color: var(--color-error-text); }

    Other hooks: .upload-prompt (and its small), .upload-file-list li, .upload-file-name, .upload-file-size. In forced-colours mode the focus outline and the drag border use Highlight.

    Accessibility

    • The native file input is the only control and the only tab stop. Its <label> names it; give it a visible one.
    • Keyboard focus on the input draws an outline around the whole zone. Enter or Space opens the picker, as on any file input.
    • The prompt, including the accepted types, is linked to the input with aria-describedby.
    • The browse cue is plain text, not a second button.
    • Rejected and dropped-extra files are announced through the role="status" line, which is also visible.
    • The file list is a labelled <ul> ("Selected files").
    • Drag and drop is never required: everything a drop does, the picker does too.
    • Without JavaScript the native file input renders as normal.
