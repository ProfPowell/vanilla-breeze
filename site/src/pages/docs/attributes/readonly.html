Overview

readonly is a boolean attribute that stops the user from changing a field's value. Unlike disabled, the field stays in the tab order, its text can be selected and copied, and its value is submitted with the form. Use it for values the user should see and send but not edit: order numbers, computed totals, a confirmed email address.

Applies to: <textarea> and <input> of type text, search, url, tel, email, password, number, date, month, week, time and datetime-local. It has no effect on <select>, checkboxes, radios, range, color, file or buttons.

Submitting that form sends order and total but not region.

Values

Boolean: present means read-only. readonly="false" is still read-only; remove the attribute or set el.readOnly = false (capital O).

Examples

Styling read-only fields yourself

:read-only matches every element the user can't edit, including checkboxes, radios, range sliders and plain paragraphs. Scope it to text-like fields, as VB does.

:is(input:not([type="checkbox"], [type="radio"], [type="range"], [type="color"], [type="file"]), textarea):read-only:not(:disabled) { background: var(--input-readonly-bg); border-style: var(--input-readonly-border-style); }

In VB you rarely need this: set the two tokens instead (see below).

Locking a select, checkbox or radio

These controls ignore readonly. Show the value as text, or disable the control and carry the value in a hidden input.

In Vanilla Breeze

  • Styling. Text fields and textareas that are :read-only (and not disabled, and not a select) get --input-readonly-bg as their fill and --input-readonly-border-style as their border style (src/native-elements/input/styles.css). The dashed border is the non-colour cue that the field isn't open for editing.
  • Tokens (src/tokens/forms.css): --input-readonly-bg defaults to var(--color-surface-raised), --input-readonly-border-style to dashed. Themes override the tokens, not the selector.
  • data-stepper disables its +/− buttons while the input is read-only.
  • data-autosave never restores a saved draft into a read-only field, so a server-provided value wins.
  • data-switch is a checkbox, so readonly does not stop it toggling. Use disabled.

Accessibility

  • Screen readers announce read-only fields as "read only" and still read the value. Because the field is focusable, keyboard users can review it in context.
  • If the field is read-only because of permissions, say so in a hint (<output class="hint" for> inside <form-field>), for example "Managed by your administrator".
  • Don't make a field read-only just to show a value. If nothing is submitted, plain text or a <output> is simpler and isn't a tab stop.

Gotchas

  • required, pattern and the other constraints are ignored on read-only fields, because they are barred from validation.
  • The value can still be changed with devtools or by script. Never trust a read-only value on the server; recompute totals and look up IDs again.
  • <select readonly> is not an error in the browser but does nothing; the user can still change it.

Related

  • disabled — off, not focusable, not submitted
  • required — ignored on read-only fields
  • <input>, <textarea>, <output>

Which to choose

  • readonly — the value is fixed, must be submitted, and the user may want to select or copy it.
  • disabled — the control does not apply and its value must not be sent.
  • <output> or text — the value is only for display.
