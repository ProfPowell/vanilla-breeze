Overview

The download attribute tells the browser to save the linked resource rather than display it. Without it, the browser decides by content type: PDFs open in a viewer, images display, HTML navigates. With a value, it also suggests the file name; the user can still change it in the save dialog.

Applies to: <a> and <area> with an href.

"Download CSV" is a data: URL with download="team-contacts.csv". "Export as JSON" builds a Blob from the table and downloads it through a temporary link. VB adds the ↓ after links that have download.

Values

ValueBehaviour
download or download=""Save the file; the name comes from the Content-Disposition header, the URL path or the content type.
download="name.ext"Save the file and suggest this name. Path separators and characters the OS forbids are replaced.

A filename in the server's Content-Disposition header takes precedence over the attribute's value.

In Vanilla Breeze

  • Download glyph. a[download] gets a trailing ↓ (src/native-elements/anchor/styles.css), with empty alt text so screen readers skip it. It is suppressed in nav, header and footer, on a.button, when the link contains an <icon-wc>, and with data-no-icon. A download link to a PDF keeps the arrow instead of the "PDF" badge.
  • File rows. [data-file] (src/utils/file-display.css) lays out an icon, name, size and download link; see the files pattern.
  • Components that download. <theme-picker> adds per-theme design-token download links, and the chart service behind <chart-wc> has a download() export that uses the Blob technique above.

Accessibility

  • Say what the user gets: format and size in the link text ("Annual report (PDF, 2.4 MB)"). The ↓ glyph is decorative.
  • A download gives no in-page feedback. For generated files, confirm in the page (a status message) as well.

Security

  • Cross-origin URLs ignore download and navigate instead (Chrome since 65, Firefox and Safari likewise), so a page cannot rename and save another site's file. Same-origin, blob: and data: URLs are honoured. To force a download from another origin, that server must send Content-Disposition: attachment.
  • Browsers may warn about or block executable file types regardless of the attribute.
  • Sandboxed iframes cannot download without allow-downloads. See sandbox.

Gotchas

  • Mobile. Some mobile browsers open the file in a viewer even with download.
  • No progress events. The page cannot tell when or whether the download finished.
  • Large data: URLs are slow and size-limited; use a Blob for anything beyond a few kilobytes.

Related

  • target — where a navigation opens; download replaces the navigation.
  • sandbox — allow-downloads.

  • data-upload — the other direction: file uploads.

Which to choose

  • A file on your site — <a download>, inside a [data-file] row for lists.
  • Data built in the page — a Blob and a temporary download link.
  • A file on another origin — Content-Disposition: attachment on that server; the attribute will not help.
