Overview

enterkeyhint chooses what the Enter key on a virtual keyboard says: "Next" between fields, "Search" in a search box, "Send" in a chat box. It is a label only. Pressing Enter still does what it always does: submit a one-line form, insert a line break in a textarea, or whatever your script handles.

Applies to: any editable element: <input>, <textarea> and elements with contenteditable. It is a global attribute.

Values

ValueKey showsUse when Enter will…
enterThe generic Enter / Returninsert a new line or has no special meaning.

goGotake the user somewhere (an address bar).

previousPreviousmove to the previous field.
searchSearchrun a search.
sendSendsend a message.
Absent or invalidThe browser's choice from the field type and form—

Some keyboards show an icon (an arrow, a magnifier) instead of a word.

Examples

Search box

Enter to send in a textarea

In a textarea Enter inserts a line break, so send is only honest if your script intercepts Enter. Skip the key while an input method editor (IME) is composing text, or Chinese, Japanese and Korean users send half-typed messages when they press Enter to confirm a character.

const box = document.querySelector('#message'); box.addEventListener('keydown', (event) => { if (event.key !== 'Enter' || event.shiftKey) return; // Enter that confirms an IME composition must not send. if (event.isComposing || event.keyCode === 229) return; event.preventDefault(); box.form.requestSubmit(); });

The keyCode === 229 check covers browsers that fire the confirming keydown just after composition has ended. In VB you don't need this script: <chat-input> does exactly this.

In Vanilla Breeze

  • VB has no styling for enterkeyhint; it only affects the virtual keyboard.
  • <chat-input> sends on Enter, adds a line on Shift+Enter, and ignores Enter during IME composition (src/web-components/chat-input/logic.js).
  • In a data-wizard form, Enter in a text field on any step but the last moves to the next step instead of submitting, so enterkeyhint="next" matches what happens there; use done on the last step.

Accessibility

  • A label that matches the action helps everyone predict what Enter will do, and is especially useful to people who rely on the keyboard's cues rather than scanning the page for a button.
  • Never let the label lie. "Send" on a textarea that inserts a newline, or "Next" on the last field, confuses more than the default would.
  • Keep a visible submit button. Enter is a shortcut, not the only way to submit.

Browser support

Baseline 2021: Chrome 77, Firefox 94, Safari 13.1. Only virtual keyboards show the label; on a desktop with a physical keyboard nothing changes, and Android keyboard apps may ignore it.

Gotchas

  • It changes no behaviour. enterkeyhint="next" does not move focus; browsers that offer next/previous do that themselves, or you handle Enter in script.
  • Implicit submission still applies: Enter in a text input submits the form if it has a submit button or only one single-line text field.
  • Avoid non-enter hints on multi-line fields unless you intercept Enter.

Which to choose

  • enterkeyhint — any field where Enter has a clear action.
  • <chat-input> — a message box where Enter sends; it brings the key handling and the IME guard.
  • Default — textareas where Enter means "new line".
