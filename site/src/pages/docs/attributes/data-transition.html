Overview

data-transition marks elements that take part in View Transitions when content changes in place. VB gives each marked element an inline view-transition-name and, for the presets, a view-transition-class, so the browser animates it during any view transition on the page: a VB.swap() call, a component's own transition, or a cross-page navigation.

Unlike data-effect (ambient animation on scroll, hover or load), data-transition describes state changes: a swapped panel, a reordered list, a card opening into a detail view.

Three attributes share the View Transitions work:

AttributeUse it forName it sets
data-transitionSame-document changes with a preset animationGenerated per element: preset-id or uid
data-vt-nameA shared element you name yourself (the same name on the thumbnail and on the detail image, or across pages)Exactly the value you give
data-vt + data-vt-classCross-page (MPA) transitions with the opt-in view-transitions.cssFixed region names (main-content, header, …)

For transitions between pages, see View Transitions, which also owns the browser support table.

Usage

Put a preset on the element, then change the DOM inside VB.swap().

Ship small, ship often.

What the runtime does:

  1. Finds every [data-transition] element, including ones added later, and calls the handler registered for its value.
  2. The handler sets view-transition-name (built from the element's id when it has one, otherwise a generated uid) and the preset's view-transition-class as inline styles.
  3. When the element is removed, or the attribute changes or is removed, the handler's cleanup clears what it set, and a new value is applied.

VB.swap()

Wraps a DOM update in document.startViewTransition(). Without browser support the update runs immediately and nothing errors. It returns the ViewTransition, or undefined when unsupported.

VB.swap(() => { // DOM mutations here: the browser captures before/after snapshots document.querySelector('main').replaceChildren(...newNodes); });

Events

data-transition fires no events of its own. Use the ViewTransition returned by VB.swap(): updateCallbackDone resolves when the new DOM is in place (move focus or announce here), finished when the animation ends.

const vt = VB.swap(() => renderPage(next)); await vt?.updateCallbackDone; document.querySelector('main h1').focus();

With effect:class, descendants with data-trigger="vt" receive vb:vt-update-done when the update commits.

Styling

The presets are plain ::view-transition-* rules in utils/vt-keyframes.css, which ships in every CSS bundle. You do not need view-transitions.css for them; that file only opts the site into cross-page transitions.

Custom property (on :root)DefaultControls
--view-transition-duration0.3sDuration of the slide, fade and scale presets.
--view-transition-stagger40msDelay between rungs of the stagger ladder.

Set them on :root: the ::view-transition pseudo-element tree hangs off the document element and inherits from it, not from the element that carries data-transition.

:root { --view-transition-duration: 0.45s; --view-transition-stagger: 60ms; } /* Your own class, used by a custom handler */ ::view-transition-old(*.flip) { animation: my-flip-out 0.4s ease-in both; } ::view-transition-new(*.flip) { animation: my-flip-in 0.4s ease-out both; }

Accessibility

  • Reduced motion. Under prefers-reduced-motion: reduce, or VB's own setting (data-motion-reduced on the root, set by the settings panel), every view transition runs with a near-zero duration and no stagger delay: the change is instant. Large sliding and scaling motion is a vestibular trigger, so do not override this.
  • Transitions are not announcements. The animation is visual only. When a swap replaces the main content, move focus to the new heading (after updateCallbackDone) or update a live region, as you would without a transition.
  • Keep the controls real. Whatever starts the swap should be a <button> or a link, so it works from the keyboard. The morph demo puts a button in each card title.
  • Short and purposeful. Keep durations around 200–400ms and let the motion explain the change (where a card went), not decorate it.
  • No support, no problem. Without View Transitions the update simply happens.

Examples

Shared-element morph

A morph needs the same name on the element in the old state and the element in the new state. Two separate elements that both carry data-transition="morph" get two different names, so they never match. Give the source an id (its name becomes morph-id) and give the destination that name inside the swap, or name both yourself with data-vt-name. Only one rendered element may hold a name at a time, so hide the old view in the same update.
