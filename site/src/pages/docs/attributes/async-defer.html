Overview

By default, a classic <script src> stops the HTML parser: the browser downloads the file, runs it, and only then carries on parsing. async and defer let the download happen alongside parsing. They differ in when the script runs.

Applies to: <script>. Both are boolean attributes. On classic scripts they only work with src; inline classic scripts ignore them. On module scripts, async works inline too, and defer does nothing because modules are already deferred.

Values

ScriptDownloadRunsOrder
Classic, no attribute (the default)Blocks the parserAs soon as it arrivesDocument order
Classic asyncAlongside parsingAs soon as it arrives (pausing the parser)Whichever finishes first
Classic deferAlongside parsingAfter parsing, before DOMContentLoadedDocument order
type="module"Alongside parsing, with its importsAfter parsing, before DOMContentLoadedDocument order
type="module" asyncAlongside parsing, with its importsAs soon as it and its imports are readyWhichever is ready first

If both async and defer are present, async wins. defer was only a fallback for very old browsers.

Examples

async for independent scripts

Analytics, monitoring and ad tags that depend on nothing else and that nothing depends on. Add fetchpriority="low" so they do not compete with resources the page needs.

defer for ordered classic scripts

Deferred scripts run in the order they appear, after the DOM is complete, so a library can come before the code that uses it.

Modules

Module scripts are deferred without any attribute. They are always in strict mode, have their own scope, and can use import and top-level await. Preload a module's dependencies with <link rel="modulepreload"> to avoid a chain of round trips.

Scripts that must run before first paint

A small classic inline script in <head> runs before the body is parsed. This is the right tool for work that must happen before anything paints, such as applying a saved theme. Keep it tiny: it blocks parsing.

In Vanilla Breeze

  • Install. The quick start loads VB as one module in <head>: <script type="module" src="…/vanilla-breeze.js"></script>. Because modules are deferred, this does not block parsing or rendering, and it runs once the DOM is complete. You do not need defer.
  • The docs site. The documentation layouts (for example site/src/layouts/attribute.html) load five module bundles at the end of <body>: core, extras, UI, doc extras and prototyping. They run in document order. See Performance for what each contains.
  • Theme boot. The docs site's theme boot (site/src/includes/head.html) is a deliberate classic inline script in <head>. It reads the saved theme and writes the theme stylesheet link before the first paint, and a :has(link[data-vb-theme-state="loading"]) rule keeps <body> hidden until that stylesheet has loaded. That is the "must run before rendering" case from the table above.
  • No-JavaScript. VB's native-element CSS works before, and without, any script. Scripts enhance; they are never required to show content.

Gotchas

  • Inline classic scripts ignore both attributes. They run immediately where they appear. The demo shows an inline <script defer> running straight away.
  • async order is unpredictable. If script B needs script A, do not make both async. Use defer or modules.
  • Deferred scripts hold up DOMContentLoaded. A slow deferred or module script delays every handler waiting for that event.
  • Script-inserted scripts are async by default. Set script.async = false on scripts you create with document.createElement('script') to run them in insertion order.
  • nomodule marks a classic script that only browsers without module support should run. Every current browser supports modules (Chrome 61, Firefox 60, Safari 10.1), so it is rarely needed now.

Which to choose

  • type="module" — your own code, including VB. Deferred and ordered by default.
  • defer — classic scripts that need the DOM or each other.
  • async — independent third-party scripts.
  • No attribute — a tiny inline script that must run before first paint.
  • blocking="render" — when a deferred or async script must still finish before the first paint.
