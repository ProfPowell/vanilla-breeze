Overview

The preload attribute hints how much of a media file the browser should download before the user presses play. It is a trade-off between bandwidth and how quickly playback starts. It is only a hint: the browser may load more or less.

Applies to: <audio>, <video>. Not <source>: set it on the media element.

Values

ValueWhat loads before playTrade-off
noneNothing.Saves the most data. No duration or first frame until play, and playback starts later.
metadataDuration, dimensions, the first frame (video), and possibly a little more.A good balance. The controls can show the length straight away.
autoWhatever the browser thinks is useful, up to the whole file.Fastest start, highest data cost.
"" (empty)Same as auto. 
Absent or invalidBrowser-defined. The spec suggests metadata. 

Examples

preload="none" with a poster

For pages with several videos, or a video many visitors will not play. Without a poster the box stays empty, so always set one.

preload="metadata" for audio

Podcast and music players. The controls can show the length before play, which helps people decide whether to listen.

preload="auto" for instant playback

Short clips that must play the moment someone asks, such as a pronunciation sample. Use it sparingly: on a page with many media elements it can download a lot.

In Vanilla Breeze

  • VB does not set or style preload; it reaches the browser exactly as written. VB's video defaults (max-inline-size: 100%; block-size: auto in src/native-elements/video/styles.css) mean the samples on this page need no inline style.
  • <video-player> and <audio-player> read the duration from the inner media element's loadedmetadata event. With preload="none" their time display shows 0:00 until playback starts; use preload="metadata" when the length should show up front. VB's own player demos use metadata.

Accessibility

  • preload="none" without a poster gives sighted users an empty box. Pair it with a poster, a heading or a caption.
  • With preload="metadata" the controls can show the length, which lets everyone judge whether to play.
  • preload does not decide whether controls are shown. See controls.

Gotchas

  • It is a hint. Browsers can ignore it based on network conditions, data-saving settings or their own heuristics, and mobile browsers often load less than you asked for.
  • autoplay needs data to play, so it overrides preload. preload="none" with autoplay has no effect.
  • There is no event that tells you which strategy the browser used. Watch loadedmetadata, progress and buffered instead, as the demo does.
  • Changing preload from script after loading has started may do nothing.

Which to choose

  • none — several videos on a page, or video few people will play. Always with a poster.
  • metadata — the default choice for a single video and for audio players, including VB's.
  • auto — short clips that must start instantly.
