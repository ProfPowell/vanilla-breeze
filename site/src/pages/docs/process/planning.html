Plans as pages

A plan kept in a separate tool drifts from the work. A plan kept as HTML in the project's repository changes in the same commits as the code, is reviewed in the same place, and needs no account to read. A user story is an element with an id, so a commit message, a test or another page can link straight to it.

@profpowell/vb-project-planning is a separate npm package of elements for this. They were moved out of Vanilla Breeze so that the library stays about building sites. They read Vanilla Breeze tokens, so a planning page follows the theme of the site it belongs to.

What the package provides

Each name links to its page on the package's documentation site.

Purpose Elements
Who it is for <user-persona>, <empathy-map>, <user-journey>
What to build <user-story>, <story-map>, <requirement-card>, <quality-target>
What comes first <impact-effort>, <quadrant-grid>, <iron-triangle>, <capacity-plan>
When it happens <product-roadmap>, <gantt-chart>, <burndown-chart>
Where the work stands <kanban-board>, <work-item>, <traceability-matrix>
What could go wrong, and what was decided <risk-register>, <adr-wc>, <review-surface>

Four elements that planning pages often need stayed in Vanilla Breeze, because any site can use them: <site-map> for the page tree, <flow-diagram> and <diagram-wc> for flows and structure, and <glossary-wc> for the project's terms.

Install and load

Load Vanilla Breeze first, then the package's stylesheet and script.

import 'vanilla-breeze/css'; import 'vanilla-breeze'; import '@profpowell/vb-project-planning/css'; import '@profpowell/vb-project-planning'; // every element // or one element at a time import '@profpowell/vb-project-planning/kanban-board';

What it uses from Vanilla Breeze

Vanilla Breeze is an optional peer dependency. Without it the elements still render, with fallback colors and without the behaviour in this table.

Vanilla Breeze part Used by For
Tokens and the active theme Every element Color, type and spacing
<drag-surface> <kanban-board>, <story-map>, <quadrant-grid>, <impact-effort> Moving cards by pointer or keyboard
<data-table> <risk-register>, <traceability-matrix> Sortable headers, the severity summary and the heat map
<form-field> <iron-triangle>, <quality-target>, <capacity-plan> Labels and validation messages in their dialogs
<chart-wc> <burndown-chart> Drawing the chart. It is in the charts bundle, vanilla-breeze-charts.js and vanilla-breeze-charts.css, not the main one

A board of stories

A board is a <kanban-board> with one <section> for each column. A story is a <user-story> with its parts in named slots. Move a story to another column by moving its element, in the editor or by dragging it on the page.

Bookshop customer reserve a seat at an author evening I know there is room before I travel Events manager see who has reserved
Bookshop customer see this month's events on one page

The story reads As a bookshop customer, I want to reserve a seat at an author evening, so that I know there is room before I travel. data-wip sets a limit on the number of cards in a column. Dragging changes the page in the browser only. To keep a move, make it in the source, or listen for the board's kanban-board:transfer event and save it yourself.
