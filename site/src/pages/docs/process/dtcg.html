What DTCG is

The Design Tokens Community Group format is a JSON file for passing design tokens between tools. Each token has a $type and a $value, tokens sit in named groups, and one token can refer to another. Design tools and code generators that read the format can take a theme without a converter written for each pair.

A Vanilla Breeze theme is CSS: custom properties under a data-theme selector. The DTCG file is a second form of the same theme, for tools that do not read CSS. The library writes and reads the 2025.10 version of the format.

/* CSS: --radius-m: 0.5rem; */ { "border": { "radius": { "m": { "$type": "dimension", "$value": { "value": 0.5, "unit": "rem" } } } } }

Token files for the bundled themes

Every theme stylesheet in the package has a token file beside it with the same name. A theme that has its own dark values has a second file for them. themes/manifest.json lists both under dtcg and dtcgDark for each theme.

https://unpkg.com/vanilla-breeze/dist/cdn/themes/classic.css https://unpkg.com/vanilla-breeze/dist/cdn/themes/classic.tokens.json https://unpkg.com/vanilla-breeze/dist/cdn/themes/classic-dark.tokens.json

The files are written from the theme's CSS when the library is built, so they hold what the theme sets and not the library's defaults. The theme library page lists every theme with links to its files.

How tokens map

The prefix of a custom property decides its group and type in the file. The rest of the name is the token name.

Custom property Group $type
--color-*colorcolor
--hue-*, --lightness-*, --chroma-*color.seedsnumber
--font-*typography.familyfontFamily
--font-size-*typography.sizedimension
--font-weight-*typography.weightfontWeight
--line-height-*typography.lineHeightnumber
--letter-spacing-*typography.letterSpacingdimension
--size-*spacingdimension
--radius-*border.radiusdimension
--border-width-*border.widthdimension
--duration-*motion.durationduration
--ease-*motion.easingcubicBezier
--shadow-*effect.shadowshadow

A custom property with any other prefix is left out of the file. Its name is recorded in a list, unmapped, in the file's $extensions. On import the table is read the other way, and a token in a group that is not in the table is reported as ignored.

Which values convert

The format holds finished values. CSS can hold a calculation. Where a theme uses one, the file keeps the CSS text in $extensions["com.vanilla-breeze"], where other tools do not look. This table says what another tool sees and what comes back on import.

CSS value In the file Other tools see Imported again
A color written as oklch(), hex or rgb() A color in the oklch or srgb space The color The same color. Lightness is written as a number, so 55% comes back as 0.55
light-dark(a, b) Three tokens, $root, light and dark, and the CSS text under lightDark Both colors, when each is a plain color The original text
A relative color, oklch(from var(--color-primary) ...) Black as a stand-in, and the CSS text under expression Black The original text
A length in px or rem A dimension The length The same length
A length in em or % A dimension in rem, and the real unit under unit The number with the wrong unit The original length
A font stack, a weight, a time, a cubic-bezier(), a shadow whose color is a plain color The matching DTCG value The value The same value
Anything else: var(), calc(), color-mix(), a named color, an easing keyword such as linear, a shadow of none A stand-in (black, zero, or a straight-line curve), and the CSS text under literal The stand-in The stand-in. The literal text is not read back

Two things follow. Before you rely on a token file in another tool, look for tokens that carry expression or literal: their $value is not the real one, and the tool needs the real one entered by hand. And a theme that sets tokens with var() or calc() does not come back whole from a file, so keep the CSS as the source and treat the file as a copy.

The themes most likely to be taken elsewhere, Modern, Minimal and Classic, set their brand colors from the hue, lightness and chroma seeds. Those export as numbers under color.seeds, and the file's $extensions carries seedDerivation: true to say the colors are built from them.

Importing a file from another tool

<theme-import> takes a file by paste, by upload or from a URL, and sets the resulting custom properties on one element of the page, #preview unless you name another with target. It does not write to :root, so a trial does not change the rest of the site. Tokens it cannot place are listed under Ignored tokens.

Sample

The import reads more of the format than the export writes:

  • A group's $type applies to the tokens inside it.
  • A reference such as {color.primary} becomes var(--color-primary).
  • A composite typography token is split into the separate properties the library uses: --font-name, --font-size-name, --font-weight-name, --line-height-name and --letter-spacing-name.
  • A token with light and dark values becomes one light-dark() value.

The file has to use the group names in the mapping table. A file from another design system usually does not, so rename its groups first or expect most tokens to be ignored.

The catalog

<theme-catalog> lists eight token sets already renamed to fit: Material Design 3, IBM Carbon, Salesforce Lightning, GOV.UK, Atlassian, Tailwind, Bootstrap and Catppuccin Mocha. Each shows its license, and its attribution once applied. The files are in the Vanilla Breeze package under dist/cdn/themes/catalog/. The element looks for them at /cdn/themes/catalog on your own site, so point it at the package when you load Vanilla Breeze from a CDN.

Exporting from a page

<theme-export> reads the custom properties set in the style attribute of one element, :root unless you name another with scope. Those are the changes made on the page by the editable specimens, an import or your own script. It does not read the theme's stylesheet: for a bundled theme, use its token file.

The element's menu switches between CSS, plain JSON and DTCG. In DTCG the download is named theme.tokens.json and has the media type application/design-tokens+json. With live the output is rebuilt each time an editable specimen changes a token.

Other tools that read the format

  • designtokens.org has the specification.
  • Style Dictionary turns a token file into code for other platforms.
  • Tokens Studio manages tokens inside Figma.
  • Penpot is an open-source design tool with design tokens built in.

Each tool has its own rules for group names and for $extensions. A tool that drops extensions on save also drops the CSS text kept there, and a file that has been through it comes back with the stand-in values only.
