Ambient Pack

Lets a site look slightly like today. The pack resolves a season, a time of day and calendar occasions for the author's place, writes them as attributes on <html>, and maps them to decorative tokens. It never asks for or guesses the visitor's location.

This is the first release of the pack. Season, time of day, occasions, tint tokens, the visitor opt-out and the preview are in. The weather feed, motif icons and animated atmosphere effects are not built yet; data-weather can be set today only by a pin or a preview.

How it works

  1. Configure. The page lists the signals it wants in data-ambient and, optionally, gives a time zone and a calendar in a JSON block.
  2. Resolve. Pure functions turn the clock and the config into a state.
  3. Reflect. The state is written to attributes on <html>: by the inline head script before first paint, then kept current by the module.
  4. Respond. The pack's CSS maps the attributes to tokens. Your CSS and your theme can select on the same attributes.

Ambient adds tokens. It does not change --color-primary, text colours, borders or focus styles, so contrast for text and controls stays the theme's own. Without data-ambient on <html> the pack does nothing.

The head script must come after #ambient-config. It does not throw, wait on the network or touch layout. With JavaScript off, the attributes your build wrote are used as they are.

The pack writes a state attribute only for a signal you enabled and a value it knows. State attributes are a public contract: select on them freely.

Two attributes go on other elements. data-ambient-surface gives an element, usually <body>, the washed background. data-ambient="off" on any element resets the tokens for that subtree.

Configuration

All keys are optional. Without tz the visitor's own clock is used.

KeyMeaning
tzIANA time zone of the author's place, for example America/Los_Angeles.
hemispherenorth (default) or south, which shifts the season by two.
seasonsA month (1–12) to label map for places without four seasons. Custom labels get no built-in tint; style them yourself.
occasionsDated windows written by a build with expandCalendar(). The head script reads these.
calendarCalendar rules, for a page with no build step. The module fetches the rule parser and applies occasions after load.
pinFixes signals for a page: { "season": "winter", "weather": "snow" }.

An occasion is active from lead days before its date to trail days after. Active occasions are sorted by priority, then by how near their own day is, and the first two are kept. No calendars ship with the pack yet.

import { expandCalendar, resolveSeason } from 'vanilla-breeze/ambient-resolve' const year = new Date().getFullYear() const config = { tz: 'America/Los_Angeles', occasions: expandCalendar(calendar, [year, year + 1]), } const season = resolveSeason(new Date(), config) // write as data-season

Tokens

TokenSet byUse
--color-ambientDerivedDecorative marks, ornaments, chart accents
--color-ambient-surfaceDerivedPage background, through data-ambient-surface
--ambient-hueSeasonAbsolute oklch hue of the season colour
--ambient-chromaWeatherChroma multiplier, 0.6 to 1.1
--ambient-warmthTime of dayShare of a warm hue mixed in at dawn and dusk
--ambient-washWeatherShare of the accent in the surface, at most 4%
--ambient-blendThemeShare of the theme's primary kept in a season colour (default 25%)

A season has a hue of its own: winter is a cool blue-grey, spring a soft green, summer a clear blue, autumn a warm brown. The season colour takes its lightness from the theme's primary and keeps a share of it, so it still belongs to the theme. Without a season, --color-ambient is the theme's primary, adjusted by weather and time of day.

At night the surface is left alone on a light page and washed at 4% on a dark one. The time of day never changes the visitor's light or dark mode.

@layer bundle-theme { [data-theme~="swiss"][data-season="winter"] { --ambient-hue: 230; --ambient-season-chroma: 0.5; } }

The treatments reset under forced colours and in print. Token changes transition over 600 ms, and not at all under reduced motion.

JavaScript API

import { Ambient } from '/cdn/packs/ambient.core.js' Ambient.state // frozen: { season, daypart, weather, intensity, occasions, occasionDay, tempC, asOf } Ambient.enabled = false // visitor opt-out, stored in localStorage Ambient.override({ season: 'winter', daypart: 'night' }) // preview; null clears Ambient.refresh() // resolve again now document.addEventListener('ambient:change', (e) => { e.detail.state // the new state e.detail.changed // ['daypart'] })

The pure resolvers are in packs/ambient.resolve.js and have no DOM access: resolveSeason(date, config), resolveDaypart(date, config, sun), resolveOccasions(date, calendar, config), expandCalendar(calendar, years) and mapWeatherCode(code, windKmh).

Visitor control and preview

The module wires any [data-ambient-toggle] button or checkbox and keeps aria-pressed or checked in step. <settings-panel> shows the same switch in its Environment section on a page that uses the pack. The choice is one localStorage key, vb-ambient.

To preview a state, add ?ambient=winter,night,snow,halloween to the URL. It is honoured only on localhost or when <html> carries data-ambient-debug.

Privacy

The pack makes no network request, sets no cookie and never asks for location. The season and time are the author's, by the configured time zone, which is why a visitor elsewhere sees the author's evening and not a guess about their own.

When to Use

Load the ambient pack on a personal or editorial site where a returning reader should notice the site feels like today. Leave it out where colour carries meaning that must not drift, such as a data dashboard with a fixed palette.
