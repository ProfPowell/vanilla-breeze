Overview

Vanilla Breeze loads no fonts by default. Text is set in the fonts already on the reader's device, so a page shows its text at once and downloads nothing extra. Every font is named by a token, so you change a typeface by setting a token and never by restyling elements.

This page is about which typeface is used. How type is sized, spaced and refined is covered in Typography.

System font stacks

Three tokens hold the font families. Each is a stack: the browser uses the first font in the list that the device has.

TokenStackUsed by
--font-sanssystem-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serifAll text, through <body>
--font-serifCharter, "Bitstream Charter", "Sitka Text", Cambria, serifNothing by default. It is there for you and for themes.
--font-monoui-monospace, "Cascadia Code", "Source Code Pro", Menlo, monospace<code>, <pre>, <kbd> and other technical text

For scripts other than Latin there are separate stacks: --font-cjk, --font-arabic, --font-hebrew, --font-thai and --font-devanagari. They apply by language, so set lang correctly. See i18n.

:root { --font-sans: var(--font-serif); }

Font slots

Beyond the three families there are named slots for particular roles. One of them is read by the library. The rest are names for a theme, a font pack or your own CSS to use.

SlotDefaultRead by
--font-headingNot setEvery heading, h1 to h6
--font-displayvar(--font-serif)Your CSS and themes, for hero text and large titles
--font-bodyvar(--font-sans)Your CSS and themes
--font-codevar(--font-mono)Your CSS and themes
--vb-font-editorialvar(--font-serif)Your CSS and themes, for pull quotes and section openers
--vb-font-dramaticvar(--font-serif)Your CSS and themes, for high-contrast display text

A separate heading face

Set --font-heading and every heading uses it. Leave it unset and a heading keeps the font of the text around it, which is why a heading inside a serif article is serif without any extra rule.

:root { --font-heading: var(--font-serif); }

An element with its own data-theme clears the slot, so a themed card inside a page does not pick up the page's heading face.

Using your own font

Declare the font, then put it at the front of a stack. Keep the system fonts after it as the fallback.

@font-face { font-family: "Literata"; src: url("/fonts/literata-variable.woff2") format("woff2"); font-weight: 200 900; font-display: swap; } :root { --font-serif: "Literata", Charter, Cambria, serif; --font-heading: var(--font-serif); }
  • Host the file yourself. A font served from your own site needs no third-party connection and is covered by your own caching.
  • Prefer one variable font to several static files. One file covers every weight.
  • Use font-display: swap. Text shows in the fallback font until the file arrives.
  • Preload only the font used above the fold. See Performance.
  • A font with one face still gets bold and italic. The library lets the browser synthesize them for emphasis. See Typography: Emphasis.

Matching the fallback

Fonts differ in how tall their lowercase letters are, so the same font-size can look larger or smaller and headings can wrap differently. --font-size-adjust is applied to <body> and defaults to none. Set it to even out a font that runs large or small. The pixel and monospace themes use values between 0.45 and 0.50.

:root { --font-size-adjust: 0.5; }

Font packs

Three packs ship self-hosted variable fonts and set the tokens for you. Each is one stylesheet.

PackFontsSetsSize
FoundationInter, Literata, Recursive--font-sans, --font-serif, --font-monoAbout 660 KB
DisplayFraunces, Cormorant, Bodoni Moda--font-display, --vb-font-editorial, --vb-font-dramaticAbout 430 KB
ExpressiveNabla, Honk, Kablammo--vb-font-nabla, --vb-font-honk, --vb-font-kablammoAbout 610 KB

The sizes are the total of the font files. A browser downloads a font file only when text on the page uses it.

The Display pack does not change your headings by itself. Point the heading slot at it:

:root { --font-heading: var(--font-display); }

Themes

A theme can set any of the tokens above. A theme's value wins over a font pack, because themes sit in a later cascade layer. So the Terminal theme keeps its own monospace face when the Foundation pack is loaded.

Themes differ in how they treat typefaces:

  • System fonts only. Many themes change color and shape and leave the fonts alone.
  • A web font loaded by the theme. Some themes load their fonts from Google Fonts when the theme stylesheet loads. That is a request to a third party.
  • A named font that is not loaded. Some themes put a font such as Inter or JetBrains Mono first in a stack without loading it. Readers who have the font installed see it and everyone else sees the next font in the stack.

To give any theme a typeface of your choosing, set the tokens after the theme loads:

:root[data-theme~="nord"] { --font-sans: "Inter", system-ui, sans-serif; --font-heading: var(--font-serif); }

See Creating custom themes and Overrides.
