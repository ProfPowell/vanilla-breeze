How it works

In most layout systems you tell each element where to go with a class. Here an element's place comes from what it is. Write <header>, <nav>, <main>, <aside> and <footer>, choose a template on their parent, and each element goes to the grid area that carries its name. That is the element's grid identity.

Change the template and the same markup becomes a different layout. No element needs to change.

Three tiers

The idea applies at three levels. Each is scoped to its own container, so they nest without clashing.

Tier Set with Places
Page data-page-layout on <body> The page regions, in areas named body-header, body-nav, body-main, body-aside and body-footer
Main data-layout="sidebar-left" or "sidebar-right" on <main> A sidebar inside the content area, in areas named main-nav, main-article and main-aside
Component data-layout="regions" or "media" on any element The parts of one component, by element type: header first, footer last, a figure beside its content

Page level

Put data-page-layout on <body>. Its direct children are placed by element type. This is the only page-template system in Vanilla Breeze. This page explains the idea; the attribute page is the full reference for modifiers, the mobile drawer and custom properties.

Try it. The demo's markup stays the same while the buttons change the template. Each region prints the grid area it was given.

Only direct children of the data-page-layout element are placed. Other children, such as a <section> or a custom element, flow into the next free cell unless they take data-layout-area.

Templates

A template has areas for some elements and not others. Use the elements in the "Places" column.

Template Shape Places
stackOne column. Also what a bare data-page-layout gives.header, nav, main, aside, footer
sidebar-leftNavigation column, then mainheader, nav, main, footer
sidebar-rightMain, then a sidebar columnheader, main, aside, footer
holy-grailThree columns: nav, main, asideheader, nav, main, aside, footer
app-shellA navigation bar the full height of the page, beside header and mainheader, nav, main
dashboardHeader across the top, nav beside main. The nav becomes a drawer on small screens.header, nav, main
articleOne centered column for readingheader, main, footer
landingOne column with extra named areas for marketing sectionsheader, nav, main, footer, plus hero, feature and cta

An element the template has no area for is pushed into an extra track at the edge of the grid. That track has no width, so the element collapses and its content is lost from view. An <aside> under sidebar-left is the usual case. Leave such elements out, or choose a template that places them.

Each template is a custom property named --tpl-name, for example --tpl-sidebar-left. The properties are declared on the [data-page-layout] element and not on :root, so to replace a template, set the property on that element: body { --tpl-sidebar-left: …; }.

When an element is missing

A template drops a column when the element for it is absent. The styles use :has() to see which children are present.

  • sidebar-left without <nav>: one column.
  • sidebar-right without <aside>: one column.
  • holy-grail without <aside>: two columns, nav and main.
  • holy-grail without <nav>: two columns, main and aside.
  • holy-grail without both: one column.

So one template can serve pages that have a sidebar and pages that do not. The element must be absent from the markup: a hidden element still counts as present and keeps its column. To drop the nav column while keeping the element, set data-sidebar="hidden" on the layout.

Small screens

Below 48rem, sidebar-left, sidebar-right, holy-grail and dashboard collapse to the stack shape, and the dashboard nav becomes an off-canvas drawer. app-shell moves its nav to the bottom. Set data-layout-nowrap to keep the wide shape. stack, article and landing are already one column.

Named areas

Some sections have no element of their own: a hero, a feature list, a call to action. For these, data-layout-area places a child in an area by name. Only the landing template defines extra areas, so three values work:

A name that the active template does not define has the same effect as an element with no area: the child lands in an extra track with no width and disappears. For the standard regions, use the elements (<nav>, <aside> and so on) and not data-layout-area.

Main level

A <main> with data-layout="sidebar-left" or data-layout="sidebar-right" is a second tier. Only these two values assign main-* areas, and only to direct nav, article and aside children. Use it for a table of contents beside an article, or section navigation inside the content area.

These templates adapt in the same way as the page templates: if the nav or aside is absent, the layout falls back to a single column. Below 48rem (unless data-layout-nowrap is set on the main) they stack in the order article, aside, nav, so a leading <nav> moves below the article visually while staying first in the reading order.

Other children of these mains (a <header>, <section> or <footer>) get no area and are auto-placed. For a header/content/footer structure, use regions on an inner element (below).

Component level

Two layouts carry the idea down to a single component. They work on any element and place children by element type, with no named areas.

Regions

A grid of region cards

Regions are most useful inside a grid. The grid makes the cards equal in height, and each card pins its footer to the bottom, so the footers line up however much text a card holds.

All three together

The tiers nest. The page and main tiers use different area names (body-* and main-*), and the component tier places by element type, so nothing clashes.

Container names

The regions are named query containers. A component can ask how wide "the main region" is, by name, and not only how wide its nearest container is.

In Element Container name
data-page-layout<main>region-main
data-page-layout<nav>region-nav (only where the nav column has a definite width; see data-page-layout)
data-page-layout<aside>region-aside
main[data-layout="sidebar-left"]<nav>region-main-nav (a nav is not a size container by default; add data-container to query it)
main[data-layout="sidebar-left"]<article>region-main-content
main[data-layout="sidebar-right"]<article>region-main-content
main[data-layout="sidebar-right"]<aside>region-main-aside

For example, to change a grid when the main region is narrow:

@container region-main (width < 40rem) { .article-grid { grid-template-columns: 1fr; } }

To make any other element a container, use the data-container attribute. Its named presets are card, panel and media; with no value the container has no name.

    Accessibility

    • Grid placement changes where regions appear, not their order in the DOM. Keyboard and screen-reader order follow the source, so write header, nav, main, aside, footer in reading order.
    • The page regions are landmarks because of their elements (main, nav, aside, and header/footer as direct children of body), not because of the grid. Give each nav and aside an aria-label when there is more than one.
    • Collapsed mobile layouts and the dashboard drawer are covered on data-page-layout.
